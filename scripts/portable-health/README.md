# 便携版只读健康检查

双击便携盘根目录 `Check-DSH-Health.cmd`。中文控制台显示结果并停留，不需要重新构建桌面程序。

## 安全边界

- 只读取本地版本元数据、文件存在性、进程信息、监听端口、日志时间/大小及磁盘剩余空间。
- 不构建、不更新、不切槽、不重启、不清理，不修改配置、插件、聊天记录或现有诊断文件；默认不保存报告。
- 通过 EXE 路径和 `--user-data-dir` 同时识别正式实例。同一个 EXE 启动的隔离 UI 测试不算正式实例。
- 只向正式桌面直接启动的 Harness 子进程的回环端口发送无凭据 GET `/`，最多三个端点；每个请求默认超时 2 秒。禁用代理、重定向、Cookie，不读取响应正文。服务本身可能记录访问日志。
- 不读取启动错误正文、聊天、浏览器数据或凭据。报告仅供本地排障；JSON 含本地路径、版本和进程号，分享前仍应检查隐私。
- 拒绝越界相对路径、目录联接及符号链接。不会以管理员权限自动重试。

## 状态含义

“等待正常退出后启动验证”表示候选已准备但尚未激活，不是更新完成，也不因进度停在 94% 就断定失败。

“关键文件存在且槽清单哈希匹配”仅为基础完整性检查，不是完整包校验或发布签名认证。它不会取代启动器原有的完整更新验证。

桌面版本取自正式进程 EXE 的版本资源；实际运行时版本取自该进程直接启动的 Harness 命令所指向的包。配置指针单独列出，不能冒充实际运行版本。

正式桌面未启动时，服务检查不适用；工具不会为了检查而启动它。HTTP 2xx 仅表示回环服务可达，401/403 仅表示返回认证拒绝，不证明界面、插件或模型调用正常。

错误日志早于主进程启动时，标为历史记录；本次启动后有记录时提示注意，但不直接判定当前服务失败。检查前后版本指针或已识别的进程变化时，标为不完整；多文件读取不是跨进程事务快照。

## 命令行

```powershell
# JSON 输出到标准输出，不自动写文件
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\portable-health\Check-DSH-Health.ps1 -AsJson

# 完全跳过 HTTP 请求；运行中的服务会标为未验证
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\portable-health\Check-DSH-Health.ps1 -NoHttp
```

可选参数：`-PortableRoot` 指定另一便携目录；`-TimeoutSeconds 1..10`；`-MinimumFreeGB 0..1024`（默认 2）。空间阈值仅是排障提示，不代表更新所需空间估算，也不证明目录可写。

退出码：`0` 未发现明确异常（含未启动和正常等待激活）；`1` 有警告或错误；`2` 检查不完整。有明确错误时优先返回 `1`，详细结果仍保留所有未确认项。调用 PowerShell `-Command` 包装脚本时，需要显式 `exit $LASTEXITCODE` 才能保留退出码；双击入口已保留。
