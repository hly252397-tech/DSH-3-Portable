> 审计基线：本文全部结论来自真实代码/配置/脚本交叉验证，证据以相对 `G:\DSH-3-Portable` 的路径标注。未能核实的条目显式标"未核实"。

## 1. DSH 是什么

- **官方 DSH（DeepSeek Harness）**：插件化 AI Agent 运行时（npm 包 `@deepseek-ai/dsh`），提供 Web UI 形态的智能体会话、工具、插件、技能等能力。打包源与 `src/bundled-plugins.ts` 的 `OFFICIAL_DSH_VERSION` 同为 **`0.1.7-rc.2`**（`package.json.config.bundledDshVersion` 一致，门禁强制）。运行时实际跑的是 **A/B 活动槽** `Data/Runtime/Harness/`（当前 `0.1.7-rc.2`）。legacy `App\dsh-runtime` **存在但已非首选**：其内为历史解压产物 `0.1.2-alpha.3`（2026-09-26 实测），**只作 slots 全不可用时的最后回退**（启动器自 2026-09-22 起优先 `pointer.current → previous → 扫描 slots/`），不保证与清单同步——禁止原地覆盖 `App/` 修它。
- **本仓库（便携版3）**：DSH 官方桌面启动器 `dsh-codex-desktop`（`package.json:2,4`，`name: deepseek-harness-desktop`，repository 指向 `MichengAI/dsh-codex-desktop`）的**便携盘定制**。核心目标（证据：`docs/00-交接入口/01-项目概览.md` §项目定位）：通过 Electron 管理本地 DSH Web 服务与窗口，让非技术用户**无需安装系统 Node、无需命令行**即可使用；全部数据收口到便携盘，目录可整体放 U 盘/移动硬盘并按当前盘符重算路径（`便携版3-使用说明.md:3`）。

### 用户主要工作流

1. **双击 `DSH便携版3.exe`（或 `Start-DSH-Portable.cmd`）启动** → 主界面即 DSH Web UI + 外壳工具栏 + 内置浏览器面板（`便携版3-使用说明.md:21`；`src/main.ts` `startApplication`→`showStartupWindow`→`createMainWindow`）。
2. **在 DSH 会话里使用 AI 智能体**（对话、工具、技能、插件客户端 UI：侧栏空间、工作模式、黑洞空间等，见 profile bundles 清单 `Data/DSH/profiles/web/package.json` `dsh.profile.bundles` 共 21 项）。
3. **更新**：点顶部"更新"图标或 帮助→检查更新 → 可视化总进度/分阶段进度 → 候选构建后用户确认"部署并重启" → 优雅退出 → 启动器切候选槽并真实启动验证，失败自动回滚（`便携版3-使用说明.md:22-23,39-45`；`src/desktop-updater.ts`、`Start-DSH-Portable.ps1:277-343`）。
4. **插件安装/升级不退出应用**：安装器同盘暂存校验→原子切换→DSH 子服务热重载（`便携版3-使用说明.md:49`）。
5. **改源码后自建**：跑 `Build-DSH-Portable.cmd`（类型检查→测试→打包→候选暂存，不覆盖活动 `App/`），之后托盘退出再启动才切候选（AGENTS.md 强制验证节；`Build-DSH-Portable.ps1`）。

## 2. 系统入口链（实读核实）

```
DSH便携版3.exe                       ← scripts/build-launcher.ps1 生成的无窗口启动器，仅拉起 ps1
  └─ Start-DSH-Portable.ps1          ← 真实启动逻辑（350 行，全文已读）
       ├─ . Portable-Environment.ps1 → Set-DshPortableEnvironment（便携路径 + 环境变量收口）
       ├─ 读 Data/Updates/Desktop/pointer.json（current/pending 槽引用）
       ├─ Resolve-SlotApplication：校验槽内 5 个关键文件存在；
       │   非 App 槽还校验 slot-manifest.json 哈希 + 12 个关键文件逐个 SHA256
       ├─ 有 pending 候选 → 写 activation-attempt.json → 注入 DSH_DESKTOP_UPDATE_TRANSACTION/
       │   HEALTH_FILE 环境变量 → 启动候选 → 轮询 health.json（3min 租约/15min 硬限，
       │   startup-progress.json 活跃可续租）→ 失败杀进程树并回滚 pointer 到 current
       ├─ 无候选 → 启动 current 槽（首次无 pointer 时回退 legacy `App\DSH Codex Desktop.exe`）
       └─ 启动参数：--user-data-dir=Data\Electron\UserData --disk-cache-dir=Data\Electron\Cache
           工作目录 = 工作空间/
```

`App/` 里跑的是什么（实测目录结构）：

- `App\DSH Codex Desktop.exe` + Electron 运行时 DLL/pak —— Electron 44.1.1 打包产物（`package.json:43`）。
- `App\resources\app.asar` —— 主进程代码（源 `dist/`，入口 `dist/src/main.js`，`package.json:26`）。
- `App\resources\node\node.exe` + `pnpm.cmd`/`pnpm-package` —— 内置 Node 24 与随包 pnpm。
- `App\resources\dsh-runtime.tgz`(+sha256) —— 官方 DSH 运行时归档，首启解压到 `Data\Runtime\dsh-runtime`（环境变量 `DSH_DESKTOP_RUNTIME_DIR`，`Portable-Environment.ps1`；解压逻辑 `src/extract-runtime.ts`）。
- `App\resources\plugins-store.tgz`(+sha256) —— 离线插件仓库，首启由 `plugin-seed` 种入 profile。
- `App\resources\desktop-bridge\*.mjs/js` —— 桌面桥接包（`dsh-desktop-bridge`，作为 DSH 插件 bundle 注入，见 `src/desktop-bridge.mts` `name='dsh-desktop-bridge'` 与 `src/desktop-host.ts` `DESKTOP_BRIDGE_PACKAGE`）。
- `App\resources\bootstrap.mjs`（`src/dsh-bootstrap.mts` 编译产物，带 SIGTERM 优雅关停的 DSH 启动入口）、`shell.html/startup.html/settings.html/about.html/shortcuts.html/browser-panel.html` 等外壳页面、`theme.js/theme.css`、图标资源。
- `App\dsh-runtime\` —— 解压后的 DSH 运行时（node_modules + `dsh.cmd`），属运行时装配产物。
- `App\plugins\`、`App\locales\` —— 未逐一核实内容（目录存在）。

## 4. 版本与发布形态

- **版本号（2026-09-26）**：桌面启动器 `1.0.76`（基础版本跟随上游，便携重建用 `+build.N`，禁止第 4 段数字）；打包清单内置 DSH 家族 `0.1.7-rc.2`（bundledDshVersion / `OFFICIAL_DSH_VERSION`）；**活动 Harness 槽** `0.1.7-rc.2`；legacy `App\dsh-runtime` 仍为 `0.1.2-alpha.3`（遗留回退件，见上文）。发布契约要求 git 标签名恰为 `v<精确版本>`（AGENTS.md 认祖标签节、`scripts/create-portable-release-contract.mjs`）。
- **发布形态**：便携盘目录整体分发（U 盘/移动 SSD），非安装器；electron-builder 的 NSIS/ZIP/DMG/AppImage 目标是上游官方发布产物形态（package.json build 节），便携版经 `Build-DSH-Portable.ps1` 在盘内自建并暂存候选。
- **A/B 槽**：`Data/Updates/Desktop/slots/` 不可变候选槽 + `pointer.json`（current/previous/pending，各含 relativePath/version/sha256）+ `state.json`（phase/overallProgress）+ `events.jsonl` 审计 + `launcher.log` + `transactions/<id>/health.json` 健康证明。`App/` 永不被原地覆盖，仅作 legacy 兼容槽（Start-DSH-Portable.ps1:263-267；便携版3-使用说明.md 目录职责表）。**回退风险（2026-09-22 起已收窄）**：启动器优先从 pointer/slots 恢复完整校验槽；仅 slots 全不可用才回退 `App/` 遗留旧 `dsh-runtime`（当前仍为 `0.1.2-alpha.3`）——这是已知边界，不在本文件内假装已同步。
- **bundledNodeVersion**：`package.json` 声明 `v24.21.0`，**但实际随包二进制是 `v24.20.0`**（`App/resources/node/node.exe --version`，2026-09-26 实测）——两者不一致，见 `docs/00-交接入口/02-当前状态.md`「有效风险」。五平台 SHA256 门禁见 `package.json` 对应节；构建时校验哈希不符自动重下（`Build-DSH-Portable.ps1`）；类型与测试门禁必须用 `App/resources/node/node.exe` 跑（AGENTS.md）。
- **离线闭环**：`runtime-dsh.tgz` + `plugins-store.tgz` 随包（含 content-sha256 sidecar），首启免联网；`scripts/verify-dsh-official-baseline.mjs --online` 用于开发期对照官方 HEAD。
