# 10 — Global Context Check 与 Global Impact Review 执行模板

> 用途：DSH 项目内中/大型任务的前置与后置强制检查。本文件是模板本体，落地方式（挂进 AGENTS.md / 技能 / 子代理提示词）见 `09-System-Intelligence-Layer实施方案.md`。
>
> 适用判定：任务涉及 `src/`、`App/resources/**`、`scripts/`、打包与启动脚本、`Data/DSH/profiles/**`、`cordis.patch.yml`、`package.json` 中任意一项，即视为中/大型任务，两项检查都必须执行并留档。
> 纯文档修订、单文件文案修改可豁免，但需在任务记录中注明豁免理由。

---

## 一、任务前置：GLOBAL CONTEXT CHECK（12 项）

进入编码前逐项作答，写入任务记录（或最终答复）：

| # | 检查项 | 作答要求 |
|---|---|---|
| 1 | 当前任务属于哪个模块？ | 给出模块路径，引用 `02-代码地图.md` 条目 |
| 2 | 该模块在整个 DSH 中负责什么？ | 一句话职责，注明是源码还是生成物 |
| 3 | 上游是谁？ | 调用方/触发方，附代码证据路径 |
| 4 | 下游是谁？ | 它调用了谁，附代码证据路径 |
| 5 | 哪些地方调用它？ | 用 grep 反查调用点，列出文件:行号 |
| 6 | 它调用哪些公共能力？ | 公共组件/工具/服务清单 |
| 7 | 是否已有类似实现？ | 先查 `local/` 插件、`docs/05-系统认知/` 索引；有则说明为何不复用 |
| 8 | 是否存在可复用组件？ | 明确列出复用对象 |
| 9 | 是否涉及公共 API / Schema / 数据结构？ | 涉及则必须评估兼容性并核对内置类型声明 |
| 10 | 是否存在历史设计约束？ | 对照 `07-设计决策记录.md` 与 AGENTS.md「已踩过的坑」 |
| 11 | 修改可能影响哪些已有功能？ | 直接 + 间接影响清单 |
| 12 | 哪些文件明确不应该修改？ | 生成物目录（App/resources 运行时槽、node_modules）等 |

### 前置结论模板（回答完成后填写）

```text
Task Position: <任务在系统中的位置>
Direct Impact: <直接影响>
Indirect Impact: <间接影响>
Reusable Existing Capability: <已有可复用能力>
Architecture Constraints: <架构约束>
Expected Files: <预计修改文件清单>
Do Not Touch: <禁止/无需修改区域>
Regression Scope: <回归测试范围>
```

## 二、任务后置：GLOBAL IMPACT REVIEW（10 项）

编码完成、门禁全绿后执行，与验证证据一起留档：

| # | 检查项 | 结果 |
|---|---|---|
| 1 | 实际修改文件（逐个列出） | |
| 2 | 是否超出原计划范围 | YES / NO（YES → 重新执行影响分析） |
| 3 | 是否出现跨模块修改 | YES / NO |
| 4 | 是否引入重复能力 | YES / NO |
| 5 | 是否破坏公共接口 | YES / NO |
| 6 | 是否改变数据结构 | YES / NO |
| 7 | 是否违反现有架构 | YES / NO（对照 `07-设计决策记录.md`） |
| 8 | 直接依赖测试 | PASS / FAIL（tsc + node --test，0 fail） |
| 9 | 间接影响回归 | PASS / FAIL（按 Regression Scope 执行） |
| 10 | 项目构建 | PASS / FAIL（`src/` 改动须含 Build-DSH-Portable.ps1 候选暂存 + 启动验证） |

### 判定规则

- 第 2 项为 YES：实际修改范围明显超过最初判断 → **不得**直接交付，重新回到前置检查。
- 第 5、6、7 任一为 YES：必须附兼容性/合规性论证，否则视为不通过。
- 第 8、9、10 任一 FAIL：任务未完成，禁止标记验收通过。
- 全部通过且证据齐全，才允许在 `docs/00-交接入口/07-功能清单.md` 登记"已实现"。

---

## 三、留档要求

- 中/大型任务的最终答复中必须包含两份检查的完整填写结果（可折叠/附录形式）。
- 涉及 UI 的任务，回归范围必须包含「前后端与 UI 三项对齐」要求的入口反查与真实链路证据（见 `docs/01-当前工作/便携版3-变更与答复质量门禁.md` 第 6 节）。
