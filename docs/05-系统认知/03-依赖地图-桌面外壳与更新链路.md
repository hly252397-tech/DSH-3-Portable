## 3. 机制调用关系（代码证据）

- **指纹槽**：`validateHarnessRuntimeCandidate` 生成指纹（harness-runtime-candidate.ts:95-102）→ 写入 `.dsh-runtime-fingerprint`（:50）→ 槽目录名 `slots/<version>-<指纹前16>`（runtime-slots.ts:64-68）→ `seedOfficialRuntime` 见指纹标记即视为不可变制品，早返回（plugin-seed.ts:562-567）。指纹只覆盖 lock + 家族清单，**不含根 package.json**（harness-runtime-candidate.ts:95-102 的 hash 输入），因此坏清单只能靠 `reconcileOfficialRuntimeManifest` 自愈（plugin-seed.ts:346-359）。
- **resolutionMode**：三处同时生效——`pnpmWorkspaceYaml(..., {resolutionMode})`（harness-runtime-candidate.ts:43；plugin-seed.ts:421）、安装参数 `--config.resolution-mode=time-based`（plugin-seed.ts:409）、已存在目录的补写 `ensureRuntimeResolutionMode`（plugin-seed.ts:417-429）。常量定义 bundled-plugins.ts:161。
- **pending-updates**：文件名 `.dsh-pending-updates.json`（profile-updates.ts:5）→ `applyPendingProfileUpdates`（plugin-seed.ts:480-512）只取社区条目安装，官方条目读出 `officialRuntimeUpdateVersion` 但仅在 `allowOfficialRuntimeUpdate === true` 时走 `applyOfficialRuntimeVersion`，最后无条件删除 pending 文件（:510）。
- **桥接→外壳链**：desktop-host.ts:133 `send(REQUEST_HARNESS_UPDATE_IPC)` → dsh-process.ts:122 把子进程 message 交给 `onIpcMessage` → main.ts:1165-1168 `isRequestHarnessUpdateIpc` → `startHarnessUpdateTask(true)`（main.ts:2880-2894，单飞行任务）。`request-harness-update` 常量在 bundled-plugins.ts:15。

## 4. 反向影响分析（改这里会坏什么）

### 4.1 `src/runtime-archive.ts`
- **Direct**：首启/候选预热的 `dsh-runtime.tgz`、`plugins-store.tgz` 解压（main.ts:830；scripts/stage-local-desktop-candidate.ts 调 `preparePackagedRuntimeCacheInChild`）；内容摘要 `*.content-sha256` 生成/校验。
- **Indirect**：tar 探测行为变化会同时打崩**测试环境（GNU tar）**与**用户双击启动器（bsdtar）**其中一边——AGENTS.md「已踩过的坑」第 1 条；摘要算法变化会让既有缓存全部失配（`packagedRuntimesNeedExtraction` 重算）。
- **Regression Risk：高**。必须用双击启动器路径实测，测试绿≠用户可用。

### 4.2 `startHarnessUpdateTask`（main.ts:2880）
- **Direct**：设置页/「关于」页手动更新、桥接 IPC（main.ts:1168、1738）三条触发入口；单飞行语义。
- **Indirect**：周期调度依赖它结束后的 `scheduleHarnessUpdateCheck`（:2891）；改坏会导致插件市场「升级官方运行时」按钮失灵或双周期并发。
- **Regression Risk：中**。改它必须连带核对 `runHarnessUpdateCycle` 的 interactive 分支与 retry gate 交互（:2941-2983：手动永远放行）。

### 4.3 `writeOfficialRuntimeManifest`（plugin-seed.ts:322）
- **Direct**：候选槽 staging 清单（harness-runtime-candidate.ts:40）、`reconcileOfficialRuntimeManifest` 自愈（:357）、`applyOfficialRuntimeVersion`（:435）、scaffold 路径（:712）。
- **Indirect**：在**活动槽**调用它就是 AGENTS.md 坑「官方运行时绝不原地安装」的根源（清单新版本 + node_modules 旧版本）。家族对齐门禁 `isOfficialRuntimeFamilyAligned`（:308-320）读它写下的 overrides；「关于」页与更新器读的版本号来自它。
- **Regression Risk：高**。任何新增调用点必须确认目标不是活动槽或已有指纹的槽。

### 4.4 `scripts/prepare-runtime.ts`
- **Direct**：构建期把随包运行时/插件仓库装配进 `resources/`（electron-builder extraResources 的内容来源）。
- **Indirect**：启动器槽完整性验证要求的 `resources\dsh-runtime.tgz(.sha256)`、`plugins-store.tgz(.sha256)`、`desktop-bridge/*.js`（Start-DSH-Portable.ps1:83-112；portable-desktop-update.ts:149-163 `REQUIRED_APP_FILES`）缺一件候选槽即被判不完整回滚。
- **Regression Risk：高**。改输出物清单必须同步两处 required 清单 + `PortableDesktopUpdater` 校验。

### 4.5 `Build-DSH-Portable.ps1`
- **Direct**：门禁（`pnpm install --frozen-lockfile` + test + pack，:68-82）→ `stage-local-desktop-candidate.js` 进 A/B 候选槽（:94）。
- **Indirect**：TEMP/ELECTRON_BUILDER_CACHE 依赖 `Portable-Environment.ps1` 的 `Set-DshPortableEnvironment`（:8；AGENTS.md 坑第 5 条）；`--replace-pending` 会覆盖已有待部署事务（portable-desktop-update.ts:485-487）。
- **Regression Risk：中**。绕过包装脚本直接跑 electron-builder 必挂 TEMP；它不覆盖 `App/`、不结束桌面进程——破坏这一约束即违反「禁止原地覆盖 App」。
