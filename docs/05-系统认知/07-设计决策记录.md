## D-01 桌面与运行时更新一律走 A/B 不可变候选槽，禁止原地覆盖

- **Decision**：桌面更新与本地构建只写入 `Data/Updates/Desktop/slots/` 与 `Data/Runtime/Harness/slots/` 的不可变候选槽；由 `Start-DSH-Portable.ps1` 在启动时验证健康后切换指针，失败自动回滚。已删除的 `Update-DSH-Portable*`、`deploy-new-build.ps1` 等原地覆盖脚本禁止恢复。
- **Reason**：桥接的 `desktopRuntimeDir` 就是正在运行的活动槽；原地改写会留下「清单新版本 + node_modules 旧版本」的坏槽，且 Windows 下正在使用的文件必然替换失败（用户看到「更新成功但版本没变」）。
- **Therefore**：任何提交点必须先过候选校验；「部署完成」定义为清单复验 + 启动 + readiness + 健康文件落盘 + 指针提交进入 `completed`，缺一步都不得显示完成。
- 出处：`AGENTS.md` 坑清单「禁止原地覆盖 App」「官方运行时绝不原地安装」；`docs/03-技术架构/00-桌面启动器架构基线.md` §3、§7；`docs/00-交接入口/07-功能清单.md` #45/#45b；git `e4439c2`（统一 A/B 更新器收尾）、`0d19435`（I025 官方运行时升级链路修复）。

## D-02 本地插件用目录链接（Junction）替代双拷贝，声明只许 `link:` 不许 `file:`

- **Decision**：profile `package.json` 中本地插件以 `link:./local/<名字>` 声明，`node_modules/<插件>` 是指向 `local/<插件>` 的 Junction；改 `local/` 即时生效。禁止改回 `file:`（会重新物化拷贝）；lockfile 里残留 `file:` 解析的条目必须摘除后重装。
- **Reason**：`file:` 协议被 pnpm 物化为真实目录拷贝，宿主读 node_modules 副本，导致「改了 local 源但不生效」的双拷贝陷阱；官方 `runtime-tree.ts` 的目录链接思路验证了 Windows junction 可行。
- **Therefore**：新本地插件一律 link 声明；跑 profile 内 `pnpm install` 前先 diff specifier 与实际安装（见 D-09）；回滚备份在 `Data/Updates/LinkMigration-backup-20260911/`。
- 出处：`docs/03-技术架构/评估-目录链接替代插件双拷贝.md`（全文，含沙箱实验与实施记录）；`AGENTS.md` 坑清单「profile 本地插件已改为目录链接」；git `0c1423d`、`fc3bc4b`。

## D-03 官方运行时家族钉版靠 `resolutionMode: time-based`，不靠 overrides

- **Decision**：官方运行时统一按发布时间解析依赖；`resolutionMode: time-based` / `--config.resolution-mode=time-based` 必须同时写入三处：生成的 `pnpm-workspace.yaml`、安装参数、以及**已存在**的运行时目录（幂等 `ensureRuntimeResolutionMode`）。
- **Reason**：pnpm 11.24 完全忽略 `pnpm.overrides`，通配 overrides（`@deepseek-ai/dsh-*`）实测不命中；官方发版包把传递依赖写成 `^<同元组预发布>`，最高版语义会把候选拉成混用家族（rc.1 根包 + rc.2 传递包），被家族对齐门禁判失败。只在文件缺失时写入 resolutionMode 的旧代码永远补不上既有目录。
- **Therefore**：动官方运行时装配（`harness-runtime-candidate.ts`、`plugin-seed.ts`）时，三处缺一不可；家族对齐门禁失败先查 resolutionMode 是否三处齐备。
- 出处：`docs/03-技术架构/DeepSeek-Harness-官方兼容基线.md` 2026-09-11 审阅记录第 1 条；`AGENTS.md` 坑清单「官方运行时家族钉版」；`docs/00-交接入口/07-功能清单.md` #45b；test：`test/harness-runtime-candidate.test.ts`、`test/prepare-runtime.test.ts`。

## D-04 官方 pending 条目是幽灵，绝不回写

- **Decision**：`applyPendingProfileUpdates` 只消费社区插件条目；官方运行时条目一律清除，不合并、不回写 `profile/.dsh-pending-updates.json`。
- **Reason**：codex-ui 在安装前就写 pending 文件、失败不回滚，而 profile 安装路径明确拒绝官方包——回写会让一次失败点击变成永远无法应用的待更新项，并在之后每次插件更新里被合并带回。
- **Therefore**：改动插件更新链路时，官方条目的正确去向是「清掉」，不是「保留待重试」；官方运行时更新的唯一入口是 D-05 的 request-harness-update 链路。
- 出处：`AGENTS.md` 坑清单「官方 pending 条目是幽灵」；`docs/03-技术架构/DeepSeek-Harness-官方兼容基线.md` 2026-09-11 第 4 条；test：`test/profile-updates.test.ts`。

## D-05 官方运行时更新走 request-harness-update 事件桥，且插件「关于」页与外壳发现通道必须一起改

- **Decision**：插件侧点「更新」不再直接安装；桥接发 `request-harness-update`（`isRequestHarnessUpdateIpc` 判定，兼容字符串与 `{type}`）→ 外壳 `startHarnessUpdateTask(true)` → A/B 更新器。npm `next` 标签纳入外壳发现通道 `[policy.channel, next, latest]`，与 codex-ui「关于」页读取口径一致；受信清单三重核对（npm integrity + GitHub 标签 commit + 受信列表）。
- **Reason**：见 D-01 的原地安装问题；另外「关于」页读 `next`、外壳只发现 `[alpha, latest]` 时，提示与可切换目标天生不一致（用户点更新必失败）。
- **Therefore**：改 dist-tag 口径（next/latest/alpha 任一）时必须同步改两处消费方与受信清单；rc.1 保留受信以支撑回滚/降级。
- 出处：`docs/03-技术架构/DeepSeek-Harness-官方兼容基线.md` 2026-09-11 第 2、3 条；`docs/00-交接入口/07-功能清单.md` #45b；git `66824f6`、`4e30ab5`；test：`test/harness-update.test.ts`。

## D-06 影子验证有盲区，部署失败必须带按版本退避闸门

- **Decision**：保留 `harness-shadow.ts` 一次性 profile 影子验证（只装 `OFFICIAL_PROFILE_BUNDLES`、空 patch），同时用 `state.json` 的 `deploymentFailures` + `evaluateDeploymentRetryGate` 按目标版本退避（默认 2 次 / 24 小时，手动检查永远放行）；新增部署失败点（`deployHarnessCandidate` 抛错、切换回滚）必须记一次，切换提交成功必须清除该版本记录。
- **Reason**：影子验证不覆盖社区插件——`apply()` 里同步抛错的服务依赖插件（历史实例 0.1.5-alpha.1 `cannot get property webServer without inject`）只有真实 profile 切换时才暴露；启动自修复只挡「无法解析的 bundle」。没有闸门会陷入「构建 → 切换 → 回滚 → 重启」死循环。
- **Therefore**：**不要**为了让自动升级更积极而绕过退避闸门；给影子 profile 加装更多插件不是解法（会拖慢且仍不完备），闸门才是兜底。
- 出处：`AGENTS.md` 坑清单「影子验证不覆盖社区插件」；`docs/00-交接入口/07-功能清单.md` #45b；test：`test/harness-shadow.test.ts`、`test/portable-desktop-update.test.ts`。

## D-07 指纹槽清单损坏没有启动检查能发现，靠 `reconcileOfficialRuntimeManifest` 自愈

- **Decision**：在家族版本单一可读时，把已存在的根清单与 `resolutionMode` 拉回实际安装版本；不动 lock、不动物化依赖、指纹语义不变；家族混用时保持原样交给 A/B 门禁；**绝不在指纹槽里凭空造文件**。
- **Reason**：`isOfficialRuntimeLaunchable` 只看入口与 peer 存在；`.dsh-runtime-fingerprint` 有意排除根 `package.json`；指纹槽在 `seedOfficialRuntime` 早返回——三者叠加使「清单 0.1.5-rc.2 + node_modules 0.1.2-rc.1」的坏槽永远不被修，错误版本号一路传到「关于」页与更新器。
- **Therefore**：给指纹/清单增加新字段时，同步检查该自愈函数与指纹计算的一致性；「槽是不可变制品」约束优先于修复便利。
- 出处：`AGENTS.md` 坑清单「指纹槽的清单损坏」；`docs/00-交接入口/07-功能清单.md` #45b「活动槽清单自愈」；test：`test/runtime-slots.test.ts`。

## D-08 外壳合成层永远盖不住 DSH WebContentsView，禁用应用内模态

- **Decision**：外壳 HTML 是独立合成层，永远在 DSH WebContentsView 之上，z-index 无法穿透；工具栏类交互用**按钮内联状态（两步确认）**实现，不做应用内模态。
- **Reason**：WebContentsView 是独立合成层，DOM z-index 跨层无效；曾尝试主题化模态确认重启（git `f6b8fea`、`ade2919`）最终改为按钮内联两步确认（git `0a5b87c`，移植旧版成熟方案）。
- **Therefore**：外壳上任何「浮在 DSH 之上」的 UI 设想（全局遮罩、中央对话框）直接否决；改用按钮内联状态、托盘菜单或独立窗口。
- 出处：`AGENTS.md` 坑清单「外壳内浮层盖不住」；git `f6b8fea`/`ade2919`/`0a5b87c`；`docs/01-当前工作/I007-浏览器原生层遮挡修复/`。

## D-09 profile 包 specifier 领先安装是地雷：跑 profile 内 pnpm 前先 diff

- **Decision**：任何在 `Data/DSH/profiles/web/` 内执行的 `pnpm install`（包括为无关目的跑的）之前，先 diff `Data/Updates/LinkMigration-backup-20260911/package.json` 的 specifier 与实际安装差异；`pnpm add` 后必须复跑 `sidebar-service-lifecycle` 测试。
- **Reason**：2026-09-11 实例：link 迁移的一次 install 物化了 codex-ui 0.2→1.1 全矩阵，引发三连故障——①`--dcu-sidebar-*` 变量命名空间致设置页回退淡绿；②裸 `schemastery` 被剪枝致本地插件 import 失败；③DSH 自愈把加载失败的本地插件从 `dsh.profile.bundles` 摘除。
- **Therefore**：manifest 显式声明运行时 peer（schemastery@3.18.0）；主题层补变量映射并有防回归测试；bundles 被自愈摘除后按备份恢复，不手动逐项加回。
- 出处：`AGENTS.md` 坑清单「profile 包 specifier 领先安装是地雷」；git `7f3a5bc`（codex-ui 1.1 变量映射）；test：`test/codex-ui-style-ownership.test.ts`、`test/sidebar-service-lifecycle.test.ts`。

## D-10 GNU tar / bsdtar 必须运行时探测

- **Decision**：`runtime-archive.ts` 在运行时探测 tar 实现，只有 GNU tar 才加 `--force-local`。
- **Reason**：测试环境（Git Bash）解析到 GNU tar，用户双击启动器环境解析到 System32 bsdtar，参数语义不同——**测试通过 ≠ 用户可用**。
- **Therefore**：涉及归档/解包链路的改动，必须用双击启动器路径（真实用户入口）再验证一次，不能只信 `node --test`。
- 出处：`AGENTS.md` 坑清单「GNU tar / bsdtar 差异」；`docs/00-交接入口/07-功能清单.md` #10；test：`test/runtime-archive.test.ts`、`test/extract-runtime.test.ts`。

## D-11 含中文的 ps1 必须带 UTF-8 BOM

- **Decision**：`Start-DSH-Portable.ps1`、`Build-DSH-Portable.ps1` 等含中文的 PowerShell 脚本保存为带 BOM 的 UTF-8，且必须可被 Windows PowerShell 5.1 解析。
- **Reason**：PowerShell 5.1 按 ANSI 解析无 BOM 的 UTF-8，中文注释会变成语法错误。
- **Therefore**：新增/修改 ps1 后用 5.1 语法验证；编辑器保存格式检查纳入交付步骤。
- 出处：`AGENTS.md` 坑清单「ps1 脚本必须带 UTF-8 BOM」；`docs/03-技术架构/00-桌面启动器架构基线.md` §6。

## D-12 测试禁止读取实机 `Data/` 产物，CI 是全新检出

- **Decision**：`test/` 中凡直接读取/导入实机产物（`Data/DSH/profiles/web/local/*`、`profiles/web/node_modules/*`、运行时槽、仓库外 `工作空间/`）的用例，必须 `existsSync` 守卫 + `t.skip('实机产物缺失（CI 全新检出）')`；模块级读取/导入一律改惰性；改完用干净克隆复验 0 fail。

- **Therefore**：新增测试的验收标准包含「干净克隆（`git clone . 别处` + `pnpm install --frozen-lockfile` + tsc + node --test）0 fail」；非 Windows 平台专属行为（便携盘符路径）用 `process.platform` 守卫（git `1d367b6`）。

## D-13 官方兼容性双基线：实现基线钉内置版本，审查基线追官方 HEAD

- **Decision**：实现以便携版实际内置的 `@deepseek-ai/dsh` 导出/类型为准（**实现基线 = 活动运行时槽**；**2026-09-26 为 `0.1.7-rc.2`**，槽 `Harness/slots/0.1.7-rc.2-4d29c691bfdf224c`。沿革：撰写本条时为 `0.1.2-rc.1` → 迁移目标 `0.1.5-rc.2` → 2026-09-22 `0.1.6-alpha.2`，均仅保留为决策沿革）；每个功能开始前跑 `scripts/verify-dsh-official-baseline.mjs --online` 核对官方 HEAD。官方变化必须人工审阅后才能更新基线，禁止脚本自动接受；无法联网时只能继续诊断，不得宣称「符合官方最新要求」。
- **Reason**：官方处于 Developer Preview 允许破坏性变更；社区插件按 0.1.2-rc.1 API 开发，移植进新运行时前必须逐项核对 API 存在（dsh-agency-agents 的 settings-compat 双代桥接就是版本漂移的活教材）。
- **Therefore**：不得因官方文档出现新 API 就在旧运行时调用；运行时迁移一律按「兼容性迁移」流程：独立候选 + 依赖闭包锁定 + Profile 真实组合测试 + A/B 切换 + 回滚。版本事实源顺序：活动槽 `current.json` → `package.json`/`src/bundled-plugins.ts` → 本文与认知层文档。
- 出处：`docs/03-技术架构/DeepSeek-Harness-官方兼容基线.md`（全文，含逐日审阅记录与受信裁决）；`AGENTS.md`「官方兼容性双基线」章；`docs/03-技术架构/DeepSeek-Harness-社区插件rc1-alpha3兼容对照.md`；机器可读版 `DeepSeek-Harness-官方兼容基线.json`。

## D-14 行为归属：桌面宿主管进程/窗口/部署，DSH 内部能力进 Cordis 插件树

- **Decision**：先分类行为归属——Electron 桌面宿主、DSH 插件、Profile/Bundle、运行时升级、用户数据迁移；只有 DSH 内部能力进入 Cordis 插件树，桌面宿主不伪装成 Harness 插件。工具→`ctx.tools`、提供方→`ctx.llm`、拦截→事件、命令→`ctx.commands`（复数，无 `ctx.command()`）、后台任务→`ctx.jobs`、独立 LLM 子任务→`ctx.subagents` fork + `ctx.tools.guard`。
- **Reason**：越界归属会让生命周期、回滚与安全边界全部失效；`ctx.command()` 这类想当然的服务名曾实际踩坑。
- **Therefore**：注入声明通道按导出形态区分（命名导出→模块级 `inject`；default 类→静态 `inject`；default 函数→cordis 条目写 `inject:` 字段，plan-quota 即此形态）；未在组合中的服务用 `ctx.get()` 可选访问，绝不写进 inject。
- 出处：`docs/03-技术架构/DeepSeek-Harness-插件开发规范知识库.md` 第 10 节「新行为归属表」；`AGENTS.md` 坑清单「DSH 插件服务名与注入」+「社区插件生态实证」表；`docs/03-技术架构/DeepSeek-Harness-官方兼容基线.md` §官方兼容性判定。

## D-15 模型可见即已记录：触碰模型可见输入必须走会话事件

- **Decision**：任何影响模型可见输入的改动必须新增会话事件（扩展 `SessionEventMap`）；向当前会话注入消息用 `invocation.agent.followup(createUserMessage({source:{kind:'plugin', …}}))` 且必带插件名；用户可见状态只在事务提交点后发布。

- **Therefore**：审查清单里的「是否触碰模型可见输入」「事务提交点后发布」两项是硬门禁，不是建议。
- 出处：`AGENTS.md` 审查动作清单；`docs/03-技术架构/DeepSeek-Harness-插件开发规范知识库.md` 铁律；`docs/03-技术架构/DeepSeek-Harness-官方兼容基线.md` §官方兼容性判定；`docs/01-当前工作/便携版3-变更与答复质量门禁.md`。

## D-16 认祖合并用 `-s ours`，版本标签名归便携仓库

- **Decision**：同步上游用 `git merge -s ours` 保持便携树，内容按分组补丁另行吸收；认祖后 `git tag -f v<精确版本>` 把标签声明给便携仓库自己的发布提交（发布契约要求标签名恰为 `v<精确版本>`）；此后 `git fetch upstream --tags` 对该版本报标签冲突属预期，不要删自己的标签。
- **Reason**：便携树与上游已深度分叉（桌面 fork 无同步关系）；`fetch --tags` 会把上游 `v<版本>` 拉进本地与发布契约冲突。
- **Therefore**：同步上游是「认祖 + 按组移植」两步，不是普通 merge；发布契约脚本依赖标签归属正确。
- 出处：`AGENTS.md` 坑清单「认祖后的版本标签名归便携仓库」；git `e68d364`（认祖 v1.0.53 merge -s ours）、`fbe34a2`（认祖 v1.0.51）、`4e30ab5`（认祖后版本对齐）。

## D-17 便携版自助更新发布源三级解析

- **Decision**：`resolvePortableReleaseSource` 按 `<便携根>/Data/config/desktop-release-source.json`（机器本地覆盖）→ `resources/release-source.json`（构建期把 `DSH_PORTABLE_RELEASE_SOURCE` 烘焙进打包资源，CI 注入自有仓库）→ 内置默认（上游仓库）依次解析；CI 在 `v*` 标签自动生成便携兼容契约并发布 Release。
- **Reason**：上游 1.0.51 无便携契约，应用内更新被拦成「已阻止」；便携版需要能从自有仓库自动更新而不必每次改代码。
- **Therefore**：改更新源逻辑时三级优先级与回退行为都要覆盖测试；缺契约的上游新版本进 `incompatible` 阻止状态而非「更新失败」。
- 出处：`docs/00-交接入口/07-功能清单.md` #45（2026-09-11 发布源三级解析）；git `4e30ab5`、`b7b0023`、`7e47fff`；test：`test/portable-desktop-update.test.ts`。

## D-18 槽位与缓存回收（slot-gc）：指针引用槽永保留，未引用保留最近 3 个

- **Decision**：`prunePortableDesktopSlots` 只在健康提交与本地构建暂存两个提交点回收历史槽与下载缓存；指针引用的 `current` / `previous` / `pending` 永保留，**其余槽一律删除**（`keepUnreferencedSlots = 0`，2026-09-19 用户定案，单槽 ≈780 MB，A/B 契约只需"当前槽 + 一个回滚目标"）；需要多留几版只允许显式传参（测试用），**不得改默认值**；审计写 `events.jsonl`（source=slot-gc）。
- **Reason**：便携盘空间有限，但回滚路径必须永远可用；回收只能发生在事务提交点，否则可能删掉回滚目标。
- **Therefore**：新增槽类型或提交点时，同步纳入 prune 的引用计算与审计事件。
- 出处：`docs/00-交接入口/07-功能清单.md` #45；test：`test/portable-desktop-update.test.ts`。

## D-19 electron-builder TEMP 必须指向真实可写临时目录

- **Decision**：NSIS 打包统一经 `Build-DSH-Portable.ps1` 包装，由 `Portable-Environment.ps1` 的 `Set-DshPortableEnvironment` 设置 `TEMP/TMP → <便携根>\Data\Temp`、`ELECTRON_BUILDER_CACHE → Data\Development\electron-builder-cache`；绕过包装脚本直跑 electron-builder 时必须自行设置这两个变量。
- **Reason**：TEMP 指向非常规位置时 electron-builder 找不到临时 include 文件。
- **Therefore**：CI/脚本化构建一律走包装脚本；新构建参数加进包装脚本而非绕过它。
- 出处：`AGENTS.md` 坑清单「electron-builder TEMP」；git `845cae5`（构建器回退 electron 镜像）。

## D-20 ASAR 归档哈希必须用 Electron `original-fs`

- **Decision**：读取 `app.asar` 归档本体的 SHA256 用 Electron 的 `original-fs`，不用被虚拟文件系统补丁过的 `node:fs`。
- **Reason**：Electron 对 `node:fs` 有 ASAR 虚拟文件系统补丁，会把归档当目录读，误报 ENOENT。
- **Therefore**：涉及候选清单哈希校验（`main-safety`/`portable-stability` 链路）的实现不得换成普通 fs。
- 出处：`docs/03-技术架构/00-桌面启动器架构基线.md` §6；test：`test/main-safety.test.ts`。

## D-21 Git Bash 调 PowerShell 的转义规则

- **Decision**：Git Bash 里调用含 `$_` 的 PowerShell 命令，用单引号包裹或写成 ps1 文件执行。
- **Reason**：Bash 会把 `$_` 展开成自己的变量，PowerShell 收到的是被篡改的命令。
- **Therefore**：复杂 PowerShell 逻辑一律落成 `.ps1` 文件（顺带解决 D-11 的 BOM 问题），不写内联长命令。
- 出处：`AGENTS.md` 坑清单「PowerShell 转义」。

## D-22 外链走内置浏览器，逃逸路由收口

- **Decision**：DSH 内外部链接改走内置浏览器面板，移除外部 Edge 出口；`escape-routing.ts` 统一处理外链/逃生路由，导航白名单只放行本地 DSH loopback 源。
- **Reason**：便携版不应依赖宿主机特定应用；安全门禁要求导航收敛到受控源。
- **Therefore**：新增窗口/导航入口时先过 `navigation.ts` 白名单与 `escape-routing.ts`，不直接 `shell.openExternal`。
- 出处：`docs/00-交接入口/07-功能清单.md` #33/#34；git `b15a232`；`docs/03-技术架构/00-桌面启动器架构基线.md` §6；test：`test/navigation.test.ts`、`test/escape-routing.test.ts`。

## D-23 插件故障隔离：检疫不删除，官方/社区错误不混淆

- **Decision**：启动前社区 bundle 完整性检查；损坏社区插件只从启用清单隔离（检疫），不删除文件或依赖；官方 bundle 或运行时损坏进入 Runtime Slot 修复/回滚流程，不得伪装成社区插件错误；插件恢复模式在无插件可隔离时自动退出，`lastHealthyAt` 跨恢复启动保留。
- **Reason**：隔离 ≠ 卸载，保留文件才能恢复；把运行时错误记到社区插件头上会引导错误修复方向。
- **Therefore**：改 profile 自修复/检疫逻辑时，验证移动 node_modules 目录时移动的是 Junction 本身（link 迁移后的新语义）。
- 出处：`docs/03-技术架构/00-桌面启动器架构基线.md` §5、§4 生命周期边界表；git `87549a6`、`ce8a5ff`、`f99d526`、`2498ede`、`95273c5`；test：`test/profile-repair.test.ts`。

## D-24 UI 三项对齐门禁与功能清单登记

- **Decision**：所有新增/修改/下线的用户功能（含纯前端/插件客户端变更）必须执行质量门禁第 6 节：建立「用户入口 → 前端事件 → 后端处理 → 结果反馈」对应关系并从后端反查入口；交付前保存真实链路与 UI 验证证据；历史「✅ 已实现」不自动代表三项对齐已验收。
- **Reason**：曾出现入口缺失、点击无反应、虚假成功类缺陷；只有后端测试绿的交付在真实 UI 上不可用。
- **Therefore**：改功能先改 `docs/00-交接入口/07-功能清单.md` 登记，交付时回填证据链接；例外（内部能力/纯前端交互）须在门禁记录理由。
- 出处：`docs/01-当前工作/便携版3-变更与答复质量门禁.md` 第 6 节（唯一事实源）；`docs/00-交接入口/07-功能清单.md` 头部登记要求；`AGENTS.md`「前后端与 UI 三项对齐（强制）」章。

## D-25 UI 文案由本地化字典拥有，样式归属有测试锁定

- **Decision**：新增 Client UI 文案走 `ctx.locale.register(NS, {zh, en})` + `ctx.locale.bind(NS)` 类型化命名空间字典；UI 注入一律走宿主 slots（实证路径：`settings.section`、`sidebar.schedule`、`conversation.input.*` 等）；codex-ui 侧栏颜色约束归便携版主题层，页面每次重载恢复主题。
- **Reason**：散落硬编码文案/样式会在插件升级（如 codex-ui 0.2→1.1 变量命名空间 `--dcu-sidebar-*`）时整片失效。

## D-26 上游有价值技术「评估后按本仓库痛点重实现」，不照搬官方私有实现

- **Decision**：官方桌面（私有实现）与便携版方向趋同（不可变槽/清单哈希/启动进度页）但互不移植；个别技术（目录链接暴露共享包、renderer 独立启动页）走评估流程（沙箱实验 → 评估文档 → 采纳/否决）后按本仓库痛点重实现。
- **Reason**：官方 `apps/desktop` 是私有代码不可依赖；但痛点同构，官方方案是可行性佐证（link 迁移即由此触发，见 D-02）。
- **Therefore**：看到官方新能力先写评估文档，而不是直接抄或直接忽略；评估文档是决策链的一部分。
