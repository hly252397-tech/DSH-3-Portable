## 1. 冷启动数据流（双击 DSH便携版3.exe）

> 实际入口是仓库根 `DSH便携版3.exe`（启动器），它转调 `Start-DSH-Portable.ps1`；下述从该 ps1 开始。

1. **启动器环境设置**：`Start-DSH-Portable.ps1:12-13` dot-source `Portable-Environment.ps1` 并调 `Set-DshPortableEnvironment` → 设置 `DSH_PORTABLE_ROOT / HOME / TEMP(=Data\Temp) / ELECTRON_BUILDER_CACHE` 等全量变量（Portable-Environment.ps1:38-77），并重置 pnpm `.modules.yaml` 中的绝对路径（同文件尾段「Rebase the two known portable profiles」）。JS 侧等价实现在 `src/portable-paths.ts:76-111 applyPortableEnvironment`（main.ts:49-52 启动即调）。
   **⚠ `DSH_HOME` 不再是 `Data\DSH`**：真实值按**家园代际**推导——`Data/Updates/Harness/homes/<runtimeVersion>.json` → `generation` → `DSH_HOME = Data/DSH-generations/<代>/home`（`portable-paths.ts:95,110-118,172`）。详见第 6 节。
2. **重启接管握手**：`-WaitForProcessId > 0` 时写 `handoffs/*.ready` 并等旧桌面主进程退出、Chromium 子进程清空（Start-DSH-Portable.ps1:235-258）。
3. **桌面槽指针读取**：读 `Data\Updates\Desktop\pointer.json`（:128-134 `Get-DesktopPointer`），解析 `current` / `pending` 引用；无指针或指针损坏时回落 `App\DSH Codex Desktop.exe`（:263-267）。
4. **健康检查/回滚（候选激活分支）**：`pointer.pending` 存在时——
   - `Resolve-SlotApplication` 校验槽内 5 件必需文件 + `slot-manifest.json` 的 SHA256 与 schema/version 匹配 + 11 个关键文件的逐文件哈希（:74-126）；
   - `activation-attempt.json` 已存在 → 拒绝重复尝试，`Restore-CurrentDesktopPointer`（:221-233，重写 pointer 为 current，state phase=`rolled-back`）后启动当前槽（:287-295）；
   - 否则写 attempt 文件、注入环境变量 `DSH_DESKTOP_UPDATE_TRANSACTION` / `DSH_DESKTOP_UPDATE_HEALTH_FILE`（:301-302）、state phase=`validating`（:303 `Set-UpdateState`，state.json 字段：phase/currentVersion/overallProgress=97/stageProgress=20/targetVersion/transactionId/slotRelativePath），启动候选并以 `health.json` 出现 + `startup-progress.json` 心跳续租（3 分钟租约 / 15 分钟硬限）判定成败（:305-325）；
   - 失败 → 先撤销 pending 再杀候选进程，恢复当前槽（:327-339）。
5. **Electron 启动**：`Start-DesktopApplicationReliable` 最多 3 次尝试启动，带 `--user-data-dir=Data\Electron\UserData --disk-cache-dir=Data\Electron\Cache`（:170-213）。
6. **主进程初始化**：main.ts 识别便携根（portable-paths.ts:47-69，槽布局 `Data/Updates/Desktop/slots/<...>` 也被认出）、应用环境变量；显示 startup 窗口；首启解压 `resources\dsh-runtime.tgz` / `plugins-store.tgz` 到 `Data\Runtime` 缓存（main.ts:824-853，extract-runtime.ts 子进程 + `DSH_EXTRACT_PROGRESS` 进度行）。
7. **运行时槽选择**：`resolveActiveRuntimeDir(Data\Runtime\dsh-runtime)` 读 `Data\Runtime\Harness\current.json`，current 坏则 previous，再坏则旧固定目录（runtime-slots.ts:54-62）；启动自愈 `recoverInterruptedRuntimeSwitch` 对未提交指针（`pendingTransactionId` 非空）自动回滚（:136-141）。
8. **插件与 profile 准备**：`seedBundledPlugins`（main.ts:874）→ 指纹槽早返回 + `reconcileOfficialRuntimeManifest` 自愈（plugin-seed.ts:557-567）；`applyPendingProfileUpdates`（main.ts:885）消费社区 pending；`installDesktopBridge`（main.ts:896）；会话日志修复（:897-905）。
9. **DSH Web 启动与 readiness**：`startDsh`（main.ts:931；dsh-process.ts:43-59）以 node + `dsh-bootstrap.mts` + `web --port 0 --no-open` 拉起（DSH_RUNTIME_DIR=活动槽）；`parseReadyUrl` 从 stdout 抓 `dsh web: http://127.0.0.1:<port>/?token=...`（readiness.ts:3-20）→ `waitForHttpHealth` 验证首跳 200 或 303+Set-Cookie（dsh-process.ts:173-202），超时 45s。
10. **就绪收尾**：主窗口加载 `server.url`（main.ts:942）；候选分支写健康文件 `confirmRunningCandidate`（:948-953；portable-desktop-update.ts:376，校验 pending 事务一致后落盘 health.json，启动器随后退出循环，state phase=`completed`）；15 秒后首次 harness 更新检查 `configureHarnessUpdater`（:954-965；HARNESS_INITIAL_CHECK_DELAY_MS=15_000，:2847）；启动失败且处于候选事务时 `app.exit(1)` fail-closed 让启动器立即回滚（:967-977）；错误落 `Data\Electron\UserData\startup-error.log`（:1139、:1267）。

## 2. 桌面自动更新数据流（桌面外壳本体）

1. **发现**：`checkDesktopUpdate('background')` 延迟触发（main.ts:2841-2844）或设置页手动（:1709）；`fetchLatestRelease` 拉 GitHub Release（portable-desktop-update.ts:748-773，拒绝 draft/prerelease，`compareReleaseVersions` 判新）。
2. **发布源**：默认 `MichengAI/dsh-codex-desktop`（:82-86），可被 `Data/config/desktop-release-source.json` 覆盖（:676-690）。
3. **下载/校验/建槽**：state.json phase 依次 `checking→downloading→verifying→building→deploying→validating→completed`（phase 白名单 :694）；下载 zip → SHA256 + 便携发布契约 `REQUIRED_PORTABLE_CAPABILITIES`（:181-187）→ 解压到 `Data/Updates/Desktop/slots/` 候选槽 + 写 `slot-manifest.json`。
4. **指针置 pending**：pointer.json 写入 `pending = {relativePath, version, sha256, transactionId}`（保存同 :731-734 原子写）。
5. **启动切换**：重启后走 §1 第 4 步候选激活分支。
6. **验证/回滚**：候选 Electron 就绪后写 health.json → 启动器视为通过（state `completed`）；任何失败/超时/重复尝试 → `Restore-CurrentDesktopPointer` → state phase=`rolled-back`（Start-DSH-Portable.ps1:221-233），槽由 `prunePortableDesktopSlots` 在提交点后回收（portable-desktop-update.ts:553-564）。

## 3. DSH 运行时（Harness）自动更新数据流

触发：15s 首查/每 `checkIntervalHours`(默认 6h) 周期（main.ts:2856-2876）或桥接 IPC `request-harness-update`（desktop-host.ts:133 → main.ts:1165-1168 → `startHarnessUpdateTask(true)` :2880，手动=interactive 永远过闸门）。

1. **checking**：state.json → `phase:'checking'`+新 transactionId（main.ts:2918）；`checkHarnessUpdate` 查 npm dist-tags `[alpha,next,latest]`（harness-update.ts:355）→ 候选需 SHA512 integrity + registry 签名 + GitHub 标签 commit（:369-397）→ 与 `BUILTIN_TRUSTED_HARNESS_RELEASES` 比对 integrity+commit 才 `automaticEligible`（:399-417）；未受信只 `phase:'blocked'` 通知。
2. **retry-gate**：`evaluateDeploymentRetryGate`（:274-289）——同版本 `deploymentFailures[version].attempts ≥ 2`（`maxAutomaticDeployAttempts`）且未过 24h 冷却时自动轮 blocked；interactive 放行（main.ts:2959-2983）。
3. **building**：`acquireHarnessUpdateLock`（Data/Updates/Harness/locks/update.lock，30 分钟过期）；`buildHarnessRuntimeCandidate` 在 `Data/Runtime/Harness/slots/.staging-*` 写清单（resolutionMode=time-based）→ 随包 pnpm 安装 → `validateHarnessRuntimeCandidate`（入口/家族对齐/lock 含受信 integrity/来源白名单/家族无混用）→ 写 `.dsh-runtime-fingerprint` → rename 成 `slots/<ver>-<指纹16>` 不可变槽（harness-runtime-candidate.ts:26-63）；失败指数退避重试 `maxDownloadRetries`=3（main.ts:3066-3085）。state：`phase:'building'`。
4. **shadow-validating**：`validateHarnessShadowStart` 造 `Data/Updates/Harness/canary/shadow-*` 一次性 profile（只含官方 bundles，harness-shadow.ts:12-28）→ 以候选槽为 DSH_RUNTIME_DIR 真实启动 + HTTP readiness（main.ts:3022-3042，超时 `shadowStartupTimeoutSeconds`=60）。state：`phase:'shadow-validating'`。
5. **waiting-idle**：连续 30s（`idleQuietSeconds`）无运行任务/回收/市场操作（`waitForHarnessIdle` main.ts:3087-3098，最多等 10 分钟），忙则 `phase:'blocked'`、候选槽保留复用（:3044-3049）。
6. **switching（启动切换）**：`activateRuntimeSlot` 重写 current.json：`current=候选`、`previous=旧槽`、`pendingTransactionId=<事务>`（runtime-slots.ts:70-99）→ 停旧 DSH 子进程 → 以新槽启动 → state `phase:'switching'`（main.ts:3123-3149）。
7. **observing / 提交**：5 分钟（`observationMinutes`）在线观察，异常退出即触发回滚；期满 `commitRuntimeSlot` 清 `pendingTransactionId`、写 `committedAt`（runtime-slots.ts:101-110），state → `phase:'succeeded'` + `lastSucceededAt`，并 `clearDeploymentFailure` 清该版本失败记录（main.ts:3151-3174）。
8. **回滚**：观察失败或启动异常 → `rollbackRuntimeSlot`：current→previous、`lastFailed={failedAt,reason}`（runtime-slots.ts:112-133）→ 用旧 startOptions 恢复服务（main.ts:3175-3210），state → `phase:'rolled-back'` + `recordDeploymentFailure` 记一次失败。进程在观察期直接崩溃时，下次启动 `recoverInterruptedRuntimeSwitch` 兜底回滚（runtime-slots.ts:136-141）。

## 4. 本地构建部署数据流（Build-DSH-Portable.ps1）

1. **环境**：dot-source Portable-Environment.ps1（Build-DSH-Portable.ps1:7-8）——TEMP/TMP→`Data\Temp`、ELECTRON_BUILDER_CACHE→`Data\Development\electron-builder-cache`（electron-builder TEMP 坑的修复点）。
2. **工具链**：按 package.json `engines.node` + `config.bundledNodeSha256['win32-x64']` 校验/下载便携 Node 到 `Tools\node`（:18-42）；便携 pnpm 到 `Tools\pnpm`（:44-50）；npmmirror Electron 镜像兜底（:59-61）。
3. **门禁**：`pnpm install --frozen-lockfile`（:68）→ `pnpm test`（:77-80，`-SkipTests` 可跳）→ `pnpm run pack`（electron-builder，:81-82）；产物校验 `release\win-unpacked\DSH Codex Desktop.exe`（:88-91）。**任何失败 throw，不部署**。
4. **候选暂存**：调 `dist\scripts\stage-local-desktop-candidate.js <root> <builtApp> <version> --replace-pending`（:94）——
   - 后台预热候选共享环境 `preparePackagedRuntimeCacheInChild`（stage-local-desktop-candidate.ts:16-25，活动槽已是指纹槽时跳过官方解压）；
   - `stageLocalDesktopBuild`（portable-desktop-update.ts:464-551）：校验源 App（`validatePackagedApp` + REQUIRED_APP_FILES）→ 复制到 `Data/Updates/Desktop/transactions/<tx>/app` → 写 `slot-manifest.json` 并自校验 → rename 到 `slots/<version>-local-<sha16>`（已存在同名槽则复用）→ pointer.json 写 `pending{transactionId}`（已有 pending 且未 `--replace-pending` 时抛 `PENDING_ACTIVATION`，:485-487）→ state.json `phase:'deploying'`（overallProgress 94）→ events.jsonl 记账 → `prunePortableDesktopSlots` 回收历史槽（:545）。
   - **全程不触碰 `App\`、不结束桌面进程**（脚本 :93 明示「不会覆盖或结束当前 App」）；切换与验证/回滚交给 §1 第 4 步的启动器候选激活分支。

## 5. 与 profile 插件更新的边界

- 社区插件更新：`.dsh-pending-updates.json` 只消费社区条目（plugin-seed.ts:488-501），官方条目读出后**丢弃**、文件无条件删除（:502-510）——防 codex-ui 幽灵 pending 回写（AGENTS.md 坑）。
- 官方运行时更新的唯一权威是 §3 的 A/B 更新器；桥接 `request-harness-update` 只是触发器（desktop-host.ts:133）。插件「关于」页 npm `next` 标签与外壳发现通道 `[policy.channel, next, latest]`（harness-update.ts:355）必须一致改。

## 6. 家园代际隔离数据流（官方兼容基线所称「数据安全核心」）

**目的**：不同 DSH 运行时版本的用户数据**互不污染**。每个运行时版本绑定一个**代号代际**，数据按代际落盘；旧版本继续读它自己那一代，绝不写进别人的家。

### 6.1 绑定解析（`src/portable-paths.ts:90-125`）

```
Data/Updates/Harness/homes/<runtimeVersion>.json     ← 绑定声明（schema=1）
        │  内容例：{ "schema":1, "runtimeVersion":"0.1.7-rc.2", "generation":"v4-rc2b" }
        ▼
Data/DSH-generations/<generation>/home               ← DSH_HOME（:114）
Data/DSH-generations/<generation>/runtime/dsh-runtime ← 该代际的运行时目录（:115）
```

- 代际名**受白名单校验**：`/^[a-z0-9][a-z0-9_-]{0,95}$/i`（`:110`），非法即拒绝——防路径穿越。
- **越界防护**：`realpathSync` 解析后必须仍落在 `Data/DSH-generations/<代>/` 之内（`:117-118`、`:123`）；解析失败或越界 → **fail-closed**（宁可不启动，也不写进错误代际）。
- `DSH_HOME` 由此推导后注入子进程（`:172`）。

### 6.2 启动期数据流（与 §1 的对应关系）

| 阶段（§1 步号） | 家园代际相关动作 |
|---|---|
| 1 环境设置 | 读 `homes/<runtimeVersion>.json` → 算出 `DSH_HOME` / `runtime`，注入环境变量 |
| 6 主进程初始化 | 解压产物落到**代际目录内**的 `runtime/dsh-runtime`（不再是全局 `Data\Runtime\dsh-runtime`） |
| 7 运行时槽选择 | **两套并存**：`Data/Runtime/Harness/current.json` → `slots/<版本>-<指纹>` 是**官方运行时的 A/B 槽**（§3）；代际目录下的 `runtime/dsh-runtime` 是该代际的**数据归属根**。改动任何一侧都要同步 `homes/*.json` |
| 8 profile 与插件 | profile 落在 `DSH_HOME` 之内 ⇒ 插件的安装/升级只影响**当前代际** |
| 10 就绪收尾 | 会话日志、附件、知识库等全部落在当前代际的 `home` 下 |

### 6.3 与冻结 legacy 面的关系

- `Data/DSH` 是**上一代的冻结面**，供旧版本继续读取；**新版本不写它**。
- `Data/DSH-generations/v4-rc2-old1` 是更早一代的遗留目录（保留备查）。
- `App/dsh-runtime` 是 **legacy 回退运行时**（`0.1.2-alpha.3`，2026-09-26 实测），仅在 slots 全不可用时兜底；它**不是**代际目录，也不承载用户数据。

### 6.4 改动禁区

- 不得手改 `homes/*.json` 的 `generation`（会让运行中的数据"换了家"）。
- 不得跨代际复制 `home` 内容（会话日志/附件/知识库的路径与 cid 会失配）。
- 代际目录的 `realpath` 校验是安全边界，**不要为"方便"放宽**。
- 迁移/合并代际属于独立迭代，必须走 A/B 候选 + 明确回滚点。
