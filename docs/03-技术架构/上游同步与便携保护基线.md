## 5. 固定升级流程（10 步）

1. **独立同步工作区**（干净克隆）；禁止在有大量本地改动的工作区直接 merge/rebase/覆盖式同步
2. 拉取上游指定 tag（认祖后注意 `git tag -f v<版本>` 把标签名声明给便携仓库自己的发布提交）
3. 生成上游差异清单（`git log/diff <旧tag>..<新tag>`，逐提交按 §4 分类）
4. 先合并普通源码（C 档）
5. 人工处理保护文件（A/B 档；B 档逐 hunk + 字节 diff 复核）
6. 更新 Runtime 和插件矩阵（`resolutionMode: time-based` 三入口同写；官方运行时绝不原地安装，走 A/B）
7. 门禁：`pnpm check` → `pnpm test` → `pnpm spec:check` → `scripts/ui-baseline.mjs`
7b. **运行时升级专项核对：会话"打开方式"体检**（2026-09-28 事故新增——官方 0.1.7-rc.2 升级改道聊天视图文件打开器、绕过 `workspaces.openPath` wrap，旧拦截静默失效直到用户点出弹窗）。运行时/官方 web 包升级后必须跑 **一键体检：`Tools/node/node.exe scripts/gate-node-run.mjs scripts/check-open-behavior.mjs`**（30 秒，6 项：插件存活 / 官方 fileLink DOM 形态（title/文本路径可解析率）/ 文件卡片拦截器活性 / 开进编辑器卡 / https 外链拦截器活性 / broker 通道；2026-09-28 实跑 6/6 PASS 模板。**体检脚本已于 2026-09-29 改为跟随活动代际**——此前它把 broker token 钉死在 `v4-rc2b`，而 0.2 起的活动代际是 `v5-020rc1`，钉死会导致鉴权失败、原理性跑不通；端口与探针文件也改为按便携根解析，不再写死盘符）。任一 FAIL 按脚本尾部的三层排查指引修（类名形态/路径来源/注册链路），修复实录见 [20260928-会话文件卡片开进侧边栏](../01-当前工作/20260928-会话文件卡片开进侧边栏.md)。判定依据是 better-sidebar 的 `registerLinkInterception` / `registerFileLinkInterception`（DOM 捕获层，类名 `fileLink` 子串 + title/textContent 路径）——官方若改类名后缀、title 携带路径或打开器行为，体检即红。日常也可随时跑（副作用：体检会开 1-2 个 PROBE 标记的侧栏卡片，可随手关）。更新已锁 manual（2026-09-28 用户决定），自动升级不再发生，本关卡由手动升级触发
8. 重新打包并暂存候选槽（`Build-DSH-Portable.ps1` → `stageLocalDesktopBuild`；全量门禁红在他人改动上时可 `-SkipTests` 但 tsc 与定向用例必须单独补跑并记录）
9. **激活窗口必须安静**：无构建/回收清理、无其他会话写 `Data/DSH`（止损纪律 4+7；2026-09-19 两次真实回滚均因窗口撞上外部写入）→ 请用户重启
10. 健康验证通过 → `confirmRunningCandidate` 提交 → `prunePortableDesktopSlots`（只留 current + previous 两版）

失败任意步：候选自动回滚（fail-closed），归因先查四件套——`Data/Electron/UserData/startup-error.log`、`Data/Updates/Desktop/transactions/`、`Data/Updates/Desktop/events.jsonl`、`Data/Updates/Desktop/launcher.log`，**先找原因再改代码，不要先动更新器**（2026-09-19 16:15 实例：ENOENT 实锤外部写入干扰，候选内容排除）。

## 7. 目录职责与三条规则

`App/`（启动入口与默认资源）、`Data/`（`Updates/Desktop`、`Runtime/Harness`、`DSH`、`Electron/UserData`、`config/`）、`customizations/ui/`（定制+基线+证据）、`Customize/`（可复用定制工作台）。职责细节见 [00-桌面启动器架构基线](00-桌面启动器架构基线.md) 与 [UI 定制维护契约](UI定制维护契约.md)，此处只固化三条不可破规则：

1. **不直接改正在运行的槽**（现役槽只读；一切变更先进新槽）；
2. **不覆盖 `Data/DSH`、`Data/Electron`、`customizations/`**（用户数据、凭据、定制证据）；

## 9. 差异台账：逐次吸收中「刻意不跟」的上游改动

> 规则：本节记录**已审阅但决定不吸收**的上游改动及其理由。混合文件禁止整文件取上游时，
> 必须先在此登记，否则下一个人会把"漏合并"当成"可随手补上"。

### 9.1 上游 v1.0.77（2026-09-29）：Windows zip 版不能原地安装 → 改为下载 zip

- **上游做了什么**：`src/desktop-updater.ts` 新增 `installable` 快照字段与 `canInstallDesktopUpdateInPlace()`
  （判据：Windows 下 `execDir` 里有没有 `Uninstall DSH Codex Desktop.exe`）；`DesktopUpdateAction`
  新增 `open-archive`；托盘与设置页在 `installable === false` 时改为"下载压缩包"并打开 release zip；
  `src/main.ts` 的 `checkDesktopUpdate` / `downloadDesktopUpdate` / `installDesktopUpdate` 全部先过这道闸。
- **不吸收的理由**：**该判据的前提对本仓库不成立，照搬会造成功能倒退。**
  上游的前提是"桌面更新 = electron-updater 下载 NSIS 安装包 + `quitAndInstall` 原地替换"，
  而 Windows 解压版没有卸载器、装不了原地。本仓库的桌面更新走的是
  `portableDesktopUpdater.prepare()`（`src/main.ts:4248`）—— A/B 候选槽暂存 → 影子验证 → 空闲切换 →
  观察窗口 → 失败自动回滚，**全程不需要 NSIS，也不需要卸载器**，这正是现役 1.0.76 能从
  `release/win-unpacked` 自更新的原因。
  若吸收，`runningDesktopUpdateInstallable()` 对便携版恒为 `false`，便携版自更新会被降级成
  "请用户自己去下载 zip 手动替换"——把一条已经跑通的自动通道关掉。
- **结论**：`src/desktop-updater.ts` 与 `assets/settings.html` 的 `installable` / `open-archive`
  相关改动**整体不吸收**。判断依据不是"便携版也是 zip"，而是"我们的安装器是 A/B 槽，不是 NSIS"。
  将来若真要引入 NSIS 安装包形态，再连同这条一起评估。
