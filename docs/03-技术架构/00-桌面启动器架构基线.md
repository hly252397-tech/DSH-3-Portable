# 桌面启动器架构基线

状态：已实现，生产候选待完整 A/B 激活演练
更新时间：2026-09-02（Asia/Shanghai）

## 1. 架构与便携边界

运行链路为：

`DSH便携版3.exe → Start-DSH-Portable.ps1 → 当前桌面槽 → 内置 Node 24.20.0 → DSH Runtime Slot → 127.0.0.1 随机端口 → Electron 外壳`

所有可变数据都在便携根目录：

- Electron 配置、缓存和日志：`Data/Electron/`
- DSH 配置、凭据引用、Profile、会话和对话：`Data/DSH/`
- 官方运行时 A/B 槽：`Data/Runtime/Harness/`
- 桌面更新 A/B 槽、事务、状态和审计：`Data/Updates/Desktop/`
- 用户项目：优先使用 `工作空间/`，兼容既有 `Workspace/`

指针只存相对路径，换盘符后仍可定位。更新不得清理 `Data/`、`工作空间/` 或用户插件目录。

## 2. 启动与恢复顺序

1. C# 启动器只负责单入口、前台激活和调用 PowerShell 启动器，不直接判断固定 `App/` 是否存在。
2. PowerShell 启动器读取 `Data/Updates/Desktop/pointer.json`，校验候选清单自身摘要及关键文件 SHA256。
3. 有待部署候选时，启动器设置事务和健康文件环境变量后启动候选；180 秒内必须完成 Electron、DSH readiness 和主窗口健康确认。
4. 健康确认后原子提交当前槽并写 `completed`；超时、异常退出或摘要不一致则恢复上一槽并写 `rolled-back`。
5. 没有候选时启动当前指针槽；首次或兼容场景才回退到 `App/`。

候选失败时只先请求候选窗口正常关闭；8 秒仍未退出才按已记录 PID 结束候选进程树。禁止按进程名结束系统中的 Node 或 DSH。
失败事务的尝试标记在启动候选前落盘；同一事务只允许启动一次。回滚必须在清理失败候选前先原子撤销 `pending`，避免启动器清理过程被中断后重复进入坏槽。

## 3. 桌面更新单一入口

桌面更新的唯一实现为 `PortableDesktopUpdater`：

- 来源固定为 `MichengAI/dsh-codex-desktop` 稳定 GitHub Release；
- 只接受 Windows x64 的精确 ZIP 资产名、HTTPS 允许域、GitHub 资产 SHA256、声明大小和版本；
- 下载到 `.partial`，验证后解包到独立事务目录，再同卷提交到不可变 `slots/`；
- 本地 `Build-DSH-Portable.ps1` 也进入同一 A/B 候选协议，不覆盖 `App/`；
- 工具栏更新图标与设置页共享同一状态，显示检测、下载、验证、构建、部署、完成及总进度；
- 桌面切换只在用户确认后正常关闭 Electron，再交给外部启动器完成。

已删除并禁止恢复原有 `Update-DSH-Portable*`、`Update-Portable-Files*`、`Sync-Upstream-Source.ps1`、`deploy-new-build.ps1` 及同类原地覆盖脚本。

## 4. 生命周期边界

| 对象 | 切换单位 | 中断范围 | 回滚 |
| --- | --- | --- | --- |
| Electron 桌面 | 整个不可变桌面槽 | 正常退出并重启桌面 | 外部启动器恢复上一槽 |
| 官方 Harness | 不可变 Runtime Slot | 只回收 DSH 子服务 | 原子恢复运行时指针 |
| 社区插件 | 单插件/Profile 事务 | 只回收 DSH 子服务 | 清单备份、隔离与恢复 |
| 用户源码定制 | 构建为桌面候选槽 | 不影响当前运行实例 | 未通过健康验证不提交 |

安装或更新插件不应退出 DSH Desktop。只有桌面二进制自身切换才需要退出 Electron。

## 5. 启动故障自愈

- 启动前执行社区 bundle 完整性检查；损坏社区插件只从启用清单隔离，不删除文件或依赖。
- 会话目录因盘符/工作区名称历史变化错位时，读取每个 jsonl/zstd 会话头，只有头部 `cwd` 与物理目录能形成精确一一映射时才修复。
- 会话目录移动前必须完整备份到 `Data/Electron/UserData/session-path-repair/`；不改写对话日志字节。
- 官方 bundle 或运行时损坏不得伪装成社区插件错误，应进入 Runtime Slot 修复或回滚流程。

## 6. 安全门禁

- Electron 使用 `nodeIntegration: false`、`contextIsolation: true`，导航只允许本地 DSH loopback 源。
- 候选必须包含 exe、`app.asar`、Node、两类归档及其 sidecar、桌面桥和进程控制文件；清单及关键文件全部做 SHA256。
- Electron 对 `node:fs` 有 ASAR 虚拟文件系统补丁；读取 `app.asar` 归档本体的 SHA256 必须使用 Electron `original-fs`，否则会把归档当目录并误报 ENOENT。
- 路径必须经过便携根目录边界检查，拒绝绝对路径、`..` 和目录逃逸。
- 日志与状态全部落在便携盘；UI 展示脱敏错误，详细审计使用事务 UUID。
- `Start-DSH-Portable.ps1`、`Build-DSH-Portable.ps1` 必须可被 Windows PowerShell 5.1 解析，包含中文的脚本保持 UTF-8 BOM。

## 7. 完成定义

“构建完成”只表示候选已产生；“部署完成”必须同时满足：候选清单复验通过、候选由启动器启动、DSH readiness 成功、主窗口确认、健康文件落盘、指针提交、状态进入 `completed`。任一步失败都不能显示完成。
