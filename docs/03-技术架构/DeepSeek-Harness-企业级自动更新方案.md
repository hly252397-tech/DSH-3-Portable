# DSH 便携版 3：统一更新与企业级投产方案

状态：**企业级候选实现；尚未宣称企业级投产**

核对日期：2026-09-04（Asia/Shanghai）
官方来源：[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)、[DSH Desktop](https://github.com/MichengAI/dsh-codex-desktop)

## 1. 决策摘要

更新采用一个用户入口、两个独立事务协调器：

- 桌面协调器负责 GitHub Release 和本地源码构建，使用不可变桌面槽、外部启动器、健康提交和自动回滚；
- Harness 协调器负责官方运行时，使用不可变 Runtime Slot、影子启动、空闲门禁、只重启 DSH、5 分钟观察和自动回滚；
- 社区插件继续走 Profile 事务及隔离恢复，只回收 DSH 子服务；
- 所有状态、下载、槽、备份、审计、对话和工作区都留在便携盘。

“安装插件后退出桌面”不符合生命周期边界，禁止实现。桌面宿主只在替换桌面二进制时正常重启。

## 2. 当前已实现

### 2.1 桌面端

- 唯一 Release 来源：`MichengAI/dsh-codex-desktop` 的稳定 GitHub Release。
- 只接受精确 Windows x64 ZIP，检查 HTTPS 来源、版本、资产大小、GitHub SHA256、磁盘空间和 ProductVersion。
- Release 必须同时提供 `dsh-portable-contract-<version>-win-x64.json` 兼容契约；客户端在下载大包前校验契约自身摘要、制品摘要及 `portable-data-v1`、`desktop-ab-v1`、`desktop-update-state-v1`、`embedded-browser-v1`、`runtime-prewarm-v1` 五项能力。缺失或不兼容时在检测阶段拒绝，禁止官方原始包覆盖便携定制能力。
- 下载、验证、解包、候选构建均在 `Data/Updates/Desktop/` 下进行；关键文件闭包写入 `slot-manifest.json`，指针锚定清单 SHA256。
- `Build-DSH-Portable.ps1` 的本地定制构建进入相同 A/B 候选槽，绝不覆盖当前 `App/`。
- 桌面候选在写入 pending 前后台预热共享运行环境；当前桌面在下载、校验、解包和预热期间保持可用，正常重启只执行槽切换、DSH readiness 和健康提交。
- 归档同时携带字节 SHA256 与逻辑内容 SHA256：前者验证下载和制品完整性，后者排除 tar/gzip 时间戳差异并跨桌面构建复用同一缓存。启动阶段重新解压仅用于断电或缓存损坏后的自愈。
- 正常关闭桌面后，外部启动器复验清单并启动候选；900 秒绝对上限内收到健康文件才提交，否则自动恢复旧槽。该上限覆盖低速便携盘首次解压插件仓库的合法耗时，过程仍由心跳租约约束，不能无限等待。
- Electron 内复验使用 `original-fs` 读取物理 `app.asar`，避免 ASAR 虚拟文件系统把归档本体误判为目录；失败事务只允许启动一次，且先撤销 pending 再清理进程。
- 已验证的 Release 缓存按资产大小和 SHA256 双重校验后复用；缓存不完整或摘要不符立即清除，禁止把损坏缓存送入候选构建。
- 工具栏更新图标及设置页显示总进度和检测、下载、验证、构建、部署、完成六阶段。
- 所有旧的同级更新、源码覆盖和原地部署脚本已删除，避免双写和绕过门禁。

### 2.2 官方 Harness

- npm `alpha` 与 GitHub 不可变 tag/commit 交叉核对；未知版本不能静默自动切换。
- 构建完整依赖闭包，校验 npm integrity、包名/版本、家族包实际版本、路径和运行时入口。
- 候选写入 `Data/Runtime/Harness/slots/`，先以隔离 DSH_HOME、随机 loopback 端口和真实 Profile 快照完成影子 readiness。
- 等待连续 30 秒无运行任务、审批或插件事务后，只重启 DSH 子服务；Electron 保持运行。
- 新槽上线后观察 5 分钟；崩溃、健康失败或协议错误时恢复上一运行时槽。
- `0.1.2-alpha.5` 已核对 npm integrity、GitHub tag commit，并在本机完成最小影子启动和当前社区 Profile 隔离兼容启动，因此进入内置受信候选清单。

### 2.3 启动错误修复

- 已引入会话路径精确修复器：读取 jsonl/zstd 会话头，根据其中 `cwd` 重建 DSH 项目键。
- 只有“日志可读、头部 cwd 明确、目标一一对应、无冲突”时才移动目录；移动前完整备份，日志内容不改写。
- 该修复在启动 DSH 前执行，处理 U 盘盘符或中英文工作区历史变化导致的 `dsh p` 启动失败。

## 3. 统一状态和用户体验

| 可视阶段 | 桌面状态 | 成功条件 |
| --- | --- | --- |
| 检测 | `checking` | Release 元数据与版本有效 |
| 下载 | `downloading` | 字节数完整，`.partial` 下载结束 |
| 验证 | `verifying` | 大小、SHA256、版本、来源通过 |
| 构建 | `building` / `ready` | 不可变槽和清单完成复验 |
| 部署 | `deploying` / `validating` | 用户正常退出，启动器拉起候选 |
| 完成 | `completed` | DSH readiness、主窗口与健康文件提交 |

失败使用 `error`，自动恢复使用 `rolled-back`。UI、`state.json` 和 `events.jsonl` 必须由同一状态转换生成，不允许 UI 自行推断“完成”。

## 4. 数据与目录契约

```text
Data/Updates/Desktop/

  downloads/

Data/Runtime/Harness/

Data/Updates/Harness/
```

所有指针保存便携根目录相对路径。`Data/DSH/`、`Data/Electron/`、`工作空间/` 和社区插件不属于桌面制品，任何更新流程都不得删除或覆盖它们。

## 5. 故障与恢复合同

| 故障 | 必须行为 |
| --- | --- |
| 无网络、超时、Release 不存在 | 保持当前槽；错误可见；允许重试 |
| 非允许域、错误资产名、预发布或缺少便携兼容契约 | 检测阶段拒绝；不得下载或部署原始包 |
| 大小、SHA256、版本或清单不符 | 候选拒绝；当前槽不变 |
| 下载、解包或构建中断 | 下次标记事务中断；不得提交半成品 |
| 候选共享环境预热失败 | 不写入/不替换 pending；当前桌面继续运行 |
| 桌面候选不能启动/readiness 超时 | 撤销 pending，恢复并启动上一槽 |
| Harness 影子验证失败 | 不切换生产运行时 |
| 用户任务仍在运行 | 推迟 Harness 切换，不强杀任务 |
| Harness 观察期失败 | 90 秒目标内恢复旧指针并验证旧槽 |
| 会话路径不确定或目标冲突 | 不移动，记录审计并显式报错 |
| U 盘盘符变化 | 相对指针和便携环境重新解析 |

### 6.1 2026-09-04 桌面更新故障修复记录

- 现象：官方 `1.0.46` ZIP 已完成大小和 SHA256 校验，但候选在 78% 被误报 `PACKAGE_INCOMPLETE`，重试又重复下载；外层异常处理随后把可诊断进度覆盖成 0%。
- 根因：Electron 的 ASAR 虚拟文件系统把物理 `resources/app.asar` 暴露为目录语义，候选闭包校验和失败清理错误使用了被补丁化的 `fs`。
- 修复：物理文件判定、摘要读取和事务清理统一使用 `original-fs`；已验证缓存直接复用；检测失败写入 `lastCheckedAt`；外层错误包装保留底层进度、错误码和事务号；设置页显示完整诊断。
- 回归证据：真实 `1.0.46` 缓存资产大小为 `351005311` 字节、SHA256 为 `ee23e50b557ed648425e42b9e1827cd87baf6de1a35fab2474ac40207bc79e67`；候选物理 ASAR 冒烟和全量自动化测试均通过。

### 6.2 2026-09-04 官方 1.0.46 兼容集成记录

- 第二层现象：修复物理 ASAR 读取后，进度能够正确保留在 78%，但官方包被报缺少 `resources/desktop-bridge/profile-bundle-health.js`。
- 根因：更新器把当前便携定制版的静态桥接文件清单用于验证不同版本的官方包。官方 `1.0.46` 采用自己的 `recovery-mode.js` 闭包，制品本身没有损坏；直接删除文件门禁虽能通过验证，却会让原始官方包覆盖完整版内嵌浏览器、便携数据隔离和 A/B 更新能力。
- 修复：发布 CI 为便携发行版生成机器可读兼容契约并与 ZIP 一同发布；客户端先验证契约和能力集合，再获取制品。没有便携兼容契约的官方原始发行版会以 `INCOMPATIBLE_RELEASE` 明确拒绝，且当前槽保持不变。
- 官方同步：以 `v1.0.46` 为基线集成通知完成徽标修复及社区插件版本，同时保留便携版浏览器、数据路径和更新事务；构建脚本新增便携 Node 摘要校验、非交互 CI 安装、Electron 二进制补全和显式禁止隐式发布。
- 部署结果：事务 `8ef00478-8c76-43a5-8e9f-30639a7bc308` 已由外部启动器完成真实 A/B 启动、健康提交并清空 pending；当前槽为 `1.0.46-local-178f0b5b95798f45`，状态 100%。

### 6.3 2026-09-04 重启阶段反复解压修复记录

- 现象：桌面候选每次切换都在启动页 15% 执行运行环境或插件仓库解压，低速便携盘需要处理约 1 GiB、近 6 万个小文件。
- 根因：缓存身份使用 tar/gzip 归档字节摘要；内容完全相同时，打包时间戳仍会改变归档摘要，从而为每个桌面构建创建新缓存。并且候选环境直到桌面退出后才准备，把重型 I/O 放进了用户不可用窗口。
- 新流程：归档增加逻辑内容 SHA256，忽略文件系统时间戳；pnpm 仓库额外忽略会记录每个文件本地 mtime 的易变 `v11/index.db`，同时把确定性的 `pnpm-lock.yaml` 固化为 `dsh-store-lock.yaml` 纳入摘要，确保包身份或内容变化仍会使缓存失效。桌面 Release 与本地构建均在当前桌面仍可使用时预热候选共享环境，通过后才能原子写入 pending。正常重启只执行槽切换、服务启动和健康提交。
- 自愈边界：启动时仍复验缓存；只有断电、人工删除或内容损坏时才进入解压自愈，并把页面明确标记为恢复流程。逻辑摘要与解压结果不一致时拒绝缓存。
- 实机证据：新候选预热时官方 Harness 命中独立活动槽并跳过，插件仓库完成后台准备；随后对真实便携根目录计算得到 `needsStartupExtraction: false`。缓存完成标记早于桌面启动验证约 9 分钟，相同内容二次构建复用同一逻辑指纹。新候选物理 ASAR 由 Electron `original-fs` 校验通过，隔离全新 Profile 最终输出 `SMOKE_PACKAGE_PASS`。

证据状态必须区别：正常退出后的外部启动器真实切换和健康提交已经通过；故意失败自动回滚、盘符变化和其余投产矩阵仍按第 7 节独立验收，不能由成功路径结果替代。

## 7. 尚未满足的企业级投产门禁

以下项目完成前，状态保持“企业级候选实现”：

1. 发布 CI 生成并签名桌面与 Harness 机器可读清单，客户端内置轮换公钥并验证发布者证明；GitHub 资产摘要不能替代独立签名治理。
2. 完成维护窗口、暂停/恢复、跳过版本、灰度组、强制/可选策略和最低桌面版本的管理 UI。
3. 执行断网、磁盘满、只读盘、下载截断、解包中断、断电恢复、清单篡改、候选崩溃循环等故障注入矩阵。
4. 在真实便携盘完成至少一次桌面成功切换、一次故意失败自动回滚、一次盘符变化恢复，并保存审计报告。
5. 由 CI 产出锁定依赖闭包、SBOM、漏洞扫描结果、制品保留与撤回记录；定义密钥轮换和发布权限双人复核。
6. 定义并监控 RTO/RPO、更新成功率、回滚率、平均验证耗时及失败版本隔离期。

## 8. 投产阶段

1. **候选阶段（当前）**：本机自动检测、完整性验证、候选构建；用户确认桌面重启。Harness 只对内置受信版本执行 safe-auto。
2. **试点阶段**：小范围设备启用签名清单、维护窗口和遥测；完成成功切换与回滚演练。
3. **灰度阶段**：按 5% → 25% → 100% 放量；每级观察成功率、崩溃率和回滚率，超阈值自动暂停。
4. **正式阶段**：全部独立验收证据归档后，才允许将文档状态改为“企业级已投产”。

## 9. 验收原则

“自动更新”不是自动覆盖文件，而是自动完成检测、获取、验证、候选构建、受控切换、健康确认和失败恢复。任何不能证明当前版本仍可启动、用户数据未受影响、失败可回滚的路径，都不得进入统一更新入口。
