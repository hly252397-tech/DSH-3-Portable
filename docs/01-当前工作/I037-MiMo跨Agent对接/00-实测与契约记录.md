### 7.1 三处 v4 契约漂移（运行槽 `0.1.7-rc.2-4d29c691bfdf224c`）

| # | 旧写法（0.1.6 时代） | 新写法（官方 v4 依据） |
|---|---|---|
| 1 | `source:{kind:'plugin', plugin:name, form:'relay'}` | `source:{kind:'plugin:'+name, form:'relay'}` —— `dsh-session-format-v3-to-v4/lib/index.js:87-93` 的 `producerKind()` 对第三方插件的产出；`MessageSourceMap` 已无通用 `plugin` kind |
| 2 | `data.message.content[0].toolCallId/isError` | `data.message.toolCallId` / `data.message.isError` —— `dsh-llm/lib/types/message.js:92-100` 的 `createToolResultMessage()` 把两者放在消息层；`content[0]` 的 `tool-result` 包装块已被 v4 退役 |
| 3 | `await listening` / 写发现文件放在**第一次 `yield` 之后** | 移到 `yield` **之前** —— `yield` 交出的是处置器，其后代码不属于加载阶段 |

### 7.2 一手证据

- **失败可确定性复现**：`assertV4RowAdmission` 对旧形状抛 `SessionFormatError: format v4 message requires a producer-owned source kind`（与生产 `POST /tasks` 的 `err_msg` 逐字相同）；对新形状 `ADMITTED`。
- **A/B 探针（同一运行时，两个 apply 形态对照）**：旧 async generator → `create()` 返回时 `fiber=1 LOADING`、发现文件未落盘，`loader.await()` 之后才 `state=2` 且落盘；thenable 形态 → `create()` 返回时已 `state=2 ACTIVE`、发现文件仍未落盘，`loader.await()` 无事可等 ⇒ **生成器形态是承重的**。
  - 结论：审核档 R-28 建议的"改成标准 `export function apply`"会**破坏**加载等待语义，实测否定，不采纳；改为在注释里写明理由以免后人再改。
- **端口被占的真实结局（0.1.7 实测）**：`create()` 不抛、`loader.await()` 不抛、条目保留，但 `fiber.state=3 FAILED` 且**不写发现文件**。0.1.6 时代的"`create()` 抛 EADDRINUSE + 条目不驻留"对**任何**插件形态在 0.1.7 上都不成立（A/B 已证），故测试改为断言可观测的失败关闭（fiber 必须 FAILED、不得发布发现文件），并给插件补了失败日志使其不再静默。
