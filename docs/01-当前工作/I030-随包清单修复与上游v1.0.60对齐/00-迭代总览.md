## 1. 更正我先前的一处误报

我最初报「你的实际安装偏旧、缺 4 项」是**错的**：当时比对的是 profile 的**声明文件**（`package.json`），而不是**实际安装的包**。以实机 `node_modules` 为准逐个核对后：16 项里 **13 项已达标**，仅 Context / MCP Connector 偏旧、usage-billing 未装。教训与前一轮同源——**要比对运行件本体，不要比对声明**。

## 2. ①修复：随包清单

`src/bundled-plugins.ts` 的 `BUNDLED_PLUGINS` 由 10 项陈旧版本改为 16 项对齐版本，并补齐
`@michengai/dsh-codex-pet` / `dsh-btw` / `dsh-simplify` / `@michengai/dsh-code-review` /
`@michengai/dsh-pua` / `@kenz1117/dsh-ui-usage-billing`。

**顺带补上让这份清单真正生效的机制**：`planBundledPluginSeed` 过去只补「缺失」的插件，已装但低于基线的**不会升**——所以清单再怎么改也影响不到已有 profile。现补上游 v1.0.55 的同名行为：
按随包基线升级**低于**基线的已装插件，并加**两道护栏**：

1. **只升不降**：已装版本不低于基线时一律不动；
2. **本地定制免疫**：用户以 `link:` / `file:` / `portal:` 声明的包（本仓库 8 个定制插件全走 `link:local/…`）
   **永不参与基线比较**——照基线「升级」会把本地定制件换成 npm 发布包，等于覆盖定制。

`installedVersions` / `localLinkPackages` 均为可选入参：不传时退化为旧的「只补缺失」，既有调用方行为不变。

### 8.1 发现并处置的一处隐患：启动补种因 pnpm 仓库不匹配而失败

- **现象**：重启后 `plugin-seed.log`（21:31:35）被写入 `[ERR_PNPM_UNEXPECTED_STORE]`：
  profile 的 `node_modules` 链接自 `G:\.pnpm-store\v11`，而该次 pnpm 命令想用
  `Data\Development\pnpm-home\store\v11`。结果：**启动补种失败，Context / MCP Connector / usage-billing 未自动补齐**。
  该项失败由本轮的「启动失败可见化」按设计弹窗提示，因此用户侧是「看得见」的，不再是静默失败。
- **已确认的机制**：环境里 `PNPM_HOME=…\Data\Development\pnpm-home` 使应用自带 pnpm 的**默认仓库**变成
  `pnpm-home\store\v11`，与 profile 实际链接的仓库不同；只要命令没显式带 `--store-dir=<profile 记录的仓库>`，
  pnpm 就必然报此错。**反证实验**：用**同一套参数并带上** `--store-dir=G:\.pnpm-store\v11 --cache-dir=G:\.pnpm-store`
  在实机上执行，一次成功（`dsh-context 0.52.1` / `dsh-mcp-connector 0.2.47` / `usage-billing 1.3.0` 全部装上）。
- **未完全定论的部分（如实声明）**：静态核对下 `resolvePnpmStoreDir(profileDir, …)` **本应**从
  `.modules.yaml` 读出该仓库并带进参数（已用编译产物实测：现在返回 `G:\.pnpm-store\v11`），
  因此"那一次为什么没带上"的触发条件**尚未复现**。旁证：`.modules.yaml` 在失败之后（21:32:15）被重写。
  不做进一步归因，避免在没有复现的前提下改代码。
- **处置**：用应用自身更新插件时的同一条路径（`pnpm add` + profile 记录的仓库）把三项装上 → 16/16 达标。
  由于现在**没有任何低于基线的插件**，启动补种的计划为空、不再执行 pnpm，该症状**自然不再出现**。
- **遗留风险（供下一轮）**：将来基线再次抬升时，若补种又一次拿不到显式仓库，仍会失败。
  建议下一轮：让补种在「profile 已有 node_modules 但解析不到仓库」时**不要发出不带仓库的 pnpm 命令**，
  而是给出明确可执行的日志/提示（而不是把 pnpm 的仓库错误原样抛出）。
