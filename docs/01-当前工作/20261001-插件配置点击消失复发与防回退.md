# 插件配置点击消失复发与防回退（2026-10-01）

状态：**已修复并在现役实例完成正反对照实机验证**；防回退机制已落地为仓库资产 + 三道零构建闸门 + 7 条回归用例 + 保护清单登记。

## 一、问题与诊断

**现象**：设置导航「插件配置」点击后从导航中消失、回落到「常规」，面板不渲染，刷新页面才恢复。

**诊断一行**：问题是 2026-09-28 已修的 `props.useStore is not a function` 缺陷在新家园 `auto-020-rc2` 原样复发；证据是活动家园 `Data/DSH-generations/auto-020-rc2/home/profiles/web/node_modules/@michengai/dsh-codex-ui/lib/client.js` 的 sha256 为 `04106142…`（09-28 记录的**未打补丁原始哈希**）、`nlink=2`（与 pnpm store 硬链），而作为其来源的 `v5-020rc1` 家园是 `00cc596e…`（已打补丁）；下一步是把补丁收编为仓库资产并在三个必经点设闸，而不是再手改一次 `node_modules`。

**根因链（与 09-28 完全同源）**：

1. codex-ui `registerPluginConfigSection` 把官方 PluginManagerPage 注册进 `settings.section` 槽时只转发 `inject`/`locale`，**漏转发 `store`**；
2. 官方页首渲染即调 `props.useStore()` → `TypeError`；
3. 崩溃经 `reportEntryError(abdicate)` 退位，`SlotCore.entriesOfSlot` **永久排除**该条目 ⇒ 导航项消失且不自愈。

**为什么这次会复发（新增结论）**：09-28 的修复方式是**就地改 npm 包文件**。`auto-020-rc2` 家园于 09-30 由 pnpm store 重新物化，store 里存的是未打补丁的原包，硬链一落就把补丁覆盖回去——这正是 AGENTS.md 所记「profile 包 specifier 领先安装是地雷」的同型事故。**只要修复还停留在"改产物"，下一次物化必然复发。**

## 二、修复（走资产，不手改产物）

新增仓库自有资产 `customizations/codex-ui-patches/`：

- `apply.mjs` —— 唯一的补丁施加/校验入口，导出 `PATCHES` / `applyToText` / `targetRoots` / `targetFiles` / `run(root, verifyOnly)`，CLI 支持 `--verify` / `--root`。
  - **三态判定**：`applied`（已打补丁 → no-op）/ `patched`（本次施加）/ `drift`（上游变形 → 抛 `PATCH_SHAPE_DRIFT` 并打印上下文、退出非零）。**绝不静默跳过**，否则等于把同一个坑留给下一个人。
  - **rename 断链**：写入走"临时文件 + `renameSync` 覆盖"，绝不 `writeFileSync` 直写目标。原因是 `nlink=2` 时直写会污染整个 pnpm store 的原包（且日后被物化重置 again）。施加后 `nlink=1` 属预期，测试对此断言。
- `README.md` —— 缺陷说明、复发时间线（`04106142` 原始 / `00cc596e` 09-28 已修 / `auto-020-rc2` 09-30 复发）、闸门表、codex-ui 升级时的处理规矩。
- `evidence/20261001/live-verification.json` —— 本轮实机取证。

## 三、防回退设计（用户明确要求：修复前先想好如何避免回退）

四层，**全部零构建生效**（补丁与闸门都在 `.mjs` / 仓库脚本里，不进 `app.asar` 的编译产物）：

| 层 | 位置 | 作用 |
|---|---|---|
| 资产层 | `customizations/codex-ui-patches/apply.mjs` | 补丁成为仓库事实来源，可重放、可校验；不再有"只存在于 node_modules 的暗改" |
| 闸门层 1 | `scripts/prepare-dsh-home-generation.mjs` | 新家园复制完成后、**绑定文件 rename 落位之前**施加补丁；失败即走既有 catch 撤绑定 + 隔离该家园目录，绝不留下指向坏家园的生效开关。receipt 增记 `communityPatches.codexUi` |
| 闸门层 2 | `scripts/prepare-kernel-update.mjs` | 内核升级全部家园过完后做一次全量 `run(root, false)` 校验，失败抛错并列出破损文件清单 |
| 闸门层 3 | `Build-DSH-Portable.ps1`（'定制源码保护门禁' 阶段） | `--verify` 只读校验，非零退出即阻断打包与候选暂存 |
| 测试层 | `test/codex-ui-patches.test.ts` | 7 用例：正向应用 / `store` 确实转发到同一次 register / 幂等字节不变 / **变形必抛 `PATCH_SHAPE_DRIFT`** / 锚点唯一 / 临时家园端到端 / 实机全家园扫描（CI 缺 `Data/` 自动 skip） |
| 清单层 | `customizations/preservation.json` rev 4→5 | 新增 `sources` 条目（`codex-ui-patches`）、`features` 条目 `ui.plugin-config-section-store`、以及含 reason/change/evidence/negativeControl/deployment 的完整 `changes` 记录 |

**升级 codex-ui 时的规矩**：若闸门报 `PATCH_SHAPE_DRIFT`，说明上游改了写法——**必须逐条重核锚点并重写补丁，绝不允许放宽锚点把门禁哄过去**。
