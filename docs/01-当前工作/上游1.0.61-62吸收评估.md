## 已知坑（勿再踩）

- **部署候选时绝不能用 PowerShell `Set-Content -Encoding UTF8` 写 `pointer.json`**：PS5.1 会带 BOM，
  Node `JSON.parse` 吃到 BOM 抛错 → `confirmRunningCandidate` 读出空指针 → 报「桌面更新事务与待部署指针不一致」
  → 候选自杀、启动器回退（2026-09-16 实锤，白烧两次重启）。重挂 pending 一律用便携 Node `fs.writeFileSync`（无 BOM）。
- **外壳「重启应用」交接的双触发赛跑**（2026-09-16 08:56 / 14:14 两次实锤）：两个启动器实例在 ~70ms 内并发，
  实例 A 读到实例 B 刚写下的 `activation-attempt.json`，走「已尝试过未提交」分支撤销 pending 并启动旧槽，
  旧槽的 Chromium 单实例锁把 B 正在启动的候选挤死（`退出码=0` 连三退）。症状＝候选秒退＋pending 被撤。
  ✅ **已修**（`3f21766`）：该分支先判「在途」（候选槽进程存活 OR 尝试标记 < 90 秒）→ 让位退出，
  不撤指针、不抢启动；标记过期才走原回退安全网。回归测试见 `test/portable-desktop-update.test.ts`。
- `git ls-remote` 必须加 `-c http.sslBackend=openssl`，否则 schannel 报 `SEC_E_NO_CREDENTIALS`。
- 本地 `v1.0.61/62` 标签指向**便携自己的**提交——判定永远比上游提交号。
- 夜巡自动化工作区钉在「宏建云系统」，改仓库类操作会被挡；上游再发版需吸收时，重建自动化并把工作区设为 `G:\DSH-3-Portable`。
