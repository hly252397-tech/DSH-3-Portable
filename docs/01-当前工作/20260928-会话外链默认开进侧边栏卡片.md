# 2026-09-28 会话外链默认开进侧边栏卡片（better-sidebar HTTPS 拦截默认值）

## 现象（用户报告，"老问题"）

DSH 会话里点开内容（HTTP(S) 外链）走的是**原生浏览器面板**（顶部完整浏览器：地址栏/标签条/导航条），而不是定制的 better-sidebar 右侧工作台浏览器卡片。

## 诊断（证据链）

1. **外壳路由**：`src/main.ts:620 routeDshExternalLink` 把 DSH 视图的所有外链送 `openBrowser()`（原生面板）。这是链接**没被客户端拦截时**的兜底路径。
2. **客户端拦截器存在且活着**：better-sidebar v0.18.0-alpha.0 内置 `registerLinkInterception`（`lib/client.js:20970`，document 捕获阶段 click，仅未修饰左键，`a[href]` 非同源 http(s)；Ctrl/Cmd/Shift/Alt 点击始终绕过）。
3. **根因——协议开关默认值**：`takeoverEnabled`（`client.js:22713`）要求 `browserInterceptHttps !== false`，而默认值三处均为 **false**（`lib/client.js:79`、`lib/index.js:52`+`126`、`lib/client-registry.js:68`，源码 `src/prefs-shared.ts:283`+`src/config.ts:144`）。两家园 settings.yaml 均无 better-sidebar 显式记录 ⇒ 全走默认 ⇒ **https 链接全部不拦**（当代外链几乎全是 https）。
4. **实机取证**（`Data/Temp/link-probe.mjs`，经 hj broker 8976 向运行中的 DSH 页面注入合成点击）：
   ```json
   { "httpIntercepted": true, "httpsIntercepted": false, "httpsCtrlBypass": true }
   ```
   拦截器注册正常、http 正对照拦截成功、修饰键绕过正常——唯独 https 不拦，与代码分析一致。
5. 上游默认 false 的理由（"多数 HTTPS 站点拒绝 iframe 内嵌"）不适用于便携版：browser 卡片走**原生 WebContentsView**（`portable/browser-view.js`，经 `dshDesktopShell.browserPanel` IPC，与顶部浏览器共享标签页/历史），无 iframe 限制。

## 修改（双家园 src + bundle 双层，共 11 处；不跑插件构建避免动依赖树）

`browserInterceptHttps` 默认 `false → true`：

| 文件 | 位置 |
|---|---|
| `src/prefs-shared.ts` | SIDEBAR_PREFS_DEFAULTS（+决策注释） |
| `src/config.ts` | zod schema default（+注释） |
| `lib/client.js` | 客户端 bundle 默认值 |
| `lib/index.js` | host defaults + zod schema（两处） |
| `lib/client-registry.js` | 注册入口 bundle 默认值 |

活动家园（`Data/DSH-generations/v4-rc2b/home/...`）与旧家园（`Data/DSH/profiles/web/...`）各 5 文件，改后 5 文件 md5 两两一致（`98377bb4…` 等），`--check` 语法通过，全目录无 `browserInterceptHttps: false` 残留。

行为语义：已显式存过 `false` 的设置不受影响（record 优先）；未显式设置的会话全部默认拦 https 进卡片；总开关 `browserInterceptLinks`（默认 true）与浏览器卡片启用开关（`tabsEnabled.browser`）仍各自可关；Ctrl/Cmd+点击仍随时绕过走原生路径。
