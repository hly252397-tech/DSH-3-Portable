# I032 · 浏览器面板宽度策略统一（用户截图里那条"右侧白区"的修复）

> 触发：用户发来 8 张实机截图 + 一句「**全是问题**」。逐张取证后，其中一张的**红框正好框住
> 浏览器卡片右侧那片空白**（用红像素栅格程序化提取，确认是用户手绘的闭合矩形，非渲染噪点）。
> 结论：这**不是渲染故障**，而是**两套宽度策略各写一套、而且单位不同**。

## 0. 根因（代码 + 实渲染双重证据）

| 侧 | 位置 | 策略 | 单位 |
|---|---|---|---|
| 页面卡片 | `assets/theme.css` → `body .nArs4W_panel{max-width:calc(100vw - 1040px)}` | 视口 − **1040**（官方内容下限 680px 推得；被 `test/workbench-panel-clamp.test.ts` 钉住） | **CSS px** |
| 外壳原生视图 | `src/browser-panel-layout.ts` → `MAXIMUM_PANEL_WIDTH_MARGIN` | 视口 − **900**（按 ~560 保底；被 `test/browser-panel-layout.test.ts` 钉住） | **DIP** |

两侧**都各有测试钉着、都自称"对话列保底"**，但数值不同、单位还不同 ⇒ 网页缩放 ≠ 1 时偏差为
`margin/zoom − margin`：
- **卡片比原生视图宽** ⇒ 差出来的那一条露出卡片白底 = 用户红框圈住的**右侧白区**；
- 反过来（另一侧偏大）⇒ 原生视图**压住对话列**（不可见覆盖，那段区域的对话点不到）。

## 1. 改动（策略只剩一处）

| 文件 | 改法 |
|---|---|
| `src/browser-panel-layout.ts` | `MAXIMUM_PANEL_WIDTH_MARGIN` **900 → 1040**（统一到页面侧那条、依据官方 680 下限）并导出；新增 `browserPanelMaxWidthCss(panelWidthDip, zoom)` 把上限**折成 CSS px** |
| `src/main.ts` | 新增 `publishBrowserPanelMaxWidth()`：布局时把上限写成页面根上的 CSS 变量 `--dsh-browser-panel-max-width`；导航后 DOM 重置，由 `applyDshDesktopTheme` 复位标记并按同一把尺子重发 |
| `assets/theme.css` | `max-width: var(--dsh-browser-panel-max-width, calc(100vw - 1040px)) !important` —— **单一来源**，兜底值与外壳常量同值 |
| `test/browser-panel-layout.test.ts` | 新增「CSS px 折算」用例 + **跨模块一致性用例**（CSS 兜底常量必须 `===` 外壳常量，防止再各写一套）；面板钳制用例的期望数按新策略更新 |
| `test/workbench-panel-clamp.test.ts` | 改钉新契约（`var(...)` + 兜底 1040），并写明它现在与外壳同源 |

> 原则：**不是把测试改绿，而是把"两把尺子"改成"一把"** —— 一致性用例把这条钉死，
> 以后再单边改数就会直接红。
