## 1. 为什么要做成插件（而不是只写进 AGENTS.md）

`AGENTS.md` 只在**会话开始**注入一次；长会话被上下文压缩后，早期指令可能连同上下文一起被摘要掉——
这正是"昨天显得聪明、今天显得笨"的结构性原因之一。`ctx.systemPrompt.section()` 的节文本是**每轮重建**的 ⇒ 压缩免疫。
本插件与已装插件 `@michengai/dsh-pua`、`@michengai/dsh-agency-agents` 用同一机制（后者的调用现场是本插件 API 的实证来源）。

## 7. 弯路与更正（供后续，不要重复）

1. 我最初预估需要**全量构建 + A/B 候选槽**（约 30 分钟）。**错误**：profile 插件由运行时在启动时加载，改清单即触发**热重启**，
   不需要 `Build-DSH-Portable.ps1`，也不产生新槽。
2. 也必须避免"顺手跑一次 pnpm 装依赖"——本仓库已实证任何 `pnpm install` 会把整个官方家族矩阵物化。用 **Junction** 手工建链接即可（与既有 7 个本地插件同一形态）。
3. 起初想直接把插件放进 `node_modules` 实体目录：会绕过目录链接契约，且 `ui-baseline` 的 link 校验会把它判成"双拷贝"。
