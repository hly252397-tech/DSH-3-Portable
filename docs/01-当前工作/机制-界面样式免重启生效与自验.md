# 机制：界面样式「免重启」生效 + 自己抓图自验（含 2026-09-15 会话被杀事故的根因修复）

> 用户 2026-09-15 要求：全程自动、重启也自动、**最好想办法不重启验证**；有问题自己想办法解决。
> 同日晚追加要求：**「你重启后会话就停了」**——这是本文件下半部分的根因修复。

## 一、为什么原来必须重启 App

- 外壳把样式注入 DSH 页面（`insertCSS`）时，读的是**活动槽**里的 `resources/theme.css`；
  而槽是**不可变制品**（改动只能新出候选槽 + App 重启才切换）。
- 所以每改一行 CSS：全量/快通道出槽 → 重启 App → 才能看到 ⇒ 慢，且把用户拖进来当验收员。

## 二、免重启的落地形态（已生效）

1. 本地插件 `Data/DSH/profiles/web/local/dsh-ui-tweaks/`（Junction 进 `node_modules`，已登记 `dsh.profile.bundles`）；
   client 侧注入 `<style>` + 用 JS 做「输入区右上角」布局搬运，宿主侧提供一条热重载令牌路由。
2. 样式来自**可变目录**，改完即可生效；`assets/theme.css` 只保留「最终固化」那条路径（App 自然重启时随候选槽落地）。
3. 自验：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\look-ui.ps1 -NarrowWidth 1100`
   → `Data\Temp\ui-wide.png` / `ui-narrow.png` → `read_image` 自己判。**用户不进这个闭环。**

## 三、事故与根因：为什么我一「重启」会话就停（2026-09-15）

- **现象**：我每次改完插件去触发生效，正在跑的这次对话就被打断（工具调用返回 `host_interrupted`），
  用户必须再说一次「继续」。GUI 端口连续变化（61420 → 51074 → 60827）是同一回事。
- **证据链**：
  1. `src/profile-watch.ts:77` 只监听 `package.json` / `node_modules` / `.dsh-reload-request`；
     `profile-watch.ts:78` 见到 `.dsh-reload-request` 就把 `forceReload = true`；
  2. `src/main.ts:976` 把该 watcher 接到 `scheduleProfileActivationRecycle`；
  3. `src/main.ts:2733`：`reload` 动作 → `recycleDshForPluginUpdate()` = **整个 DSH 运行时回收**；
  4. 我这次对话就跑在那个被回收的 DSH 进程里 ⇒ 自己把自己的会话杀了。
  5. 补充实证：**改 `lib/client.js` 根本不在监听名单里**，所以早先那些 client 侧改动其实一直没生效，
     App 里跑的仍是旧 bundle（这是「界面改了看不见」的另一半原因）。
- **反向结论**：`recycleDshForPluginUpdate` 只在**装宿主侧改动**时必需；**客户端改动压根不需要回收运行时**，
  因为 client bundle 是**每次 HTTP 请求现读磁盘**的（实测：诊断实例里 `browser_refresh` 一次就拿到新 bundle）。

## 四、正式机制（验证过的）

### 4.1 客户端热重载通道（改样式/布局走这条，会话不受影响）

- 宿主侧 `lib/index.js`：`ctx.webServer.register({ kind:'exact', path:'/ui-tweaks/reload-token', handler })`
  → 每次请求现算 `lib/client.js` 的 `mtimeMs` 当令牌，`cache-control: no-store`，
  并且只接受回环 Host（非回环返回 403）。
- 客户端 `lib/client.js`：每 1500ms `fetch('/ui-tweaks/reload-token')`；
  令牌变了 **且输入框为空**（不丢草稿）→ `window.location.reload()`。
- **实测证据（2026-09-15）**：
  1. `GET http://127.0.0.1:61870/ui-tweaks/reload-token` → `{"ok":true,"token":1789485646730}`；
  2. `(Get-Item lib/client.js).LastWriteTime = Get-Date` 后令牌变 `1789485715717`；
  3. 页面 `performance.timeOrigin` 由 `1789485695461` → `1789485717097`（1.5s 内自动刷新，插件重新注入成功）。
- 效果：**改文件 → ~2 秒后页面自己刷新 → 截图看结果**，DSH 运行时不动、对话不丢。

### 4.2 唯一需要回收运行时的场景：装宿主侧改动

- 宿主侧（`lib/index.js`：新增 `inject` / 新增路由 / 改 `apply`）必须等 DSH 重启才加载。
- **正确姿势**：把触发写成脚本，**后台延时**执行，让本轮答复先落地：
  `Data/Temp/trigger-dsh-reload.ps1` → `Start-Process powershell -WindowStyle Hidden -File ...`。
- 🚫 禁止在对话进行中同步写 `.dsh-reload-request`：那等于自杀。
- 该请求文件外壳不会删；重复写入即重复触发（`forceReload` 只在事件上置位）。

## 五、自验闭环（每次必做）

- 抓图：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\look-ui.ps1 -NarrowWidth 1100`
- 看图：`read_image` 自己判；看不清就裁剪放大再量（`System.Drawing` 裁剪 + NearestNeighbor 放大）；
- 判定：像素/尺寸/DOM 值对齐算通过；“我看着像”不算；

  定位确认后**必须删除**，不许留在用户界面上。
