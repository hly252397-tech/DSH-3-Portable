# 机制：界面样式「免重启 App」生效 + 自己抓图自验

> 用户 2026-09-15 要求：全程自动、重启也自动、**最好想办法不重启验证**；有问题自己想办法解决。

## 为什么现在必须重启

- 外壳把样式注入 DSH 页面（`insertCSS`）时，读的是**活动槽**里的 `resources/theme.css`；
  而槽是**不可变制品**（改动只能新出候选槽 + App 重启才切换）。
- 所以每改一行 CSS：全量/快通道出槽 → 重启 App → 才能看到 ⇒ 慢，且把用户拖进来当验收员。

## 免重启的原理（可行，已被本仓库既有实践证明）

- `Data/DSH/profiles/web/local/**` 是**可变目录**（本地插件是 Junction，改完即时生效），
  且 DSH 运行时**每次启动都会重读 profile**；
- 外壳有「重新加载」动作 → `recycleDshForPluginUpdate()`：**只重启 DSH 运行时，不重启桌面 App**；
  本仓库已有先例：I034 的 `dsh-agent-discipline` 插件改完即「热重启，无需全量构建、无需 A/B 槽」。

## 落地方案（下一步执行）

1. 新建本地插件 `Data/DSH/profiles/web/local/dsh-ui-tweaks/`（client 侧注入一段 `<style>`），
   把我这些界面覆盖样式（面板宽度/工具栏/图标/窄档降级）**从 `assets/theme.css` 搬进来**；
2. 在 profile 的 `dsh.profile.bundles` 登记该插件（带备份）；**不动**用户现有 8 个 link 插件；
3. 触发一次 DSH 运行时热重启（外壳「重新加载」/ `recycleDshForPluginUpdate`），确认样式生效；
4. 之后每次改样式：改插件 → 热重启(秒级) → **`scripts/look-ui.ps1` 自己抓图看** → 不满意继续改；
   **全程不需要重启 App、不需要全量构建、不需要用户参与**；
5. 待桌面 App 下次自然重启时，这些样式同时固化进候选槽（两条路径最终一致）。

## 自验闭环（每次必做）

- 抓图：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\look-ui.ps1 -NarrowWidth 1100`
- 看图：`read_image` 自己判；看不清就裁剪放大再量；
- 判定：像素/尺寸/DOM 值对齐算通过；"我看着像"不算；
- 用户不进这个闭环（他明确说了：我不参与了）。
