## 3. 修改位置、原因与关键选择

三条不可让步的安全约束，逐条落到代码上：

**① 网页渲染层不持有全权限控制凭据。** Bridge 的 admin token 只在 `bridge-link.js` 内从 `<bridgeDir>/data/admin.token` 读取，且**每次请求重读**（Bridge 每次重启轮换该 token，缓存即失效）。新增的四个 `bridge.*` 操作**没有任何一个返回 token**；已有的 `credentials` 操作仍然只管 9801 的 MCP 令牌，未扩展。`readBridgeState` 连 token 都不需要——`/console/state` 是只读开放端点。

**② 只终止自己创建并确认归属的进程。** `stopBridge` 必须同时满足：归属文件 `DSH_HOME/agent-bridge-ownership.json` 匹配 **且** 本进程仍持有该 ChildProcess 句柄（模块内 `children` Map）。任一不满足返回 `NOT_OWNED` 且不动。DSH 重启后句柄丢失 ⇒ 拒绝杀，按外部实例接管。进程终止：Windows `taskkill /pid /t /f`，POSIX 需 `detached:true` + `kill(-pid)`；**没有**用 `child.killed` 提前返回（这是 `src/process-control.ts:31-33` 记的历史坑）。

**③ 端口被占一律如实报错，绝不 spawn、绝不 kill。** `probeBridge` 不满足「TCP 连通」这一条，而是读 `/health` 并断言 `service === 'agent-bridge'`；应答别的服务即判 `PORT_NOT_BRIDGE`，`startBridge` 直接拒绝。

「已产生结果 ≠ 已通过验证」：运行表有独立的 **未验证** 列，`verified` 只表示「Bridge 记录到了 result」，不是验收判定；页面顶部常驻这条告警横幅。
