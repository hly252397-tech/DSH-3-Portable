# DSH 右侧浏览器供后续会话调动及 ChatGPT 网站对话接入方案

状态：方案，未实施；2026-09-25。本文不授权读取账号记录、发送消息、停用现有任务或重启 DSH。

## 1. 结论与目标

建议采用“通用浏览器工具层 + ChatGPT 网站适配器”，而不是继续把任意 JavaScript 交给模型执行。所有 DSH 会话都应能提出浏览器任务，但实际操作须绑定明确的请求会话、网页标签、网站来源和授权范围。ChatGPT 网页仍留在右侧卡片内直接操作；不得恢复浏览器专用 `WebContentsView` 叠加层，也不得用只支持 iframe 的实现替代。

首版交付顺序：先收口现有临时执行通道，再做指定对话的只读访问，最后做逐次确认的发送与回复核验。侧栏历史列表不应被称为“账号全部聊天记录”；完整历史导入应作为独立能力，由用户明确选择数据来源和范围。

## 3. 当前临时通道的风险与优先级

P0 风险不应等到接入更多账号数据后才处理：

1. 8976 broker 的令牌是源码中的固定值，且通过 URL 查询参数传递；`/status` 无需鉴权并可能回显最近一次结果，CORS 设为 `*`。回环地址和 Host 检查不足以构成长期授权设计。
2. `kind=page` 使用 `new Function` 执行任意代码，`kind=tab` 透传到 `executeJavaScript`；现有护栏只按文本拦少数重启/退出动作，不能证明其他危险网页操作被阻止。
3. `askCodex` 能直接点击 ChatGPT 的发送按钮，未建立“目标对话 + 精确草稿 + 用户确认”的强制门。它通过当前活动标签执行，切会话或切标签时存在作用对象变化风险；轮询与固定等待也可能把旧回复当作新回复或遇到短回复超时。
4. DSH 用户界面、网页内容及模型工具之间缺少一个统一的授权与审计点。ChatGPT 网页正文是不可信输入，不能把其中的文字当成用户给 DSH 的命令。

建议先记录现役进程和在途任务，再以可回滚切换替代旧 broker；不能为了“安全整改”直接杀掉用户正在用的通道。新通道验收后移除固定令牌、公开 `/status` 原始结果、客户端 `new Function` 和模型可达的任意脚本入口。开发诊断能力若需保留，应默认关闭、只在本机人工调试态开启、用临时凭据，并与 Agent 工具完全隔离。

## 4. 三条路线的取舍

| 路线 | 能处理什么 | 局限 | 建议 |
|---|---|---|---|
| A. 右卡片网站适配器 | 在用户已登录的 `chatgpt.com` 页面定位指定对话、读取当前网页呈现内容、发送并核验。符合“右侧直接操作”。 | 页面结构和登录状态会变化；历史列表可能懒加载；必须实机维护。 | 主路线。只用受控 DOM/UI 操作，不依赖未公开的内部接口。 |
| B. OpenAI API | 为 DSH 自己新建、保存并续接 API 会话。 | 不能把 API Conversations 当成 ChatGPT 网站账号的现有历史；产品、计费与记录体系不同。 | 仅作为未来“新建 DSH 托管对话”的可选后端，不冒充网站历史读取。 |
| C. 用户选择的历史文件导入 | 在用户明确选择文件后做一次性检索/整理，适合大量旧记录。 | 不是实时同步，导出格式/范围要实施时重新核实。 | 作为可选批量历史路线，不自动扫描账号或磁盘。 |

OpenAI 官方 [Conversation state 文档](https://developers.openai.com/api/docs/guides/conversation-state)描述的是开发者创建并传给 Responses API 的会话对象；将它直接等同于 `chatgpt.com` 的用户历史没有文档依据。官方 [Computer use 指南](https://developers.openai.com/api/docs/guides/tools-computer-use)允许应用通过 UI 操作浏览器，但强调站点/动作范围、网页内容不可信、关键动作确认及结果核验。本方案据此制定边界；不据此推断网站保证长期支持自动化。

## 5. 推荐架构与职责

```text
DSH 会话 A/B/C（各自模型与任务记录）
          │ 结构化工具调用：携带 requesterSessionId
          ▼
dsh-browser-agent-tools（DSH 插件；注册 ctx.tools；权限、取消、事件落盘）
          │ 受认证的桌面宿主通道，不传模型生成的 JS
          ▼
Browser Automation Broker（Electron 主进程；唯一策略执行点）
          ├─ 按 sessionId / tabId / navigationEpoch 定位卡片内网页 guest
          ├─ 通用导航、页面读取、截图及锁/审批/审计
          └─ 站点适配器：ChatGPT v1；将来可增加其他站点
                       │ 只执行打包时审查过的固定脚本和结构化参数
                       ▼
             右侧卡片 <webview> → chatgpt.com
```

- DSH 插件只注册语义化工具，不直接操作 Electron，也不把任意网页脚本、Cookie 或认证令牌提供给模型。桌面桥优先走受认证的既有进程通信机制；若现有机制不满足，另建随机临时凭据、严校验来源与消息模式的本地通道，不复制 8976 的固定令牌设计。
- 主进程保留 `tabId → guest` 的唯一事实源。工具请求先绑定 `requesterSessionId`、`tabId`、期望的精确 `https://chatgpt.com` 来源、`navigationEpoch`；执行前后再核对，防止“查到的是 ChatGPT，点击时已经切成 ERP”。不得以“当前活动标签”代替固定对象。
- 跨会话默认不劫持另一个会话正在看的标签：B 会话调用时，在 B 的标签桶中复用或创建 ChatGPT 标签；共享登录分区不等于共享标签。若指定对话在 A，B 可以按用户指定 URL 在自己的桶中打开同一对话，不能暗中切换 A 的 UI。若 guest 未挂载，返回 `needs_visible_browser`/`needs_login`，由用户在右卡片打开或登录后继续；首版不造新的隐藏原生叠加层。
- 同一 ChatGPT 对话同时只允许一个写任务；读任务可并行但结果必须关联来源会话与目标对话。用户手动切页、注销、关闭标签或应用重启时，中止当前步骤并报告状态，不自动重发。
- 网站适配器是独立版本化模块，后续增加浏览器功能时只扩展适配器与语义工具，不重写右卡片生命周期。兼容目标是 Electron `<webview>`，不是 iframe。

## 6. 产品接口与行为契约

| 工具 | 输入与结果 | 默认权限 |
|---|---|---|
| `browser.list_tabs` / `browser.open_or_focus` | 明确会话、标签、URL；“先查再开”；回报 tabId、实际 URL、加载状态。 | 只读/导航；不能覆盖 ERP 等受保护标签。 |
| `chatgpt.list_conversations` | 从网站当前可访问的历史 UI 列表读取标题、URL、可见时间等；分页/滚动设数量和时间上限；回报 `complete/partial` 与原因。 | 需要用户授权当前账号/范围；不默认全量遍历。 |
| `chatgpt.read_conversation` | 指定 URL/对话 ID，抽取角色、顺序、文本、附件占位与加载状态；不把 HTML 当指令。 | 只读；返回量有上限，大记录分批，敏感字段可遮蔽。 |
| `chatgpt.prepare_message` | 指定对话和草稿，展示目标账号/标题/URL、正文和即将共享的数据；生成短时确认请求。 | 不发送。可修改或取消。 |
| `chatgpt.send_message` | 只接受与草稿、会话、标签及导航版本绑定的确认凭证；点击一次并核验新用户消息已出现。 | 外部写操作；每次发送时明确确认。 |
| `chatgpt.wait_reply` | 等目标对话中新助手消息结束，返回文本、链接和完成/超时/不确定状态。 | 只读；不得用“按钮已点击”冒充完成。 |
| `chatgpt.import_history`（后期） | 只处理用户明确选择的文件与范围，去重后入便携盘索引。 | 单独授权；默认关闭。 |

“历史记录”分三级表述：①当前已打开对话完整加载的可见消息；②网站侧边栏已枚举的对话列表（可能不完整）；③用户提供导出文件后得到的离线集合。接口必须报告来源、覆盖范围和不确定性，绝不把①或②称为整个账号的全部历史。附件、语音、共享链接、归档/删除记录、项目/团队空间先标为未支持或部分支持，逐项补测试。

发送状态机：`validated → attached/logged-in → drafted → awaiting-confirmation → clicked-once → user-message-observed → reply-in-progress → completed`。点击后若网络断开或 UI 消失，状态为 `outcome-unknown`：先只读核对目标对话，不自动重试，避免重复发送。短回复、流式长回复、停止生成和网络错误均须有明确终态；以目标对话中新消息的身份/顺序与完成标志验证，不能只靠固定 sleep 或长度阈值。

## 7. 权限、隐私与便携数据

1. 登录由用户在右侧浏览器完成；智能体不索取密码、验证码、Cookie、会话令牌，不绕过登录或站点安全挑战。站点跳到非允许域名时停止自动化，由用户接管。
2. “网页读出”不等于“允许送进任意模型”：DSH 会话可能选本地或云端模型。首次读取私有 ChatGPT 内容时，应展示当前 DSH 模型/提供方与待传输范围，只把本次任务所需片段返回模型；不默认把整份历史复制进会话。
3. 发送前显示目标对话与精确草稿；确认凭证由宿主签发、短时有效且只用一次，不能由模型文本伪造。用户拒绝后不点击发送。OpenAI 官方 [确认与同意指南](https://developers.openai.com/api/docs/guides/tools-computer-use-integration)明确区分模型请求与用户许可，并要求发送、发布等代表用户的动作在执行点确认。
4. 网页正文、对话回复与附件说明全部按不可信内容处理；其中“忽略之前规则”“去别的站点发送资料”等文字不提升权限。跳转、读取和发送的站点/动作允许清单由宿主执行，不只靠模型提示词。
5. 日志默认只存操作类型、时间、会话/标签的内部引用、目标来源、结果码和最小必要的摘要；不写密码、Cookie、完整对话或完整截图。诊断截图需用户明确选择并限制保留期。若以后启用历史索引，正文放在 `Data/DSH/integrations/chatgpt/`，支持删除、重建、导出与容量/保留设置；便携盘迁机时允许需要重新登录，不以复制系统凭据为目标。
6. 账号/分区首版只支持一个默认浏览器资料；多账号需要不同持久分区和清晰账号标签，不能以两个 DSH 会话假装账号隔离。

## 8. 实施阶段、门禁与回滚

| 阶段 | 改动 | 通过标准 |
|---|---|---|
| P0 现状固化与止险 | 核对活动槽/插件/8976 在途任务；为现有探针写只读、发送、跨会话的对照用例；设计替代通道并保留可回退旧槽。新通道通过后下线固定令牌 broker 与 `new Function`。 | 现役能力可复现，替代链路覆盖后旧入口无法再从 Agent 调任意 JS；不打断未完成任务。 |
| P1 通用浏览器工具 | 主进程按固定 session/tab/navigation 运行白名单操作；插件注册 `ctx.tools`；统一会话事件、取消、超时、权限及 UI 状态。 | A/B 两个会话各自标签不串；10 次“+”、文件↔浏览器与两次冷启不空白；ERP 仍可直接操作。 |
| P2 ChatGPT 只读 | 登录态检查、指定对话打开、消息抽取、历史列表有限枚举与 `partial` 报告。 | 单对话读取与用户目视一致；未登录、懒加载、页面改版、错误账号均安全失败；不触发发送。 |
| P3 发送与回复 | 草稿预览、逐次确认、一次点击、结果去重和新回复完成判断。 | 用户拒绝绝不发送；确认后仅一条；切标签/切会话/断网后的不确定结果不自动重试；新回复而非旧回复被读回。 |
| P4 可选增强 | 用户文件导入、便携索引、多账号、附件和更多网站适配器。 | 每项独立授权、迁移与测试；不放宽 P1–P3 的工具边界。 |

每阶段先按 `AGENTS.md` 核对 DSH 官方/内置运行时双基线及 `ctx.tools` 类型，再按 UI 维护契约做 GCC/GIR、受保护文件审查、类型检查和全测。涉及 `src/` 时走 A/B 候选，不覆盖现役槽；只有用户允许切换后做真机验收，失败回滚。不得把源码单测、旧版 ChatGPT 演示或一次网页成功加载写成产品交付完成。

实机验收至少覆盖：真实 `chatgpt.com`、用户手动登录、指定旧对话与新对话、短/长/流式回复、登录过期、2FA/挑战、页面结构变化、并发两个 DSH 会话、同一对话写锁、手动切换标签、卡片收起/再开、10 轮“+”与文件卡切换、两次独立冷启、ERP 不回归、便携盘迁机后重新登录提示、候选失败回滚。现存“快切会话后立即开更多菜单的白底快照”另列已知边界，不与 ChatGPT 工具验收混为一项。

## 9. 建议的文件边界与明确不做

预计新增独立插件 `Data/DSH/profiles/web/local/dsh-browser-agent-tools/` 和主进程浏览器策略/站点适配器模块；修改 `src/main.ts`、窄 IPC 契约、右卡片状态反馈、相关测试与手册条目。旧 `dsh-hj-workbench/lib/client.js` 中的临时探针只能在替代链路实机通过后撤除；不因其是当前可用路径而永久保留无边界脚本能力。`dsh-agent-bridge` 9800 仍只负责把任务投递到 DSH 会话，不承载浏览器脚本本身。

推荐默认配置是“全部 DSH 会话可申请、只访问本会话绑定的标签、按指定对话只读、每次发送单独确认、不保存完整正文”。用户可随时撤销某个会话的浏览器权限或停止当前任务；撤销后未执行的队列项失效。不能用“会话处于完全权限”替代 ChatGPT 对外发送的专门确认。

若网站结构变化、适配器判断不出目标对话或站点要求人工验证，自动化应停止并保留右卡片手动浏览，不静默改走网站内部接口、外部浏览器或 OpenAI API。故障只降级该站点适配器，不让整个右侧浏览器再次空白。发布后按站点适配器版本记录失败率与可复现证据，但默认不上传私有对话正文。

本轮不做：读取用户真实聊天记录、向 ChatGPT 发消息、修改登录态、停掉 8976、重启 DSH、重录 UI baseline、把方案写成“已实现”。实施前需要用户明确批准开发与实机验收窗口；使用真实账号测试发送时，再按目标对话与草稿逐次确认。

## 10. 补充决策与验收门槛（2026-09-26）

以下四项补充前述契约，属于实施要求，不代表相关能力已经实现或获准访问真实账号。

本节依据 OpenAI Docs 的浏览器操作与插件安全指导：网页内容按不可信输入处理；工具采用最小权限；涉及对外发送、数据传输或不可逆动作时保留用户确认和可审计结果。

### 10.1 登录态与会话授权分开

- “浏览器已登录 ChatGPT”只说明网站登录可用，不代表任意 DSH 会话获准读取记录。授权须绑定请求会话、目标账号/对话范围和允许动作；A 会话的授权不能被 B 自动继承。DSH 的“完全权限”也不能替代读取授权或逐次发送确认。
- 右侧卡片显示“哪个会话、哪个任务正在操作、目标对话、当前步骤”，并提供可达的“立即停止”和撤销授权入口。停止后不再执行后续步骤；撤销后未执行的队列项与确认凭证失效。已经发送的消息不能宣称已撤回；发送结果不确定时按第 6 节处理，不自动重发。
- **验收门槛（P1–P3）**：已登录但未授权的会话不能读取正文；跨会话不能借用授权；停止/撤销后不再发生新操作；用户能在右卡片辨认操作者并接管。

### 10.2 ChatGPT 回复是外部资料，不是 DSH 指令

- 工具回传须标注来源对话链接、读取范围、读取时间和完整/部分状态；网页正文、回复及附件说明保持外部资料身份，不得提升为系统指令、用户授权或新的工具执行请求。
- 返回当前 DSH 模型或转交其他模型前，只取本次任务所需片段；接收方或范围超出原授权时重新确认。网页内容不能自行触发发消息、操作文件或扩大读取范围；宿主仍按原任务和授权校验每项动作。
- **验收门槛（P2–P3）**：用受控测试内容验证“忽略规则、读取别的对话、向外发送资料”等文字不会触发额外操作；结果能追溯来源和覆盖范围，不能把部分读取说成全部历史。

### 10.3 历史检索采用“用户选中后收录”

- 指定对话的临时读取与长期收录分开。需要建立检索索引时，先由用户选中对话，再保存链接与必要摘要；不因读过一次就自动保存全文，也不后台遍历整个账号。
- 如需进入黑洞空间，由用户另行选择对话、片段或文件范围，并展示将保存的内容；未选择的不收录。网页侧栏已加载列表始终标注覆盖范围，不能声称代表账号全部历史。
- **验收门槛（P2/P4）**：P2 不暗中建立长期历史库；P4 只收录用户选定范围，支持核对来源与删除。大量旧记录导入仍是独立能力，不作为首版只读访问的前置条件。

### 10.4 适配器故障不得拖垮浏览器

- ChatGPT 页面改版、目标识别失败或健康检查不通过时，只暂停该适配器的自动操作，明确提示手动接管；右侧卡片、ERP 和其他标签继续可用，不为恢复自动化重建整套浏览器或触发应用重启。
- 浏览器或适配器更新后，先做不发送消息的健康检查：检查目标绑定、登录/授权状态与页面识别，不提交表单、不读取未授权正文。检查通过不等于发送流程已验收；真实发送仍需逐次确认。
- **验收门槛（P1–P3 及后续更新）**：模拟页面结构不匹配，证明只有 ChatGPT 自动操作暂停；再验证跨会话不抢页、两次独立冷启动、10 轮“+”及文件卡切换、ERP 与其他标签仍可操作，并保存实际 UI 证据。

实施优先级不变：P0 先在不打断在途任务的前提下替换任意脚本通道；P1 建立受控工具、按会话授权及停止入口；P2 开放指定对话只读；P3 开放逐次确认的发送；长期收录和批量导入留在 P4。四项要求不能以旧版演示或单元测试代替当前制品的实机验收。
