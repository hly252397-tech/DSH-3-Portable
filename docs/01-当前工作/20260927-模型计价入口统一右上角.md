# 模型与计价入口统一输入框右上角

用户要求：所有会话的“平价 + 模型选择”都位于消息发送框上方右侧，与左侧黑洞空间同行，最大化/缩小不改变归属。保留紧凑模型图标及原菜单，不改模型配置。

问题是现有搬运在不同布局失败后退回输入框底部；证据是用户两张截图与 ui-tweaks 的 sized/reverted 分支，且欢迎页实拍仍在底部；下一步为真实 DOM 复现，修正布局判断并保留失败去重，避免再引入 MutationObserver 循环。

## 根因实证与修法

活动页面 `http://127.0.0.1:50510/`、桌面 `e0a2ad669e01b589`、运行时 `0.1.7-rc.2-4d29c691bfdf224c`、home `v4-rc2b`。旧客户端在发布会话加载后 `data-tw=reverted`；模型仍在输入框底部。缩小窗口后 `moved`，复现用户两图差异。

通过真实旧 bundle 的 Debugger 条件断点捕获：`bad=[tiny[0]]`，dock 宽736；被误当计价的 `uV2eYG_standardControls` 在模型抽出后宽0、高28，模型本身26×26正常。计价比模型稍晚挂载，回退时将同一几何状态缓存，后续计价就绪没使缓存失效。

改动仅在 ui-tweaks：

- 以 `billing-live-cost-chip` 选择计价自身，旧标记兼容仅上溯至 `conversation.input.right` 内的直接节点；不搬共享 standardControls，也不带走其他工具或 model slot。
- 模型与计价查找限定当前 composer；已搬节点也参与检查。失败缓存加入模型宽、计价文案/宽，保持相同失败状态不重复搬运的防卡顿保护。
- 首候选不再退回底部，但实机矩阵发现计价迟到后会排在模型右边；第二次修正通过 CSS order 固定为计价1、模型2，避免靠重复 DOM append 排序产生观察循环。直接搬运的计价清除额外外框，保留其数值、原语义和悬停信息。
- 没有重建模型按钮、改模型选择服务、改费用算法、改用户模型配置或发送消息。实际运行时类型 `dsh-client-ui-model-selection/lib/types/client/{slots,service}.d.ts` 已核对，仍使用原 session directory/selection 行为。
