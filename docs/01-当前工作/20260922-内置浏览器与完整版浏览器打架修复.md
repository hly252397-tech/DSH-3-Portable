# 20260922 — 内置浏览器与完整版浏览器打架修复

## 问题是 ___；证据是 ___；下一步是 ___

- **问题是**：产品里同时有两套浏览器 chrome —— `assets/shell.html` 的 `#browser`（内置浏览器，历史副本）与 `assets/browser-panel.html`（DSH 完整版浏览器，`browserPanelView`）。两者都调用 `DshBrowserWorkspace.create`、都渲染标签条/地址栏、都绑 Ctrl+F/L。
- **证据是**：
  1. `shell.html` 的 `renderBrowser` 在 `browser.visible` 时 `host.hidden=false`，并调用 `fullBrowser.render()`；
  2. `src/main.ts` `layoutDshView` 同时把 `browserPanelView` 设为可见并占同一面板区域；
  3. 文档 40 早已认定「shell 那份是外壳侧冗余/历史副本」，但显示逻辑未退役；
  4. 连带：P0 生命周期门禁把**无卡片 owner** 的 `openBrowser`（外链/主页组/智能体）挡在 panel 外，只剩 shell 空 chrome + 页面全隐藏。
- **下一步是**：退役 shell 侧重复 chrome 显示；无 owner 的 shell 工作区放行正式 chrome；撤销只在有 owner 时关可见性。

## 改法

| 文件 | 改动 |
|---|---|
| `assets/shell.html` | `renderBrowser` 永不显示 `#browser`（元素保留满足 byId 契约）；`DshBrowserWorkspace.create` 的 `getState` 恒报浏览器不可见（不抢 Ctrl+F/L） |
| `src/main.ts` | ① P0 生命周期门禁只约束**卡片内嵌**（`cardEmbedded = browserPanelOwner !== undefined`）；无 owner 的 shell 工作区放行；② `revokeBrowserPanel` 只在曾有 owner 时把 `browserVisible` 置 false；③ 卡片缺席 / DSH renderer 生命周期 / 切会话 的撤销都要求 `browserPanelOwner !== undefined` |
| `assets/browser-panel.html` | 补上最大化入口（原先只在 shell 历史副本里） |
| `test/browser-panel-layout.test.ts` | 新增 2 条防复发：shell chrome 不得再显示；P0 门禁只约束卡片内嵌 |
| `test/sidebar-spaces.test.ts` | Inventor 本机路径断言加 `t.skip` 守卫（本机/CI 未装 Autodesk Inventor 2027 时跳过，不再红灯挡构建） |

## 架构不变式（修后）

- **唯一浏览器 chrome** = `browser-panel.html`（`browserPanelView`）。
- **卡片内嵌模式**（有 owner）：P0 生命周期门禁完整生效（owner + 卡片可见 + raw 交集 + 心跳新鲜 + 会话匹配）。
- **shell 工作区模式**（无 owner，`openBrowser`）：`browserVisible` 即权威，按 widthRatio/最大化布局显示正式 chrome + 页面。
- **撤销**只在卡片持有时关掉工作区可见性；shell 工作区不因「页面没有浏览器卡片」或 DSH 导航而被关掉。

## 第二轮（2026-09-23）：文件预览与原生浏览器互斥

**用户**：「还是有」+ 截图（右侧 HTML 文件预览 + 文件卡红框）。

**根因**：截图右侧是 better-sidebar 的**文件 HTML 预览**（iframe，`/sidebar/html/` 路由），不是浏览器 chrome。
原生 `WebContentsView` **永远在 HTML 之上** —— 文件预览和内置浏览器没有互斥，打开 HTML 文件时原生层会盖住 iframe 预览。
上一轮 shell chrome 退役后，无 owner 的 shell 工作区还会把原生层拉起来，更容易撞上。

**改法（互斥：文件预览上屏 = 原生层必须收）**：

| 文件 | 改动 |
|---|---|
| `local/dsh-better-sidebar/portable/browser-view.js` | `visible=false` 时也调 `bridge.hide(lease)`（不能只靠 unmount cleanup） |
| `local/dsh-better-sidebar/src/client/intercept.tsx` + `lib/client.js` | `openSidebarFile` 打开编辑器前 `browserPanel.hide()` |
| `local/dsh-better-sidebar/src/client/EditorHost.tsx` + `lib/client.js` | 有 path 的文件挂载时 `browserPanel.hide()`（覆盖树点开等入口） |
| `src/main.ts` | `hide(undefined)` 允许强制收（文件预览接管时不管 owner 是谁） |

**门禁**：`tsc` 0；`browser-panel-layout` **16/16**（含新增互斥用例）。
**UI 基线**：better-sidebar 两文件为本轮改动；`dsh-sidebar-spaces`×2 与 `dsh-automation` 为**他人在途漂移**（mtime 10:58，晚于本轮），按契约**不代记基线**。
**未验证**：`src/main.ts` 的强制 hide 需全量构建+重启才进外壳；客户端互斥（better-sidebar）已热加载生效。
**真机自测（2026-09-23）**：启动应用 → 路径输入框打开 `output/段值达意号总表-00000080.html` →
**文件预览 iframe 完整可见**（沙箱条「已启用」+ 表格内容），**原生 WebContentsView 未覆盖**；
证据 `artifacts/browser-chrome-unicity-20260922/file-preview-no-native-overlay.png`。
（工作台浏览器标签仍在后台，互斥生效：只有文件预览上屏。）

## 第五轮（2026-09-23）：侧栏浏览器空白 → 改 iframe

**现象**：用户截图「打开浏览器是空白」；点「宏建云物料录入工作台」后又能显示。

**根因**：原生 `WebContentsView` 已删，但 better-sidebar 的 `BrowserView` 仍调 `bridge.show()` —— 没有原生视图可画 ⇒ 空白。点工作台是把 URL 塞进了同一个空壳，碰巧有内容。

**改法**：`portable/browser-view.js` 整个换成 **iframe**：
- 本地/回环地址（`127.0.0.1` / `localhost`）→ `<iframe src=url>`（工作台 8975 可内嵌）
- 无地址 → 「输入网址以开始浏览」提示
- 外链 → `window.open` 系统浏览器 + 提示
- 不可见 → `null`

**门禁**：`tsc` 0；`native-browser-card` + `browser-panel-layout` **20/20**。
**真机**：点「录入工作台」→ iframe 完整显示宏建云 ERP 工作台；证据 `iframe-browser-workbench.png`。
