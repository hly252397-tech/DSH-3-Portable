## 2. 写入和并发边界

1. 先检查工作树、并行智能体、构建锁、更新事务、活动路径、剩余磁盘空间。使用独立 worktree 或干净检出，不覆盖其他会话未提交内容；不要自动 stash、reset --hard、强推或清理他人文件。
2. 开发、测试、下载和应用可控缓存留在便携根下的独立开发区域。便携根由当前真实路径解析，不写死 G:，不向系统目录全局安装依赖或 Windows 服务。
3. Stable、current/previous/pending 对应制品及凭据保持受保护。拒绝经 junction、symlink、重解析点越界写入或清理；逻辑路径检查不能替代真实路径检查。
4. 不清空删除守卫环境，不使用 -Force、SkipTests、改哈希、删测试或降级 Node 绕过门禁。
5. 未证明资源隔离前保留已有组件互斥。随后按实际写入集合细化锁：独立下载可以并发，共享 Profile、绑定或激活事务必须协调。跨进程锁具备所有权和恢复证据，不能只凭 PID 或过期时间删除别人的锁。

## 3. 目标边界：同仓可行，产物和生命周期必须独立

桌面组件拥有 Electron、窗口、托盘、桌面菜单、原生浏览器承载、桌面快捷键及桌面专属 UI。DSH 组件拥有内核服务、自己的 Web UI、业务任务和内核依赖。每项现有功能都必须有唯一源码归属；不能为了拆分丢掉侧栏、浏览器、插件或已接受的定制。

两边只通过版本化的窄接口、能力协商和明确的连接身份通信。禁止跨组件 import 对方内部实现，禁止把对方的 dist/node_modules 复制进自己的更新包。必要的 DSH 侧桥接插件有独立归属、版本和兼容声明，不在桌面启动时静默覆盖活动 Profile。

内核使用自己经过验证的 Node/依赖闭包。可随内核包携带，也可引用独立不可变、经过验证的运行工具制品；不得依赖可被桌面更新覆盖的 resources/node。工具版本校验仍必须存在，其依据改为内核自身的可信契约，不是取消校验。开发/发布工具链仍遵守仓库 gate-node 要求。

首次完整离线安装包可以组合双方成品，但只做装配，不成为每次更新必须重新打两边的理由。桌面增量更新不得重新初始化、覆盖或降级已安装内核。

## 4. 开发体验：一个入口，保存后自动生效

实现一个面向用户的开发入口（名称可采用 开发调试.cmd），内部可有子命令，但不要求用户分别记多个脚本。

- 自动定位便携工具链、验证依赖和开发环境；已满足时复用，不每次 install。
- 建立独立开发 Profile、会话、浏览器数据、端口、运行目录和进程身份。开发用户数据不得直接链接正式 Data；最初需要配置时仅按白名单显式导入，不复制令牌或开启正式任务生产者。
- 开发产物、tsbuildinfo、日志、错误状态与正式 dist/receipt 隔离。
- CSS 更新优先局部替换；HTML/页面脚本刷新受影响页面；主进程/preload/IPC 编译成功后有序重启必要的开发进程。插件仅在真实支持安全 dispose/reload 时热重载，否则重启开发宿主。
- 连续保存合并为一批，等待完整编译成功再更新。监听忽略输出、缓存、日志、.git 等目录，避免自触发循环。删除、重命名、多文件修改、编辑器原子保存都须覆盖。
- 失败时保留上一版可运行实例，同时醒目标明新修改尚未生效；修复后自动恢复。不得把旧实例的截图、测试或响应当成新代码通过。
- 状态包含 source revision/dirty fingerprint、build generation、loaded generation、各进程身份、最近错误和时间。实际窗口与供智能体读取的状态必须一致。
- 重复启动开发入口不得重复拉起整套服务；崩溃恢复有限重试，错误可见；只终止本次拥有的进程树，不按进程名批量杀 Electron/Node/DSH。
- 关闭或重启开发版不影响正式版。深浅主题、缩放和设置样式沿用现有设计，不另起一套视觉。

开发运行不打正式包、不生成正式槽、不切正式指针，也不触发发布和大目录清理。这里的免构建指免正式打包；必要的源码编译不能省略。

## 5. 构建问题：编译、打包、暂存、激活明确分离

建立统一构建入口（名称可采用 构建组件.cmd），允许选择桌面、内核或首次完整组合。内部优先复用现有编译/缓存/收据模块，不做多个各管一套规则的脚本。

- 以实际输入依赖图分类修改，不仅凭扩展名或 git dirty。协议、公共构建代码、锁文件和资源映射变更需扩展影响闭包；未知文件明确列原因，不能静默漏构建。
- 桌面代码变更不运行内核装配或内核包压缩；内核版本变更不运行 electron-builder；插件单独构建自己的载荷及必要集成验证。公共协议修改可能需要双方验证，这是合理耦合，不得伪装为无影响。
- 开发使用增量编译和定向验证；正式交付保留现有完整质量门禁，不以开发绿灯替代。先证实正式门禁范围可拆再调整，不能因提速擅自跳过全测。
- 每个组件有独立输出和成功凭据，绑定准确源码输入、工具版本、依赖、编译输出、测试证据与最终制品。复用结果必须证明属于同一输入；失败、中断、漂移和缺文件不能得到成功收据。
- 默认构建仅产出待验制品；暂存和激活属于明确的后续动作。旧入口保留兼容或给出清晰迁移提示，不能悄悄改变旧脚本语义。
- 建立薄桌面更新包及独立内核成品的内容白名单/禁止清单，并用实际产物验证，不只是检查 package.json。
- 缓存命中要求内容和输入证据，不能仅靠 mtime；相同输入无需重复装配或打包。缓存损坏应定位并只重建受影响项，不进行广域清理。
- 构建输出阶段耗时、缓存命中/失效原因、处理组件、制品标识。大目录回收与启动验证错峰，限制并发 I/O。

## 6. 拉取更新：源码同步和用户安装更新不是同一回事

源码开发同步在独立工作区吸收指定上游 tag/commit，保留现有逐 hunk 审查和定制保护。禁止在活跃工作树直接覆盖式 git pull，也不能将官方原版桌面包直接覆盖便携定制版。

用户安装更新走预构建成品：检查组件发布清单 → 下载 → 来源和内容校验 → 暂存 → 安全激活。用户端不得隐式转去 git clone、pnpm install 或完整源码构建；缺成品应报告原因并保留现役。

复用已有桌面与 harness 发布通道，分别拥有版本、渠道、发布身份、制品名、平台/架构、大小、哈希、协议要求和更新状态。同仓时按 component 和发布契约识别，不能只取 GitHub 全仓最新 Release。

DSH 内核契约改为验证自己的 Node 和依赖闭包，更新、构建、解包、启动及恢复消费路径须同步修改。保留旧格式兼容与明确迁移策略，不准只放宽解析条件却仍用旧桌面 Node 启动。

下载来源需受信，限制重定向；校验来自可信发布契约。单独的同源哈希文件不是额外的发布者身份认证。校验包大小、内容哈希、路径穿越、链接、文件类型与实际身份；失败包不可激活。发布制品不可覆盖，未审阅版本不因字符串更大就自动受信。

分别设置检查/下载策略，页面明确区分发现新版本、已下载、候选就绪、待安全切换、验证中、已生效、已回退和阻止原因。下载完成不许显示已更新。

## 7. 部署问题：复用槽位体系，只切本组件

提供一个验证交付入口（可采用 验证交付.cmd），自动校验制品身份、凭据及目标兼容性，再暂存选定组件候选。生产激活默认不在本任务授权内；实验环境端到端激活必须使用独立根。

- 复用现有 Desktop/Harness 槽位、指针、事务和健康提交。不得再造第三套当前版本指针或平行回滚器。
- 桌面部署不得改内核槽、内核绑定、插件安装状态或业务 Data；内核部署不得改桌面安装文件和桌面指针。
- 若源或目标、Profile、契约已被其他事务改变，旧事务必须拒绝提交，不覆盖新状态。持有适当租约至健康提交或完整回滚结束。
- 覆盖磁盘满、断网、下载中断、半解包、被占用文件、掉电、崩溃、迟到回调、重试、重复激活和恢复扫描；只有完整凭据的候选才可进入恢复选择。
- 回滚组件制品不等于回滚全部 Data。数据版本与所属内核事务配对，不能二进制退回而数据仍用不兼容的新格式，也不能覆盖其他组件数据。
- 以真实启动的 executable/资源根、组件版本、指纹和健康证据认定生效，不根据最大版本目录、package.json 或 pending 字段猜测。
- 事务完成后只按现有保留规则回收未使用制品，严禁清理被 current/previous/pending、活动进程或事务引用的内容。

## 8. 服务生命周期：桌面重启与内核重启分开

优先扩展已有便携启动器/服务管理模块，使 DSH 服务具有独立于 Electron 窗口的所有权。无需安装系统服务，不以一个未经验证的 detached/unref 开关宣称完成。

桌面重启后重新连接已有 DSH；不依赖桌面能力的服务端任务应继续。依赖桌面浏览器、窗口和桌面工具的任务可能需要等待，必须向任务系统报告能力暂不可用，不能承诺所有任务零中断。检查命令、事件、认证、取消、日志和通知通道在重连后均能恢复，不能只验证网页可打开。

连接必须验证实例身份、版本、会话和权限。环回监听不等于无需认证，防其他页面或进程冒充管理端；不得向外网暴露管理接口。Windows 下处理继承句柄、Job Object、父进程退出、任务栏/托盘退出语义与进程树清理，不杀其他会话的进程。

内核更新可只重启内核而不重装桌面，桌面显示重连状态。为停机窗口提供真实任务安全边界，不把 GUI 遮罩、短暂空闲或 HTTP 200 当成队列清空证明。

## 9. 内核激活的硬门槛：不可绕过现有阻止

`harnessActivationSafety()` 的阻止只能在相应代码与证据齐备后解除，且不是改布尔值完成任务。

第一阶段可优先选择经过验证的正常退出/下次启动激活，而非冒险热切换；但退出后的 MCP、IM、定时任务及其他生产者必须确实停止，旧服务/写入者确实退出。无法证明时保持 blocked。

影子验证不得连接正式业务入口并执行真实任务。迁移/准备数据前取得一致性快照与单写者保证；Profile/家园绑定与内核版本同步提交，回滚遵守事务所有权。

观察窗口如已接纳新业务写入或造成外部副作用，不能简单恢复旧快照自动回滚。采用提交前禁止入站，或经验证的恢复/日志协议；方案须有故障注入和实机证据。中断后不得遗失已确认任务或重复执行不可幂等操作。

兼容性不足时保留现役并解释阻止原因，不自动禁用插件、摘掉 bundle、扩大 peer 范围或删掉受保护定制。

## 10. 定制保留与接口兼容

复用 customizations/preservation.json、UI baseline、真实 Profile 快照和既有能力 ID。每个受影响功能记录持久源码、生成载荷、实际加载位置、数据归属及回归证据。

桌面与内核各声明协议/能力兼容范围，至少验证旧桌面＋新内核、新桌面＋旧内核及不兼容拒绝。跨边界契约变更允许明确协调发布，不得宣称永远可任意组合。

不通过硬编码 DOM 类名或复制对方内部文件实现长期稳定接口；现存此类依赖先清单化并用行为测试保护，再逐项迁移，不能一次删掉导致功能回原版。

## 11. 必须实际运行的验收矩阵

| 验收 | 必须取得的证据 |
|---|---|
| 开发启动、重复启动 | 一个可识别开发实例；无正式 Data/槽写入；进程、端口、Profile 隔离。 |
| 连续修改 CSS/页面 | 不触发正式打包或暂存；加载代际随源码更新；受影响 UI 实际显示。 |
| 多文件保存、编译失败、修复 | 合并刷新；失败标记明确；旧实例不冒充新版本；修复后自动生效。 |
| 主进程与 preload 修改 | 必要开发进程有序更新；正式实例不受影响；无残留监听和孤儿进程。 |
| 仅桌面构建/更新/部署 | 内核装配调用次数为 0；内核槽内容、版本、指针和绑定保持不变。 |
| 仅内核构建/更新/部署 | electron-builder 调用次数为 0；桌面制品和桌面指针保持不变。 |
| 同输入二次构建 | 记录真实缓存命中和耗时，解释剩余校验成本；制品与收据正确。 |
| 损坏、缺失、等长篡改缓存 | 缓存拒绝并仅重建正确范围；不形成伪成功收据。 |
| Node 与桌面不同的合法内核 | 使用内核自身受信 Node；非法/损坏 Node 必须拒绝；不是删校验。 |
| 内核成品缺失或下载失败 | 明确阻止；不在用户端安装依赖或偷偷完整构建。 |
| 桌面升级失败 | 只回退桌面；DSH 服务与不依赖桌面的任务状态有连续证据。 |
| 内核升级失败 | 桌面不降级；内核及所属数据绑定安全恢复；无业务数据倒退或重复任务。 |
| 忙碌/待审批/外部入站 | 不强切、不丢任务；所有入口隔离或明确 blocked。 |
| 崩溃、掉电、迟到回调、并发 | 正确恢复事务；无跨组件指针覆盖；未完成候选不被误激活。 |
| 定制、浏览器、插件、缩放 | 真实 Profile/Loader 组合与 UI 行为验收；旧故障有反向对照。 |
| 换盘符、空格/中文路径、离线启动 | 工具、链接、缓存、组件解析正确；不回落系统目录。 |

性能指标先从同机基线采样：冷启动、热启动、样式修改、主进程修改、桌面构建、内核构建、下载/暂存/激活分别计时，记录中位数和较慢样本及缓存状态。任何秒数目标属于待实测目标，不把历史脚本注释当本轮提速结果。正式交付至少提供一次实际独立制品的安装消费与失败恢复演练。

## 12. 交付物与执行纪律

交付必须包含：实际代码、少量统一入口、组件边界/协议/制品清单、开发隔离与构建收据、单元及故障注入测试、Windows 真实验证、耗时对照、迁移/回滚说明、精确 commit 和逐项验收表。

执行顺序：基线测量 → 开发隔离和增量反馈 → 构建与产物拆分 → 独立 Node/契约 → 更新下载 → 独立暂存和生命周期 → 安全激活/恢复 → 真实组合验收。阶段属于同一任务，不在每完成一项后问用户要不要下一步。普通报错自行诊断和有限重试，连续失败换方法；遇权限、凭据、实质方案冲突或未授权生产写入才请求必要决定。

状态只能如实使用 PASS / FAIL / PARTIAL / BLOCKED / NOT RUN。环境缺少清单 Node、Windows、完整依赖、正式 Profile 或真实发布制品时，明确哪些证据缺失；不能用另一版本 Node 的诊断结果代替正式门禁，不能把 mock 当实机，不能把文档提交当功能实现。

最终交付标准：用户只需一键进入开发；智能体改代码后可自动确认生效并验证；交付时选择组件后完成构建和隔离候选验证；获得正式激活授权后只切换所选组件。未完成整个闭环时不得宣布已解决。
