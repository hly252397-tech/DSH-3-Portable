## 结论

用户反馈有依据：有些是伪入口，有些是重复跳转，有些是真功能但入口层级过深。此前“外观已对标 / 安装文件已同步”不能证明产品入口完整。

最优先修复：

1. “编程”是 CSS 伪元素文案，不是编码 / 通用模式开关，点击没有模式菜单。`assets/theme.css` 的 `.dcu-brand::after { content: "编程"; }` 与现场表现一致。
2. “扩展”直接打开设置默认页，与“设置”完全重复；真实插件 / 技能 / 连接器页面被藏在设置导航内。
3. 自动化独立页只多加了一个说明卡片和二次跳转；实际新建表单仍在设置内，路径冗长。
4. 知识库操作在进入库后才显示，概览没有明显“进入库后可添加资料”的引导；不能把用户找不到按钮归咎于未重启。
5. Inventor 的“连接并打开”文案强于实际能力：现场仅证明安装检测，页面自身说明 COM / Add-In 后续启用，不能声称 CAD 自动化已接通。

## 证据边界与后续验收

- 本轮属于**正式窗口入口 / 导航 / 草稿取消测试**，不是所有功能端到端验收。未新增用户条目或任务、安装插件、连接账号、改变权限、调用模型、执行定时任务或操作 CAD。
- 未测试：实际导入落盘、正式库跨更新恢复、归档恢复、多模型调用、Hooks / 子智能体、主题全页覆盖、键盘完整导航、读屏、深色对比度。它们不能因为本轮入口可见而标完成。文件选择窗口已在下面的追加复测中验证。
- 首次打开知识 / 表格由已有持久化组件正常读取 / 初始化；本轮没有手动改写、搬动或删除原用户数据，不能由当前显示一条说明断言历史资料已找回。
- 可见的辅助功能风险：伪按钮无交互；顶部搜索与底部搜索含义不清；抽屉横向溢出；部分小关闭按钮 / 次要文字的可用性需专门测量。没有作 WCAG 合规声明。
- 先修独立扩展入口和真实模式开关，再消除自动化无价值中转层，并增加知识概览引导。每项修复后必须回到同一正式加载路径再次点击，而不是仅用单测或源码检查代替。

本轮诊断工具：`scripts/audit-live-window.ps1`。脚本只允许已确认的进程 / 窗口及窗口内坐标；换实例后必须重新发现 PID、窗口句柄和截图位置，不能复用旧坐标盲点。
