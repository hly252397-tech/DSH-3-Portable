# 便携版 3：变更与答复质量门禁

本文件是便携版 3 的强制验收标准。涉及启动、插件、更新、数据路径的方案，未满足下列门禁时只能标为“临时诊断”，不得称为正式方案或推荐给用户。

## 0. “专业级”与“企业级”的强制定义

“专业级”和“企业级”是可验收等级，不是修饰词。答复、设计或实现不得在缺少对应证据时使用这两个称谓。

### 0.1 专业级

必须同时满足：

1. **事实准确**：先核对当前版本、源码、日志、发布通道和运行状态；时效性事实使用官方一手来源并标明核对时间。
2. **边界正确**：明确桌面宿主、DSH 子服务、插件、运行时、用户数据和源码更新的不同生命周期。
3. **方案完整**：同时覆盖正常路径、失败路径、数据保护、兼容性、验证方法和用户可见结果。
4. **可实施**：给出明确组件、状态、输入输出、文件位置和验收条件，不能只给原则或口号。
5. **可验证**：结论必须由静态检查、自动化测试、故障注入或真实环境验证支撑，并明确尚未验证的部分。
6. **不夸大**：临时恢复、设计方案、已实现、已测试、已部署必须分别陈述，禁止把计划写成完成状态。

任一项不满足，只能称为“建议”或“草案”，不得称为专业级。

### 0.2 企业级

企业级必须先满足全部专业级要求，并额外同时满足：

1. **供应链安全**：只信任允许列表中的 HTTPS 来源；固定不可变版本和制品哈希/完整性；校验发布身份、包名、版本、大小、依赖闭包与签名或可验证证明。
2. **策略治理**：具备发布通道、维护窗口、暂停/恢复、跳过版本、最低桌面版本、强制/可选更新和灰度策略；预发布版本默认不得静默强切。
3. **事务与幂等**：下载、解包、安装和验证在独立暂存区完成；提交使用原子指针或同卷改名；重复执行不会破坏状态。
4. **A/B 与自动回滚**：旧版本在新版本通过观察期前保持可启动；启动失败、崩溃循环、健康超时或兼容门禁失败时自动回到上一已知良好版本。
5. **最小中断**：等待任务空闲或维护窗口，只重启必要组件；运行时/插件更新只回收 DSH 子服务，桌面二进制更新才重启桌面宿主。
6. **数据与迁移安全**：更新前识别破坏性变更和数据格式迁移；迁移必须可备份、可验证、可恢复；用户数据不得作为更新清理对象。
7. **可观测与审计**：记录检测、决策、下载、哈希、安装、切换、验证、提交和回滚事件；日志带关联 ID、版本、时间、耗时和脱敏错误，且全部落在便携盘。
8. **受控发布**：至少经过候选运行时静态验证、隔离启动验证、真实 Profile 兼容检查和切换后观察期；支持逐步放量与撤回。
9. **故障预算与恢复目标**：定义检查/下载/启动超时、最大重试次数、崩溃阈值、回滚时限和保留版本数，禁止无限重试或失败后继续覆盖。
10. **独立验收**：类型检查、单元测试、集成测试、故障注入、离线/断网/磁盘满/断电边界测试、真实打包冒烟和回滚演练全部通过后才能启用全自动策略。

任一企业级项尚未实现或验证时，必须明确标为“企业级目标方案”或“候选实现”，不得声称已经企业级投产。

## 1. 先确认生命周期边界

- `DSH Codex Desktop`：Electron 桌面宿主，维护窗口、托盘和便携路径。
- `dsh --profile web`：由桌面宿主管理的子服务。
- 插件安装、升级、启用、禁用：桌面宿主保持运行，只回收 DSH 子服务。
- 桌面程序自身升级或替换 `App/`：必须从托盘彻底退出，再进行原子部署。

任何答复在提出“退出/重启”前，必须先说明重启对象，并从源码、运行日志或可复现测试确认必要性。

## 2. 正式方案的必备证据

1. **根因证据**：错误日志、缺失文件或调用链能对应到同一个故障点。
2. **数据边界**：配置、凭据、对话、缓存、运行时仍位于便携盘；不得无提示写回系统用户目录。
3. **事务性**：先暂存和校验，再提交；中途失败恢复旧文件和旧清单。
4. **可恢复性**：损坏社区插件只从启用列表隔离，保留依赖和文件；清单备份与原因写入审计日志。
5. **可观测性**：用户可以从 `.dsh-recovery/quarantined-bundles.json` 和 `manifest-backups/` 查到时间、来源、原因和备份。
6. **最小中断**：插件变更仅热重载 DSH 子服务；只有 App 更新才退出桌面。
7. **兼容与安全**：拒绝非法包名和路径越界；打包资源包含新增模块的完整依赖闭包。
8. **验证**：类型检查、单元测试、故障注入、独立打包目录导入、打包后启动冒烟必须通过。

## 3. 启动故障的标准处置

1. 启动前检查每个社区 bundle 的 `package.json`、`main`/根 `exports`、patch 入口及直接依赖清单。
2. 发现损坏时，原子备份 Profile 清单，只从 `dsh.profile.bundles` 隔离该插件，不删除依赖和插件目录。
3. 将插件名、指纹、故障阶段和原因写入便携盘内的恢复审计日志；审计写入失败则回滚清单。
4. 继续启动 DSH；若加载阶段仍报告具体社区插件，再隔离并在有限次数内重试。
5. 插件文件被修复且健康指纹发生变化后，自动解除旧隔离；正常的清单协调流程可重新启用它。
6. 官方 bundle 不做自动隔离，避免把运行时损坏伪装成社区插件问题；此类错误应明确失败并进入运行时修复流程。

## 4. 答复分级

- **正式方案**：满足上述全部门禁，并给出验证结果。
- **临时恢复**：用于立即恢复可用性，必须明确风险、影响和后续正式修复，不能冒充长期流程。
- **诊断建议**：只用于收集证据，不应修改用户数据或要求不必要的退出。

禁止在未核对现有实现的情况下，把删除插件、删除 Profile、清空用户数据或“完全退出桌面”作为通用建议。
