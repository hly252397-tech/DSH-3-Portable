## 1. 背景与目标

目前最需要解决的是：长任务续接不清楚、上下文不可解释、任务与文件关系不明确、测试包和正式版容易混淆，以及更新失败后恢复成本高。新增功能应帮助用户理解并控制工作，而不是增加更多互不关联的面板。

目标：

1. 回到旧任务时，能看清目标、进度、证据和下一步，减少重复交代。
2. 能区分历史记录是否加载、模型上下文是否准备好、记忆是否被实际使用。
3. 任务、执行、改动、成果、验证与发布状态形成可追溯关系。
4. 所有应用可控配置、环境、会话、索引、缓存和日志保持在便携盘。
5. 通过官方扩展机制逐步增加能力，不破坏启动、更新和已有数据。

调研边界：Qoder、Hermes 的参考来自官方文档及本地安装资料核对，未完成逐项实机交互体验。以下为 DSH 的目标需求，不是对本地竞品版本的已验证能力清单，也不是复制其代码的授权。

## 2. 范围和不做事项

### 2.1 需求总览

优先级：P0 为开发发布前置条件；P1 为首批产品能力；P2 为后续增强。优先级不是自动执行授权，也不代表工期承诺。

| 编号 | 能力 | 优先级 | 主要价值 | 依赖 |
|---|---|---|---|---|
| ST-00 | 稳定性与官方兼容基线 | P0 | 可启动、可验证、可恢复 | 无 |
| FR-01 | 任务恢复卡 | P1 | 重新打开后接着做 | 会话事件与任务标识 |
| FR-02 | 上下文仪表盘 | P1 | 解释占用、压缩和实际恢复情况 | 运行时可观测接口 |
| FR-03 | 成果与验证中心 | P1 | 区分生成、测试、部署与验收 | 成果索引、验证记录 |
| FR-04 | 编程／通用任务分类 | P2 | 分离开发与日常任务 | 既有项目与任务模型 |
| FR-05 | 任务中心、执行记录与改动审查 | P2 | 统一管理进行中和待处理工作 | FR-01、FR-03 |
| FR-06 | 知识中心与分层记忆 | P2 | 可控制地复用长期知识 | 来源、权限、作用域模型 |
| FR-07 | 定时任务与运行历史 | P2 | 自动执行且可追责 | 既有调度器、FR-05 |
| FR-08 | 会话恢复与对话时间轴 | P1 | 找回原会话和关键决定 | FR-01、稳定消息标识 |
| FR-09 | 浏览器元素批注 | P2 | 精确描述页面修改位置 | 现有完整版浏览器、附件接口 |
| FR-10 | 配置包导入／导出 | P2 | 安全迁移个人工作环境 | 版本化清单、迁移与回滚 |
| FR-11 | 桌面／运行时／插件分层更新 | P0/P1 | 最小中断、失败可恢复 | 既有唯一更新协调器 |

FR-03 同时覆盖 Hermes 式成果库和 DSH 所需的验证／发布证据，不另建重复的“工件中心”。FR-08 与 FR-01 共用会话恢复状态，不能各自保存一套任务进度。

### 2.2 本期不做

- 不整套复制 Qoder/Hermes，也不替换 DSH 官方 Agent 内核。
- 不新增第二套浏览器、更新器、调度器或会话数据库来绕过既有能力。
- 不承诺永久保留全部模型上下文，或在重开窗口后原样重建模型内部状态。
- 不默认跨电脑／手机云同步；“便携数据”“恢复原会话”“跨设备同步”是三个不同需求。跨设备同步需另行设计身份、加密、冲突与服务端存储。
- 不默认启用多智能体群聊、桌面宠物、悬浮助手和自动扩权；本轮未纳入交付范围。
- 不在稳定性验证未完成时启用全自动更新或破坏性数据迁移。

## 3. 核心用户流程

1. **继续旧任务**：打开任务 → 定位同一会话 → 显示恢复卡及来源时间 → 检查记录新鲜度 → 用户继续发送 → 展示本次实际采用的上下文。
2. **检查交付**：打开成果中心 → 选择文件／构建包 → 查看来源任务、修订和验证 → 进入改动审查 → 明确是否已部署及当前活动版本。
3. **反馈页面**：在原浏览器区域批注 → 预览脱敏后的截图与定位信息 → 手动发送 → 将批注关联到处理结果。
4. **更新组件**：检测 → 下载 → 验证 → 构建（确有构建时）→ 部署 → 健康验证 → 完成；出错显示阶段、原因和恢复结果，不提前显示成功。

## 4. 功能需求与验收

### ST-00 稳定性前置条件

- 正式开发前检查活动桌面／运行时、工作区差异和并行任务范围；不能只根据文档中的版本判断。
- 本文不宣称当前完整构建已通过。现有稳定性工作以 [交接记录](../../artifacts/stability-20260905/HANDOFF.md) 和实际诊断结果为准。
- 接入新功能前必须具备独立候选、可重复构建、启动／退出验收和失败回滚路径。
- 验收 ST-00-A：全新隔离目录构建与启动通过，不依赖未声明的机器缓存；已有 Profile 的会话、配置和插件保持可用；失败候选不成为活动版本。

### FR-01 任务恢复卡

**行为**：在现有任务会话内显示可折叠恢复卡，不强制新开右侧窗口。包含目标、用户约束、已完成、未完成、阻断项、下一步、最近验证结果、关联文件、最后更新时间和来源位置。

- 已完成项必须关联事件或验证证据；模型生成的摘要标为摘要，不作为完成事实的唯一依据。
- 恢复摘要记录覆盖到的最后事件标识；其后的消息必须继续加载，不能被摘要吞掉。
- 用户的新要求优先于旧摘要；发现文件／版本变化时提示重新核对，不静默沿用旧结论。
- 历史加载失败、记录过期、模型上下文准备失败分别展示；缺失数据不能用空白新任务冒充恢复成功。
- 显示卡片不等于已注入模型。若注入内容，必须走官方可持久化的会话输入路径并记录来源。

**验收**：FR-01-A，重启后恢复同一任务标识且展示正确事件范围；FR-01-B，新增消息覆盖旧摘要中的过时要求；FR-01-C，摘要损坏时仍能查看原会话并重建摘要；FR-01-D，没有验证证据时不得显示“已部署／已通过”。

### FR-02 上下文仪表盘

**行为**：展示当前模型上下文上限、占用百分比、统计时间，以及会话、系统提示、工具、技能、记忆等分类。支持查看最近一次压缩时间、压缩摘要来源和本次采用的任务恢复信息。

- 明确区分提供方实际统计、运行时统计、本地估算和不可获取；估算显示标记，未知显示“不可用”，不显示虚假的 0%。
- 分类必须互斥或解释重叠；总数与分类差额用未分类项解释，不能重复计算。
- 切换模型后重算上限；没有可靠上限时不生成百分比。
- 不为获取统计而额外发送收费模型请求；不得自动向用户暴露秘密系统配置、凭据或原始敏感内容。
- 压缩不删除原始会话记录，不改变任务是否完成。

**验收**：FR-02-A，已知计数夹具的百分比与分类正确；FR-02-B，未知／过期数据可辨识；FR-02-C，压缩及模型切换后指标不沿用旧模型值；FR-02-D，界面显示“已恢复”时能对应实际采用的事件范围。

### FR-03 成果与验证中心

**行为**：在现有文件／成果入口集中浏览生成文件、图片、链接、构建包和测试报告，支持按项目、任务、类型、日期筛选并回到来源会话。

- 成果关联来源任务、生成事件、文件修订或摘要、产生时间；同路径被覆盖时保留修订关系，不能把旧测试套在新文件上。
- 分开显示“已生成／未验证／验证通过／验证失败”和“未部署／候选／活动／已回滚”；多个测试失败时不得只挑成功项展示。
- 测试报告绑定被测制品摘要、环境与实际退出结果；测试进程结束不等于测试通过。
- 文件移走、丢失或路径变更时显示状态，不自动删除原始成果；移除索引与删除文件是独立操作。
- HTML、脚本和外部链接预览不获得桌面宿主权限；打开外部资源须遵守现有安全策略。

**验收**：FR-03-A，每条成果可追溯来源；FR-03-B，修改成果后旧验证标为不适用或过期；FR-03-C，活动版本来自真实部署指针；FR-03-D，断开便携盘或缺文件时显示错误且不丢索引数据。

### FR-04 编程／通用任务分类

**行为**：编程任务关联工作区及可选代码仓库；通用任务关联文件夹。复用原有项目／会话标识，通过视图和元数据分类，不搬移会话来改变类别。

- 编程任务展示分支、执行环境和改动审查；非 Git 文件夹仍可工作。
- 通用任务突出文件、成果和工具，不强制显示无意义的 Git 控件。
- 分类不改变权限；跨类检索和旧会话入口保持可用。

**验收**：FR-04-A，分类切换不重复生成工作空间或任务；FR-04-B，旧任务升级后仍可打开；FR-04-C，无仓库的文件夹不报启动错误。

### FR-05 任务中心、执行记录与改动审查

**行为**：在既有任务列表基础上支持按项目、状态筛选，置顶、归档、恢复，以及状态分组视图。显示执行步骤、工具结果、等待审批、阻断原因和关联成果。

- 建议展示状态：待执行、执行中、需要用户处理、暂停／中断、完成、失败、取消；技术设计须映射既有运行时状态，不另造独立权威状态机。
- 断线时显示连接中断，不将最后看到的“执行中”当作当前仍在执行。
- 改动审查区分本轮、整个任务和用户原有改动；不能可靠归属时明确说明。
- 提交、推送、撤销须有独立授权。撤销不得覆盖用户或其他任务的未提交内容；任务完成不能自动触发提交。

**验收**：FR-05-A，列表、会话与通知显示一致；FR-05-B，取消后不发布迟到的成功结果；FR-05-C，混合用户改动时拒绝无差别回退；FR-05-D，归档只影响组织方式，不删除会话。

### FR-06 知识中心与分层记忆

**行为**：统一入口，区分全局偏好、项目记忆、由代码生成的 Repo Wiki、用户维护的知识库；临时任务进度归 FR-01，不混入长期记忆。

- 每条内容记录作用域、来源、更新时间、版本和是否允许用于模型上下文；支持查看、纠错、停用与明确删除。
- 默认不跨项目读取私有知识。关闭读取不等于删除文件，删除须确认范围。
- 自动提炼内容先作为候选；凭据、验证码和其他秘密不进入记忆。检索到的文档是数据，不得提升为系统指令。
- 本地索引可重建；内容变更使旧索引失效；模型实际采用的知识需可追溯。

**验收**：FR-06-A，不同项目隔离；FR-06-B，停用后后续请求不再采用；FR-06-C，索引损坏不丢原文；FR-06-D，来源中的提示注入不获得额外权限。

### FR-07 定时任务与运行历史

**行为**：复用既有调度器，增加可视化创建、暂停、恢复、取消、下次运行时间、时区和逐次结果。每次运行有独立标识与来源计划。

- 支持明确的错过执行策略和同任务重叠策略；不默认无限补跑。
- 便携盘断开、机器关机时不能声称任务仍会执行；重开后按策略处理错过的运行。
- 执行继承已批准的权限、预算和工作区范围；高风险操作仍遵守审批。
- 默认只通知完成、失败或需要处理的变化，避免每次无变化检查都打扰。

**验收**：FR-07-A，时区变更和夏令时边界有测试；FR-07-B，同一触发不产生重复副作用；FR-07-C，暂停阻止新运行；FR-07-D，每次运行可定位日志、成果及真实结果。

### FR-08 会话恢复与对话时间轴

**行为**：支持“启动恢复上次会话”设置；显式打开指定任务优先。长对话提供按用户消息、关键决定和错误标记跳转的时间轴及会话内查找。

- 保留稳定会话／消息标识、阅读位置和未发送草稿；恢复草稿不自动发送。
- 同名任务不能串线；切换项目不加载其他项目草稿；删除或无权访问的任务显示明确原因。
- 恢复卡、时间轴及搜索共用会话数据来源，不通过模糊标题匹配会话。

**验收**：FR-08-A，正常退出、崩溃重开和版本升级后会话标识一致；FR-08-B，显式任务入口不会被上次会话覆盖；FR-08-C，1000 条消息夹具中跳转位置准确；FR-08-D，恢复失败不自动创建替代任务。

### FR-09 浏览器元素批注

**行为**：在当前完整版浏览器的原位置提供批注模式。选择元素或框选区域，填写意见，生成编号标记；统一预览后由用户手动加入消息并发送。

- 保存时间、页面地址、截图区域、批注文字以及可获取的元素定位和有限布局信息；页面导航后将旧批注标为可能过期。
- 密码、隐藏敏感字段及密钥型属性先脱敏再保存；地址查询参数亦须处理敏感信息。无法可靠脱敏时阻止采集并给出替代方式。
- 跨源 iframe 等无法访问时说明限制，可改为用户确认的区域截图，不绕过浏览器隔离。
- 菜单与批注浮层不能遮挡失控；打开菜单不得清空网页，关闭后滚动和交互状态保持。
- 不另开右侧浏览器，不上传整页不相关内容，不因保存批注自动调用模型。

**验收**：FR-09-A，多条批注只在用户发送后进入会话；FR-09-B，含密码和 token 的测试页面不泄露原值；FR-09-C，菜单开关、缩放和窗口大小变化不白屏；FR-09-D，元素失效可见且不会定位到另一个元素冒充成功。

### FR-10 配置包导入／导出

**行为**：将用户选定的技能、人设、记忆、非敏感配置及外观设置打包迁移，含 schema 版本、组件版本、文件清单与摘要。会话、定时任务默认不导出，须明确选择；导入的定时任务默认暂停。

- 排除 API 密钥、OAuth token、Cookie、密码、绝对机器私有路径等；提供导出清单预览。
- 导入先验证包大小、解压总量、条目数、路径越界、链接、版本和完整性；有效摘要不等于可信发布者。
- 先在隔离区预览冲突，默认导入新配置空间，不覆盖当前配置；失败完整回滚。
- 插件代码、脚本、MCP 和自动化定义默认禁用，单独审查启用；不信任导入包内的指令。
- 跨电脑加密数据不能解密时要求重新登录，不取消加密来实现“便携”。

**验收**：FR-10-A，含测试凭据的配置导出后秘密不出现在归档；FR-10-B，拒绝路径穿越、符号链接逃逸和解压炸弹；FR-10-C，失败后原配置摘要不变；FR-10-D，导入不会立即执行脚本或定时任务。

### FR-11 分层更新与可视化恢复

**行为**：沿用唯一协调器，在统一界面区分桌面、Harness 运行时与插件更新对象，展示当前／目标版本、阶段、百分比、错误及恢复结果。

- 插件／运行时更新优先使用官方热重载能力；确需重启时只回收所需子服务并等待任务安全点，不退出整个桌面。
- 桌面更新经用户确认后正常退出，由外部启动器切换不可变候选，健康验证通过才提交。
- 实际下载字节支持时显示百分比；总量未知或阶段不可量化时显示阶段进度／不确定状态，禁止编造百分比。
- 不需要构建的已发布制品标记“构建不适用”，不能假装在本地编译。
- 区分请求建立超时、传输停滞和任务总预算；有限重试，支持经完整性核对的缓存复用。具体实现先以随包工具能力验证，不假定支持断点续传。
- 失败保留原活动版本和用户数据，显示发生阶段及下一种可执行操作；“检查到最新”不是“候选已健康运行”。

**验收**：FR-11-A，慢速但持续传输、断网、中断、坏包、盘满均有故障注入；FR-11-B，更新插件时桌面保持运行；FR-11-C，失败候选可自动回滚且会话保留；FR-11-D，界面、日志、活动指针及制品摘要一致。

## 5. 数据与架构边界

以下为逻辑模型，不预先指定新数据库；技术设计先映射既有官方事件与存储，避免双写。

| 数据对象 | 必要关联／字段 | 权威来源与规则 |
|---|---|---|
| 任务身份 | taskId、sessionId、profileId、workspaceId | 既有会话／项目服务，不能用标题替代 |
| 恢复快照 | schemaVersion、最后事件标识、生成时间、来源、摘要 | 会话事件的派生数据，可失效／重建 |
| 上下文测量 | modelId、统计口径、上限、分类、时间、估算标识 | 实际运行时测量；缺失显式标识 |
| 成果引用 | artifactId、来源事件、相对路径、内容摘要、类型 | 文件及其生成事件；索引不是文件本身 |
| 验证记录 | artifactHash、测试类型、环境、退出结果、时间、报告路径 | 实际验证工具输出 |
| 更新状态 | transactionId、阶段、目标、活动制品、健康证据 | 既有更新协调器和部署指针 |
| 知识／记忆 | scope、来源、版本、启用状态、内容引用 | 官方可扩展服务；索引可重建 |
| 自动运行 | scheduleId、runId、计划时间、实际开始／结束、结果 | 既有调度器，防止重复提交 |

约束：

- 应用可控写入全部在便携根目录；引用便携盘内文件优先保存可重定位的相对路径，解析后必须校验边界。外部目录仅显式授权后引用。
- 本目标不等于能控制 Windows 自身的事件日志等系统行为；不能承诺应用无权控制的系统零痕迹。发现应用自身写到系统用户目录视为门禁失败。
- 会话原始日志不得为适配界面被批量重写；派生数据采用版本化 schema、原子提交、迁移备份和可重建索引。
- 模型可见的新输入必须满足官方“模型可见即已记录”；不能只由前端拼接隐藏提示。
- Electron 管窗口、进程、便携路径和桌面更新；Harness 内部能力走官方插件／服务／事件／Client Slot，不能把内部私有 API 当稳定接口。

## 6. 非功能要求与质量门禁

### 6.1 专业级／企业级定义

必须遵守 [变更与答复质量门禁](./便携版3-变更与答复质量门禁.md)。本 PRD 是企业级目标需求，不是企业级投产认证。

- 专业级：有事实来源、边界、失败处理、数据保护、可执行方案及验证证据。
- 企业级：在上述基础上具备供应链校验、权限治理、事务与幂等、审计、兼容迁移、故障预算、灰度／回滚和真实故障演练。
- 任一未验收项须显式列为未完成；禁止只凭单元测试宣布正式版修复。

### 6.2 可用性与性能目标

以下是待实测的初始目标，不是现有成绩；每次性能报告记录硬件、盘型、数据量与版本。

- 在参考 Windows 机器、便携 SSD、1000 个任务／每会话 1000 条消息夹具下，已有本地恢复卡首屏 P95 不超过 2 秒，会话内跳转 P95 不超过 1 秒。
- 后台索引和摘要重建不得阻塞输入；单次长操作可取消，有明确阶段和错误反馈。
- 上下文显示不得显著拖慢模型响应；统计以事件驱动更新，不为刷新仪表盘扫描全部会话。
- 键盘可完成核心流程，焦点可见，状态不只依赖颜色；验证 100%、150%、200% 缩放与窄窗口。
- 沿用现有主题、本地化字典和组件，不为本批能力整体重写布局。

### 6.3 安全、可恢复与可观测性

- 敏感导出、外发、删除、执行脚本、提交和推送遵守独立授权；打开文档或导入包不授予执行权限。
- 网络不可用时仍可读取本地会话与已有成果；不可用的在线功能明确降级，不伪造完成。
- 审计含关联标识、组件版本、阶段、时间、耗时和脱敏错误；日志轮转及保留策略可配置。
- 插件失败不得破坏宿主，关闭新功能可回到旧路径；禁用功能不删除已有数据。
- 每个需求交付需具备单测、失败路径测试、真实 Profile／Loader 组合测试、打包冒烟和相关迁移／回滚证据。

| 问题 | 默认处理，不阻塞本需求归档 |

| 当前运行时是否提供分类 token 统计？ | 无接口则只展示可靠统计，未知字段不估造；必要的接口升级另行评审 |
