# I024：功能板块开发面板

**日期**：2026-09-09（Asia/Shanghai）
**目标**：让维护者从桌面里直接看到 74 项功能条目与对应源码路径，不必每次回 `docs/00-交接入口/07-功能清单.md` 查。
**范围**：「视图 → 功能板块」菜单项 + 模态窗口 + 74 项静态注册表 + 文件路径点击复制。
**决策**：**全实例可见**（2026-09-09 当天修订：应用户要求从「仅开发态」放开为打包态也可见，见 §2.1 与 §6）。

---

## 1. 背景

DSH-3-Portable 现有 200+ 源文件（`src/`、`assets/`、`browser-library.cjs`、本地 `Data/DSH/profiles/web/local/*`），74 项功能散落 14 类。新人或回头维护时常见问题：「这个 UI 是哪份代码？」「改某段行为要动哪个文件？」。目前唯一索引是 `docs/00-交接入口/07-功能清单.md` 的 74 项表格，但流程不直接：打开文档 → 跳到具体行 → 去对路径。

本次新增一个**桌面端可见**的「功能板块」窗口：顶栏「视图」菜单底部打开，列全 74 项，按**视觉板块**（侧栏 / 外壳 / 设置 / 浏览器 / 卡片 / 启动更新 / 本地插件 / Profile）8 组聚合，每条带名称、文件路径（点击复制）、一句话说明。维护者在桌面里直接看到「我改这里要动哪个文件」，不必再翻文档。

## 2. 决策记录

### 2.1 可见范围：全实例可见（2026-09-09 当天修订）

**初版决策**（仅开发态）：仓库没有专用 dev 开关；`test/*` 一致把 `app.isPackaged === false` 当开发态用（`test/plugin-toolchain.test.ts:34`、`test/desktop-updater.test.ts:30` 等）。本面板定位开发辅助工具，按既有 dev 信号走最一致。落地为 `ShellActionDefinition.devOnly?` 元字段 + `localizedShellActions(locale, platform, isDev)` 第三参过滤 + `isActionEnabled` 打包态拒绝。

**修订原因**：用户日常用的是打包版（双击 `DSH便携版3.exe`），仅开发态可见意味着用户自己永远用不上；当天用户拍板「改成我也能用」。

**修订落地**：devOnly 机制整体拆除（无其他使用者，不留死开关）：
- `shell-actions.ts`：删 `devOnly` 字段、`LocalizedShellAction` Omit 项、`localizedShellActions`/`shellActionForShortcut` 的 `isDev` 参数与过滤分支
- `main.ts`：`shellBootstrap`/`popupShellMenu`/快捷键分发三处调用去掉 `!app.isPackaged` 实参；`isActionEnabled` 删 feature-panels 特判；`showFeaturePanelsWindow` 删打包态守卫与告警
- 测试改为「打包态动作列表必须含 feature-panels」的防回滚断言（`test/feature-panels.test.ts`）；`test/shell-actions.test.ts` 删 dev-only 快捷键用例

### 2.2 数据范围：全 74 项（用户已确认）

**为什么**：「想改某段行为」覆盖 1–74 任一条目，过滤范围会反向引入"哪些没收录"的二次查询。

**怎么落地**：`src/feature-panels.ts` 静态导出 `FEATURE_PANEL_CATEGORIES`（8 分类）与 `FEATURE_PANELS`（74 条 `{panel, categoryId}`）。分组按"视觉板块"切，**与 07-功能清单的 1..74 编号一一对应**（面板 id 用 P01..P74）。手工维护；不自动从 AST 抽取（会引入"全量模块清单"噪音，违背"功能板块"本意）。

### 2.3 文件路径复制走主进程 IPC，不走浏览器 Clipboard API

**为什么**：浏览器侧 `navigator.clipboard.writeText` 在沙箱化 webPreferences 下行为不稳定；改走 Electron 主进程 `clipboard.writeText` + 专用 IPC `dsh-shell:feature-panels-copy` 简单可靠。

**怎么落地**：
- `SHELL_IPC.featurePanelsCopy: 'dsh-shell:feature-panels-copy'`
- `shell-ipc-policy.ts:mayInvokeFeaturePanelsCopy(kind)` 限定 `kind === 'feature-panels'`，其他 renderer 调一律 `false`
- 前端点 `<button class="panel-file">` → `api.featurePanelsCopy(file)` → 主进程 `clipboard.writeText` → 返回 boolean，状态条提示「已复制：xxx」

### 2.4 沿用 `shortcuts.html` 骨架而非新建样式系统

**为什么**：与 `shortcuts.html`、`about.html` 同款（`theme.css` + `theme.js`、color-scheme 切换、Esc 关闭、搜索框、section/h2 分组），样式系统零新增。约定俗成的"轻量信息窗口"族。

**怎么落地**：`assets/feature-panels.html` 完全照抄 `shortcuts.html` 结构，差异在 row 渲染（`<span class="panel-name">` + `<code class="panel-file">` 按钮）和状态条提示。
