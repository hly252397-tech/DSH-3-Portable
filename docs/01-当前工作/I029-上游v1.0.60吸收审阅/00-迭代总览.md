## 1. 结论

上游 `MichengAI/dsh-codex-desktop` 在上次认祖点（v1.0.53）之后发布了 **7 个版本、17 个提交**。
变更文件共 **57 个**，但绝大多数不含产品行为：24 张截图/素材、4 份 README/CHANGELOG、11 个测试、
1 个 CI、2 个包/锁、6 个 `scripts/`，**真正的 `src/` 代码只有 9 个（约 500 行增删）**。

按组审阅后：**本仓库的实际缺口是 3 项**——已落 2 项，第 3 项（实测启动计量）本轮未做（见 §4-6）。

> **勘误（同日，用户追问触发）**：本节初稿写作「真正需要移植的只有 2 项」，并把「实测启动计量」判为
> 「本仓库已自研等价」——**该判断是错的**。两者只是文件名相同：本仓库 `src/startup-progress.ts` 是
> **固定百分比阶梯**（`boot:5 … complete:100` 十个里程碑 + 单调推进函数）；上游同名文件是**实测计量模型**
> （`verify/extract/copy/scan/sync/index/install/server/renderer` 九阶段 + `completed/total/unit` +
> 解析 pnpm 输出的 `parsePnpmProgress` + 中英双语文案）。本仓库**没有** `parsePnpmProgress`（已 grep 核实），
> 故该项属真缺口，应计入待办而非「已等价」。

**已移植（本分支）**：

| 上游来源 | 行为 | 为什么本仓库缺 |
|---|---|---|
| v1.0.59 `d281187` | `node_modules/.modules.yaml` 的 `ignoredBuilds` 构建许可恢复 | 本仓库的 `ensurePnpm11BuildPolicy` 只修**清单**（`pnpm-workspace.yaml` 的 `allowBuilds`）。历史 profile 一旦已被 pnpm 记下「忽略 node-pty/protobufjs 构建」，版本齐全就会让补种计划判 `already-installed`——包装得上，原生构建永远缺 |
| v1.0.55 `d281187`/`148af0e` | pending 更新清单不得把已安装插件降级 | `mergeProfileUpdates` 里 pending 覆盖 declared，且只按「版本不同」过滤，不比较高低。旧客户端留下的旧版本待更新项会把已装好的插件降级（连带降级其依赖） |

**未移植（逐条理由见 §4）**：随包 store 合并、插件矩阵基线地板、工具链版本、内置插件矩阵、开发者工具、启动进度、打包前离线自校验、CI 工作流。

## 2. 审阅方法

1. 上游源码抓取：`git fetch upstream main "+refs/tags/*:refs/upstream-tags/*" --no-tags`。
   **放进独立命名空间 `refs/upstream-tags/*`**，避免 `git fetch upstream --tags` 与便携仓库自有 `v1.0.x` 标签冲突（D-16）。
   ⚠️ 运维经验：本机 git 直连 github 曾报 `schannel: AcquireCredentialsHandle failed` / `Failed to connect to port 443`，
   加 `-c http.sslBackend=openssl -c http.version=HTTP/1.1` 后可正常抓取（浏览器通道始终可用）。
2. 官方双基线门禁：`App/resources/node/node.exe scripts/verify-dsh-official-baseline.mjs --online` → **PASS**
   （`bundled=0.1.2-rc.1 upstream=0.1.5-rc.2@c291e796… online=verified`）。
3. 逐文件比对 `refs/upstream-tags/v1.0.53..upstream/main`，并对每个候选改动**反查本仓库是否已有等价实现**（grep + 读取现有实现与用例）。

## 3. 实际改动

提交 `1761de5`（2 文件，+188/−5）：

- `src/plugin-seed.ts`
  - 新增导出纯函数 `needsIgnoredBuildRepair(modulesState)`：只认随包 pnpm 11 的 JSON 状态，命中 `ALLOWED_BUILD_PACKAGES`（`node-pty`/`protobufjs`/`koffi`/`@google/genai`/`@deepseek-ai/dsh-subprocess-local`）任一前缀才为真；YAML 旧状态与损坏内容一律不触发。
  - 新增 `repairIgnoredBundledBuilds(...)`：命中时沿用 **profile 自己记录的仓库**（绝不改用随包 store，避免 pnpm `UNEXPECTED_STORE`）重装同版本包。
    **与上游的有意差异：失败只 `console.warn` 不抛出**——进入该分支说明 profile 本身已可启动，机会性构建恢复不该把启动变成失败。
  - `applyPendingProfileUpdates`：以待更新目标与实际安装版本的**较高者**为准。
    **与上游的有意差异：不用随包清单当版本地板**——本仓库随包插件矩阵滞后于实际部署矩阵（`BUNDLED_PLUGINS` 记 codex-ui `0.2.102`，AGENTS.md 记录活动版为 `1.1.2`），
    拿它当地板会反过来覆盖用户与市场的显式升级选择（该风险由现有用例 `启动前会按 pending 清单升级社区插件…` 实测暴露）。
- `test/plugin-seed.test.ts`：新增 4 例（纯函数 1 + 构建恢复集成 1 + 不误触发 1 + pending 降级守卫 1）。
