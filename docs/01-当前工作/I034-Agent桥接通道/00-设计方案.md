# dsh-agent-bridge 设计与验收记录

## 目标与纠偏

用户已批准：任何 Agent 通过本机 HTTP 向指定 DSH 会话交任务，沿用该会话选择的本地或云端模型，并由 DSH 执行工具、处理审批。

早期直连 Ollama 的原型不满足这个目标，废弃其 model/provider/system 参数与模型客户端；不读取 settings.yaml 或模型密钥，不替用户批准工具。HTTP 接口面向其他程序，不新增桌面入口；任务内容与执行结果在原 DSH 会话中可见。

## 已确认的启动故障（根因 + 对照证据）

2026-09-21 真实 Cordis Loader 最小复现：`ctx.logger` 是内置对象，不是可等待服务。`inject: ['logger']` 使插件永远停在 PENDING(state 0)，`apply()` 从不执行，9800 因此从不监听。移除该项后同一测试得到 ACTIVE(state 2)。`loader.await()` 正常返回不代表插件 ACTIVE——此前把"DSH 启动完成"当成"插件已加载"就是这么误判的。

此前"只差重启"的判断不成立：无论重启多少次，旧写法都不会加载。

另一会话在 2026-09-21 给 `test/agent-bridge.test.ts` 补了 `ctx.provide('logger', ...)` 夹具，注释称"插件合法声明 inject:['logger']，是夹具缺服务"。该夹具会让旧故障重新隐形，本次不采纳该解释，只在其基础上补 `sessionController` 使旧用例仍能通过（未删对方改动），真正的守卫放在新文件 `test/agent-bridge-session.test.ts`：断言"不注入假日志服务也能 ACTIVE"。

## 实现边界

- 保留独立回环监听 `127.0.0.1:9800`（可配置，0 自动分配），以便跨 Agent 发现；端口被占用时失败关闭：`loader.create` 抛 `EADDRINUSE`，条目不驻留、不写发现文件（已测）。
- 只声明 `sessionController` 依赖，用官方 `resolveAgent(sessionId)` 恢复已有会话及其模型选择；会话不存在返回 404，绝不悄悄新建会话。
- 用 `createUserMessage({content, source:{kind:'plugin',plugin:'dsh-agent-bridge',form:'relay'}})` + `agent.followup()` 提交，每个任务独占一个普通回合；不改会话模型、系统提示或权限。
- 先注册监听再提交输入。以 `agent/inbox/claimed` 的消息 ID 关联 turn，只收该会话、该回合的 `assistant/message`、`tool/call`、`tool/result`、`turn/end`。`whenIdle()` 不代表成功。
- 只有 `turn/end.reason.kind=completed` 才判 succeeded；`blocked`/`error`/`max-tokens` 判 failed，`aborted` 判 cancelled，`interrupted` 判 interrupted；provider/model 取自实际助手消息的 source。
- 取消排队任务只 `inbox.remove` 自己那条消息；取消运行任务仅当当前回合仍归该任务，调 `agent.cancel(...,{keepInbox:true})`，且状态在 `turn/end` 之前保持 `cancelling`。不动他人队列、不销毁会话。
- 任务状态存于当前插件实例的有界内存（默认 100 项，优先淘汰已结束任务，满且全在跑时 429）；重载后旧 ID 返回 404 并提示查原会话，不自动重交。
- 超时（默认 600 秒）、监听、发现文件全部由 `ctx.effect`/生成器 disposer 管理；卸载时取消在途任务、关闭监听、删除自己写的发现文件。

## HTTP 契约 v2

| 接口 | 行为 |
|---|---|
| GET /health | 免鉴权探活，不含令牌，仅监听成功后可用 |
| GET /capabilities | 协议、接口、模型策略=session-selected、审批策略=DSH-native、超时与上限 |
| GET /sessions | 官方会话目录，供调用者明确选 sessionId |
| POST /tasks | `{sessionId,message}` → 202 `{taskId,messageId,status:'queued'}`；多余字段（含 model）400 |
| GET /tasks/:taskId | 状态、正文、实际模型、工具执行概况、结束原因、截断标记 |
| POST /tasks/:taskId/cancel | 只取消该任务 |

鉴权：启动时生成 32 字节随机令牌，监听成功后把 `{url,token,pid}` 以 0600 写入 `DSH_HOME/agent-bridge.json` 供本机 Agent 读取；不打印令牌、不进 URL 或 capabilities。除 /health 外都要 `Authorization: Bearer <token>`，用 `timingSafeEqual` 比较。Host 必须等于实际监听地址；带 Origin 或非 `sec-fetch-site: none` 的请求 403；无 CORS 头，挡跨站。请求体必须 `application/json`、上限 64 KiB，正文上限 1 MiB（超出置 `truncated`）。HTTP 断开不取消已受理的工作。

令牌授权的是"以本机用户身份驱动 DSH 会话"，不是模型密钥；调用方产生的消耗与工具审批仍由 DSH 会话侧承担。
