- Task Position：可变 Profile 本地插件 dsh-ui-tweaks 的 lib/client.js；归档 customizations/ui-tweaks/lib/client.js。

- Indirect Impact：主视图可响应性、内存、定制黑洞行及更新健康状态的可信度。
- 上游：官方客户端 Loader 调 apply；下游：DOM style 写入；所有写入由 injectStyle 拥有。调用点为 apply 和 applyAll。
- Reusable Existing Capability：现有客户端热加载、Electron 诊断接口和 ui-baseline；无需新更新机制。
- Architecture Constraints：不写不可变活动槽，不变更 Profile bundles/依赖、运行时及对话；两个客户端副本已有其他差异，只改同一故障行。
- Expected Files：上述两文件、本记录、功能清单；回归证据存 Data/Temp/blank-view-evidence。
- Do Not Touch：src/main.ts 本轮不再追加等待时间修改；sidebar-spaces、better-sidebar、build-sidebar-layout-compat 的在途基线漂移保留。
- 公共 API / Schema：无变化。行为归属为客户端纯前端修复，无新后端入口。
- 风险：阻断循环不能丢失真实外部 DOM 改动的响应；用原插件在真实 Electron 中的观察器对照及实机主界面验收。
- Regression Scope：旧/新观察器回调次数、样式内容一致、主页非空、真实菜单打开关闭、刷新稳定、TypeScript/全量测试。

## 第二处故障与范围扩展

白屏修正后真实主界面已经渲染，但 45 秒后后台仍退出。重启带诊断的正常活动槽，从其真实 ChildProcess stderr 捕获：`dsh: fatal load failure: ReferenceError: dataRoot is not defined`，位置 `dsh-p3-tiny-watch/lib/index.js:152`，随后 `EXIT 1 null`。当时采集至 Data/Temp/blank-view-evidence/backend-tail.log；后续重新安装监听覆盖了该环形文件，当前文件是新后端日志，不把它冒充原始异常快照，故障文本保留于本记录及当轮工具输出。

追加 GCC：故障归属 P3 Tiny 插件宿主定时检查；上游为 apply → installSchedule → timer.timeout / interval；下游为 monitor.status/check 及诊断日志。dataRoot 原本只在 apply 作用域，installSchedule 的正常分支和 catch 分支均错误引用它，使 catch 本身再次抛错。改动只增加内部显式参数并从现有 apply 传入；不改变公开配置、检查周期、数据位置、市场源、通知和插件启用状态。源码 plugins/dsh-p3-tiny-watch/lib/index.js 与真实 local 副本改前 SHA256 一致，分别最小修改两处，不覆盖并行工作的其他文件；该问题在源码 21:46:10 版本中存在。
