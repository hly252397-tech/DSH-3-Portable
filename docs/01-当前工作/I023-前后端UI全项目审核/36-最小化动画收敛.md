# 窗口最小化及最大化/还原动画收敛

## 用户问题

用户反馈 Windows 窗口状态切换动画出现异常中间帧：最初截图表现为最小化过程中左侧 DSH 内容变淡、首页列被压窄，右侧 Files 面板与外壳不同步，截图为 `C:/Users/96551/AppData/Local/Temp/codex-clipboard-31a940b4-c86e-436f-9e5b-66d6ca672c4c.png`。后续确认红圈位置是右上角“最大化/还原”按钮，点击该按钮也会复现同类错位。

## 根因

主窗口不是单一网页，而是外壳 BrowserWindow 加上 DSH、Files 面板和浏览器标签页多个 `WebContentsView` 合成层。Windows 原生窗口状态动画开始时，子视图仍按旧尺寸独立重绘，造成不同合成层被截取到同一动画中间帧；原先只监听最小化/恢复，没有冻结最大化/还原路径。

## 处理

- 仅在 Windows 安装窗口表面保护：真正最小化时把主窗口暂时透明并隐藏 DSH、Files 与浏览器标签页子视图；最大化/还原不隐藏内容，只延后一次布局计算，保留原生窗口外壳和内容层连续可见。
- 收到 `restore` 或 `resized` 后等待窗口状态稳定，重新执行统一布局，再恢复不透明度；最大化/还原期间不切换内容可见性，不改变 DSH 页面、会话或 Files 数据。
- `layoutDshView()` 增加冻结态短路，避免窗口动画期间的 `resize` 回调再次把子视图提前显示。
- 外壳的正常隐藏到托盘路径保持不变，macOS/Linux 不启用 Windows 专用保护。

## 对齐关系

- 用户入口：主窗口右上角 Windows 原生最小化按钮，以及最大化/还原按钮；恢复入口为任务栏窗口按钮或托盘打开。
- 前端/视图：`createWindow()` 安装 `installWindowSurfaceGuard()`；状态稳定后复用 `layoutDshView()`，确保外壳、DSH、Files 和浏览器页使用同一套边界计算。
- 后端：无业务后端变化，仅桌面主进程管理合成层可见性。
- 反馈：最小化及最大化/还原过程中不再显示子视图错位中间帧，状态稳定后内容重新按当前窗口尺寸显示。

## 2026-09-13 流畅度补修

- 用户反馈上一版虽然消除了错位，但最大化/还原时整窗透明再显示，产生“突然消失、突然出现”的不连续感。
- 最大化/还原不再隐藏 DSH、Files 和浏览器标签页等独立 `WebContentsView`，只暂缓一次布局计算；原生窗口和内容层保持可见，让 Windows 原生动画连续播放。
- 只有真正的最小化/恢复继续使用整窗透明保护，避免任务栏动画截取子视图旧帧；恢复后再恢复窗口不透明度。
- 本轮实际运行槽已切换到 `1.0.66-local-2e8e3b8612a92d8e`，启动健康校验通过，窗口实测结果已落盘；因此本轮验证覆盖“源码 → 构建 → A/B 切换 → 真实窗口状态切换”完整链路。
- 上一版实测暴露出“最大化/还原也隐藏内容层”会造成侧栏压缩和内容截断，本轮改为 `mainWindowLayoutDeferred` 延后布局；最大化/还原不再调用内容隐藏路径。
