# 插件更新后主题保持

日期：2026-09-08。用户在 Codex UI 配套插件更新后发现左侧工作栏恢复淡绿色。

## 原因与归属调整

正式 Profile 使用注册表依赖 `@michengai/dsh-codex-ui: 0.2.113`。当前安装文件含上游 `.dcu-root { background:#eef7f5 }`，与此前修改过的本地副本不同。插件更新重新安装发行包，包内定制随之被覆盖。便携版原有主题只在 qoder 预设覆盖这一区域，其他预设没有同等保护。

本次把白色背景、灰色悬停和边框约束放入 `assets/theme.css`，由已有桌面主题注入链路应用到真实 DSH 页面。规则限定浅色模式，覆盖展开、收起及玻璃伪元素背景；不依赖第三方包内修改或样式加载顺序。保留深色模式及第三方插件正常升级能力。既有会话宽度拖动条隐藏规则也迁到同一主题层，避免这一外观约束再次被升级抹掉。

真实重载测试进一步复现：原 `createMainWindow()` 只在初次 `loadURL()` 后调用 `insertCSS`，普通页面刷新会清除这份注入样式。`src/main.ts` 现对每次同源页面 `dom-ready` 重新注入主题，并以按视图保存的 Promise 合并同一文档的初始就绪检查，避免首次启动重复注入。视图销毁后不再发送主题消息。

保留 `local/dsh-codex-ui` 历史定制副本；它不是当前注册表插件的更新保护机制。旧测试中“当前安装包必须逐字等于本地定制包”的约束与正常更新冲突，现改为按规则的实际所属层检查；没有用旧包回写用户当前安装目录。

## 三项对齐

| 层级 | 链路及范围 |
| --- | --- |
| 用户入口 | Codex UI → 配套管理插件 → 更新；左侧工作栏、主题设置、展开/收起 |
| 前端 | 未修改的上游 Codex UI 客户端 + 便携版 `assets/theme.css` |
| 后端 | 继续使用既有插件管理和桌面主题注入，无新增接口、数据迁移或更新拦截 |
| 结果 | 浅色工作栏保持白色；悬停可辨认，深色仍正常切换；具体运行证据见下 |
