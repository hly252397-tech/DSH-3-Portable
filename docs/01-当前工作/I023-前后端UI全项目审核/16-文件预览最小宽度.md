# 文件预览最小宽度

2026-09-12。用户要求文件预览区最小与文件树等宽。根因：文件面板可缩至 280 px，但文件树仍固定默认 240 px，剩余预览区成竖缝。

本次在本地 sidebar-spaces 样式层约束：文件树最大占内容宽度的 50%，预览至少 50%；显示文件树时右面板最低 488 px（预览 240 + 文件树 240 + 外框留白 8），极窄视口按可用宽度收敛。主区让位与实际面板共用同一宽度计算，适用于首页及文件树打开的其他页面；关闭右面板解除最低宽度约束。不改第三方包、持久化宽度或后端协议。

开发前状态：前端/UI 待验证；后端不适用（布局约束，无接口变更）。复验需覆盖外面板拖窄、文件树拖宽、文件打开、文件树隐藏/恢复、面板关闭及缩放。官方在线基线通过。

交付验证：真实 Profile/Loader 页面在独立 Electron 验证窗口内通过，未重启用户桌面。外面板拖到最小时宽 488 px，预览和文件树各 240 px；文件树向左拖宽仍受半宽约束。实际打开 AGENTS.md、文件树隐藏与恢复、右面板关闭与恢复均正常，关闭后主区恢复全宽。80%、125%、150% 缩放及 1100、1920 窗口宽度下预览不小于文件树，主区与右面板不重叠。左栏折叠通过调用原按钮处理器完成（原按钮在桌面样式中隐藏），未作为可见入口验收。

三项对齐结论：入口为既有分隔条与文件树开关，前端宽度约束在拖动、开关和缩放时真实生效；文件读取沿用既有后端并验证实际显示内容，无新增 API。相关 CSS 已重新构建到本地插件客户端，安装目录通过 Junction 加载，刷新后生效。

类型检查通过；全量测试 431 项，419 通过、12 跳过、0 失败。证据：`artifacts/file-preview-width-20260912/results.json`、`minimum.png`、`tests.log`，复验脚本同目录。测试首轮因关闭按钮定位文案错误超时，修正验证脚本的定位后完整重跑通过，产品代码无需额外调整。
