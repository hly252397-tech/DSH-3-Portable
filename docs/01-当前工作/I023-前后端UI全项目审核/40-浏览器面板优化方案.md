# 40 · 右侧浏览器面板优化方案（提案，未实施）

## 0. 结论先行

右侧浏览器面板当前有三处可优化：

1. 顶部叠了**三层 chrome**：工作台标签条（40px）+ 网页标签条 + 导航条（42px）。只开一个网页时，中间那层网页标签条是冗余的。
2. 导航条右端 **5 个文字按钮**（收藏/资料/下载/外部/更多）挤占地址栏宽度。
3. 面板**默认过宽**（约占视口 60%），把对话区挤成窄条并留下大片空白。

对应三条优化：① 单标签隐藏网页标签条；② 文字按钮收进「更多」；③ 默认宽度收窄。

**三处关键更正**（相对效果页初版的口径）：

- 真正在跑的浏览器 chrome 是 `assets/browser-panel.html`，**不是** `assets/shell.html` 里那份 `#browser`（shell 那份是外壳侧冗余/历史副本，改它不生效）。
- 优化① **不是纯素材改动**：它牵涉 `src` 的几何常量（见 §1），必须连主进程偏移一起改，走全量构建。
- 优化③ 的真实杠杆在 **better-sidebar 侧卡宽度偏好**，不在 shell 的 `widthRatio`。

## 1. 现状与代码定位

- 实机证据：`artifacts/browser-panel-20260913/before-real.png`（红框为右侧面板，顶部三层 chrome 清晰可见）。
- chrome 结构：`assets/browser-panel.html`
  - `.browser-tabs` 高 40px（网页标签条 + `#browser-tabs-actions` 的「+」）。
  - `.browser-nav` 高 42px（后退/前进/重载 + 地址栏 + 主页 + 收藏 + 资料/下载/外部(`.optional`) + 更多）。
  - `.browser-tool.optional` 目前**仅在 `max-width:620px` 时隐藏**。
- 按钮接线：`assets/browser-workspace.js`
  - `elements.external → browser.openExternal()`；溢出菜单 `#browser-overflow` 现有 下载/资料 等价项，**但无「在系统浏览器打开」等价项**（直接常隐「外部」会丢功能）。
- 几何约束：`src/browser-panel-layout.ts` 的 `BROWSER_TABS_BAR_HEIGHT` 被 `test/browser-panel-layout.test.ts:57` 钉死等于 `.browser-tabs` 的 CSS 高度；主进程按它给原生页面视图做垂直偏移。**运行时隐藏标签条而不改该常量，原生视图会错位约 40px。**
- 宽度来源：面板占位由 better-sidebar `BrowserView` 的 `reportBounds` 上报（`portable/browser-view.js`），默认宽度取决于 better-sidebar 侧卡宽度偏好；shell 的 `widthRatio(0.36)` 只是无 panel 上报时的兜底。
- 互斥：`dsh-sidebar-spaces` 的 `coordinateRightPanels(sidebarRight, betterSidebar)` 保证同一时刻只有一个右侧面板。

## 2. 优化分项

### 优化 1 · 单标签隐藏网页标签条（省约 40px 垂直）

- 改法：网页标签数 = 1 时隐藏 `.browser-tabs` 行，「+ 新标签」并入导航条；≥ 2 时恢复显示（多标签切换不受影响）。折叠/最大化等控件保留。
- 动文件：`assets/browser-panel.html`、`assets/browser-workspace.js`、`src/browser-panel-layout.ts`（隐藏态几何常量）、主进程偏移逻辑。
- 构建：**全量** `Build-DSH-Portable.ps1`（动了 src）。
- 测试影响：需同步 `browser-panel-layout.test`（常量）与 `main-safety.test`（钉 `.browser-tabs*` CSS 规则）的断言。
- 风险：隐藏态/显示态切换时原生视图偏移要按「标签条 0px / 40px」两态重算，否则页面上下错位移。
- 回滚：还原上述文件。

### 优化 2 · 文字按钮收进「更多」（地址栏加宽约 100px）

> **状态（2026-09-13）：已实施。** 候选槽 `1.0.66-local-536047aaadd3f01a` 已随用户重启激活；源码 = release = 候选三方校验一致；`startup-error.log` 无新增、gateway boot `apply 完成`。**已目视确认（用户截图，证据 `artifacts/browser-panel-20260913/after-real.png`）**：导航条右端仅「已收藏/更多」、地址栏显著加宽；「更多」菜单含 下载内容/浏览器资料与设置/**在系统浏览器打开**。

- 改法：导航条常隐 资料/下载/外部（`.browser-tool.optional` 改为常隐）；**先**在 `#browser-overflow` 补「在系统浏览器打开」等价项并接线 `browser.openExternal()`，再常隐，避免功能丢失；「收藏」保留。
- 动文件：`assets/browser-panel.html`、`assets/browser-workspace.js`（**纯素材**）。
- 构建：界面快通道 `Build-UI-Only`；但当前被在途 src 改动门禁拦截，需 `-Force`（混血槽）或随下一次全量。
- 测试影响：不改行高（导航条仍 42px）、不碰几何常量；溢出菜单本就有 下载/资料 等价项，仅补 外部。预期零断言改动。
- 回滚：还原两文件。

### 优化 3 · 默认宽度收窄（60% → 约 42%）

- 改法：下调 better-sidebar 侧卡**默认**宽度；保留用户拖拽与上限钳制（`viewport − 900px` 对话保护）。
- 动文件：`Data/DSH/profiles/web/local/dsh-better-sidebar` 的侧卡宽度偏好默认值 / prefs schema 默认。
- 构建：profile 插件为目录链接，改 `local/` **即时生效**，无需打包；但需确认 seed 不覆盖该偏好。
- 风险：已持久化 prefs 的老用户不受新默认值影响（仅新会话/重置生效）；需确认与 `coordinateRightPanels` 互斥无冲突。
- 回滚：还原默认值。

## 3. 建议实施顺序

1. **优化 2** 先行：纯素材、不丢功能、不碰几何，收益直观（地址栏变宽）。
2. **优化 1** 其次：收益 40px 垂直，但需 src 几何 + 测试断言同步，成本最高，是否值得由用户拍板。
3. **优化 3** 单独真机验证：改 local 即时生效，多档窗口/缩放复测拖拽与钳制。

## 4. 验收方式

- 实施前：以效果页肉眼拍板（改前/改后并排、2× 放大、浅+深、px 标注）。
- 实施后：沿用 `39-外壳顶栏改版` 流程——离屏渲染改前/改后 + 2× + 浅深 + 实测几何表，断言全 PASS 才在功能清单登记；并真机重启验证候选槽健康。

## 5. 未决 / 待拍板

- 优化 1 是否值得为省 40px 引入 src 几何改动（成本高于 ②③）。
- 优化 3 对已持久化 prefs 的老用户无效：保持"仅新默认"还是做一次性迁移。
- 在途 src 改动（`desktop-theme.ts` / `main.ts` / `shell-contract.ts`）未打包，会拦截界面快通道；优化 2 若走快通道需 `-Force`（产生"新界面 + 旧主进程"混血槽）。
