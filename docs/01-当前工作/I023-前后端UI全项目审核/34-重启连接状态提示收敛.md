# 重启连接状态提示收敛

## 问题

底部导航同时出现“正在重启…”和“连接中…”。两者来自不同层：

- “正在重启…”来自 `dsh-restart-button`，表示桌面桥已经收到重启请求。
- “连接中…”来自 DSH 会话连接指示器，表示页面正在等待连接恢复。

此前重启按钮在桌面桥请求返回后立即恢复为“重启应用”。当重启交接没有完成、或页面仍然停留在原窗口时，用户无法判断重启到底成功还是卡住。

## 本次处理

- 重启请求成功返回后继续保持“正在重启…”，不再提前伪装成已完成。
- 页面在 15 秒内没有卸载并重新进入应用，按钮改为短文案“重启失败”；悬停标题和辅助读屏仍保留失败语义，避免底部窄按钮截断。
- 失败状态允许用户重新走两步确认流程。
- “连接中…”保留为真实连接状态，不用 CSS 隐藏；从设置列中拆出并压缩到 footer 同一行右侧，连接恢复后由 DSH 原生状态自动消失。
- 用户复核又发现窄栏中“正在重启…”会被截成“正…”。已将进行中文案收敛为“重启中”（英文为“Restarting”），并把“文案实际宽度不得超过按钮可用宽度”加入独立 Electron 回归，避免只测坐标、不测可读性。

## 后续排版修正

用户复核指出“连接中…”仍然挂在“设置”按钮下方，造成设置入口被撑偏。根因是连接指示器与设置按钮同属设置插槽，但旧底部 CSS 只安排了两个操作按钮。

本轮进一步将连接指示器压缩到 footer 同一行；底部按“重启 / 连接状态 / 设置”三列排版，三个元素贴底对齐，连接状态不再占第二行，也不再因连接状态改变按钮位置。

## 验证

- 重启客户端静态回归：确认存在超时收敛、失败状态和重试路径。
- 独立 Electron 窗口回归：初始状态为“重启应用”；模拟桌面桥失败后显示“重启失败”，没有触发用户桌面重启，证据为 `artifacts/black-hole-ui-20260913/restart-status-results.json` 与 `restart-status.png`。
- `scripts/ui-baseline.mjs --record`：通过，历史记录为 `customizations/ui/history/2026-09-13T06-09-03-519Z.json`。
- 成功重启交接仍需在用户确认后于独立候选窗口验证；本轮不触发正在使用的用户桌面重启。
