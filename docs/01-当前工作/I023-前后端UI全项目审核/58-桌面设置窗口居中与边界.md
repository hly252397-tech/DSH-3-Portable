# 桌面设置窗口居中与边界

问题是桌面设置窗口没有按主窗口位置计算居中且重开复用旧位置；证据是截图窗口左侧溢出主界面，main.ts的showDesktopSettingsWindow只传parent/固定760×620，复用分支仅show/focus；下一步增加主窗口可见内容区域内的居中定位与事件跟随，并按可用区域缩小。

3. 上游：外壳设置/更新入口→shell IPC/action。

5. 调用方：main.ts的showDesktopSettingsWindow创建及复用分支；不影响about/shortcuts窗口。
6. 公共能力：Electron BrowserWindow.getContentBounds/setBounds与screen.getDisplayMatching工作区。
7. 既有实现：固定尺寸加parent，不足以保证Windows父子位置跟随；不建第二套设置页。
8. Reusable：复用原设置页面、preload、更新/通知处理器。

## 实现与证据

- Electron官方BrowserWindow文档的Platform notices明确Windows子窗口不随父窗口移动：https://www.electronjs.org/docs/latest/api/browser-window#platform-notices 。核对安装版electron.d.ts的getContentBounds/setBounds、screen事件声明。
- 新增纯几何计算：父内容区域与显示器workArea交集内居中，最多760×620、周边16DIP留白；可用空间不足自动缩小，负坐标显示器不归零；父窗口完全屏外时退到显示器可用区，避免不可达。DIP计算，不重复乘DPI。
- 创建时show:false，定位后ready-to-show再显示；再次show、父move/resize/restore/show、显示器变化统一同步。窗口不可拖离、不可最大化/手动缩放；关闭父/子窗口清理监听，不累积定时器。保持独立非modal窗口，避免遮罩盖不住原生网页且不额外阻断主界面操作。
- settings.html≤580px单列顶部分类、可滚动内容、控件单列；原业务处理与设置保存完全不改。
- 活动主进程28976临时加载同一编译helper进行验证，未重启/未修改运行槽。旧负对照：main从(1137,65)移动到(1073,89)，设置仍停(900,386)，且左边溢出。新设置为(1373,229,760,620)，与主窗口居中公式一致；真实移动、缩放、hide/show复用、恢复主窗口共5项PASS。证据customizations/ui/evidence/settings-contained-20260920/live-results.json及live-settings.png。
- 隐藏原生父/子窗口4尺寸×2缩放×3页面+8几何+1监听清理=33项PASS，matrix-results.json；窄窗截图narrow-settings.png已肉眼核验。测试不触发更新、清除或保存等有副作用动作。
- 首次tsc报Electron事件重载不接受union，改为逐事件显式注册/移除；首次Inspector动态import缺callback，验证改用Node原生require加载无TLA的编译模块；首次矩阵选择器未命中分类，已修正为实际Nav id并断言可见Page id再复跑。均为验证/类型阶段失败，未混称通过。
- 类型通过；全测542项=529PASS/0FAIL/13SKIP（Data/Temp/settings-contained-tests.log）。共享受保护清单无漂移，baseline检查PASS。
- 打包前53个主进程编译模块对照旧asar，唯一既有差异为workbench-geometry.js一行“视口至少留400px给对话”；用户明确批准一起合并且不自动重启。本轮main差异与新增helper独立，不覆盖其他源码。
