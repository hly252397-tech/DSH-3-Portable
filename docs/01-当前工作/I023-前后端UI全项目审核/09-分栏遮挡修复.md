# 分栏遮挡修复

2026-09-12，用户三张截图显示 Files 面板加宽后截断首页卡片、活动分布及输入框。

当前真实启动链：桌面槽 1.0.63-d37260193e133f0f → Harness 0.1.5-rc.2-fd316e6b895e48c1 → 正式 web Profile，Codex UI 1.1.2、better-sidebar 0.18.0-alpha.0、本地 sidebar-spaces。在线规范基线 c291e796 核对通过。

根因：本地首页样式让 #root 只让位 `min(面板宽度,45vw)`，而桌面层给面板的另一上限为 `100vw - 1040px`，二者不一致。2560 px 窗口、面板请求 1400 px 时，主内容仅让位 1152 px，多出的 248 px 覆盖首页。桌面又设对话列 min-width:680px，缩小窗口会继续溢出。

| 层级 | 对应行为 | 状态 |
|---|---|---|
| 用户入口 | Files 卡片、右侧分栏拖动、窗口大小与页面缩放 | 通过 |
| 前端 | 本地 sidebar-spaces 自有样式共用面板宽度上限，首页按对话列缩放 | 通过 |
| 后端 | 复用已运行的正式 Profile/Loader、文件浏览服务；布局无新增后端接口 | 不适用（纯布局） |

不覆盖第三方 Codex UI 安装包，不改写当前桌面不可变槽。运行证据保存在 `artifacts/sidebar-layout-20260912/`。

本次布局范围限定首页 `data-phase="hero"`；进入已有对话后继续使用现有对话布局，避免扩大变更范围。Electron 隔离窗口连接同一正式服务，加载当前桌面主题并检查 80%、100%、125%、150% 实际 `WebContents` 缩放，四项全部通过（`electron-results.json`）。大比例缩放或短窗口允许页面正常纵向滚动，不裁剪内容来维持固定高度。

修复在 `local/dsh-sidebar-spaces/lib/client.src.js` 的自有布局层：根视图与面板共同消费 `--dss-panel-width`，为主内容保留 640 CSS px（含左栏），面板保留 280 px 最小宽度；对话列允许收缩，首页卡片在窄列变为两列，活动分布与输入框保持等宽。规则兼容正式桌面主题后加载及普通 Web 宿主，不再分开裁剪。

`node_modules/dsh-sidebar-spaces` 当前是指向本地源码目录的 Junction。构建 `client.js` 后两处 SHA256 一致，正式服务的新页面已加载修复；无需重建或降级桌面，现有打开页面需刷新后加载新客户端。另一个桌面版本修改保持不动。

Chromium 真实正式 Profile/Loader 共 11 项验证通过（`results.json`）：2560×1348 下三种面板宽度、1360×900、1100×720、960×720，明暗主题、折叠/恢复、真实指针拖动及页面刷新。每项核对根视图右边与面板左边一致，卡片/活动/输入及输入按钮不越界、活动与输入等宽。输入文本测试未发送消息。截图 `after-2560-1400.png`、`after-1100-700.png` 已查看。

类型检查通过，全量测试 431 项：419 通过、0 失败、12 跳过（`tests-final.log`）。第一次运行发现旧浏览器缩放测试把 1360 px 窗口新加的宽度保护误当成缩放结果，测试改用 1920 px 以独立验证缩放换算，未改浏览器功能；中途一次临时目录清理 EBUSY，完整重跑通过。此处不把静态的旧桌面宽度断言当作本次布局验收依据，以当前正式页面真实矩形为准。
