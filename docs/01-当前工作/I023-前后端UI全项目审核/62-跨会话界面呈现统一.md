# 62 — 跨会话界面呈现统一（2026-09-24，已验收）

## 用户要求与边界

用户发现不同会话的界面和状态不一致，要求检查并统一应当全局统一的部分。统一的是同一桌面窗口桌面布局的显示偏好：右卡片开合、底部面板开合与尺寸、已全局共享的右卡片宽度。窄于 768px 时右卡片成为全屏抽屉，保留原有按需展开行为，不把桌面“展开”偏好强加给手机宽度。各会话的对话、任务/模型状态、工作目录、文件/终端/浏览器标签与内容继续隔离，不把一个会话的数据覆盖到另一个会话。

## 现状与证据

- 现役为桌面 `1.0.66` 槽 `1.0.66-local-5d3a0221e067453f`；应用 PID 43376 仍运行，桌面更新事务 `phase=none`。用户后来允许继续验收；只使用 `dsh-ui-tweaks` 的页面热重载令牌加载新客户端，未触发菜单中会回收整个 DSH 运行时的“重新加载”。
- `dsh-better-sidebar/src/client/state.ts` 的 `SidebarStore` 以 `dsh-sidebar:v1:<sessionId>` 存放整份工作台状态；`loadState` 和缓存切换仅用全局键覆盖 `width`。因此历史会话各自的 `panelOpen`、`bottomOpen`、`bottomHeight` 会重新出现。
- 同一状态还含分栏树、标签、终端/浏览器计数、文件展开、浮窗；这些含会话内容，不能整体改成全局键。
- `Sidebar.tsx` 的底部“首次展开自动开终端”用一个跨会话 `bottomWasOpenRef`。切换会话时若开合不同，可能被误当成用户展开；统一呈现时也必须按会话重置此过渡记录。
- 改动前 `scripts/ui-baseline.mjs` 为 PASS。官方 HEAD 兼容门禁曾报告记录 SHA 与现行 HEAD 不同；不得自动改基线，客户端仅复用本地已存在的状态接口，不引入官方新 API。

## 本轮审计：什么全局，什么不全局

| 分类 | 状态 | 理由 |
|---|---|---|
| 主题、UI 字体、Codex 左栏展开树、对话内容宽度、卡片类型开关 | 已有全局设置/持久化 | 同一用户的界面偏好，不应随会话跳变；本轮不改它们的写者 |
| 右卡片开合、底部开合、右卡片宽度、底部高度 | 本轮提升为全局呈现 | 它们只决定外壳占位和可见性；旧版混存于每会话状态产生切换跳变 |
| 当前标签、标签分栏、浮窗、文件树展开/预览、终端、浏览器页面 | 保持每会话/每标签 | 含目录、页面、进程或内容上下文；共享会把另一个会话的数据带入当前会话 |
| 对话、工作目录、运行/审批/模型模式、草稿 | 保持每会话 | 是任务事实或安全上下文，不可为“外观一致”而覆盖 |

## 改法与真实写入路径

1. `src/client/state.ts`：新增可选 `dsh-sidebar:v1:presentation` 键，仅含三个显示字段；读取时校验并按当前视口钳底部高度。旧的 `dsh-sidebar:v1:<id>` 结构不变，桌面宽度下首次访问的会话建立全局基准；窄屏抽屉不读写此键。旧全局宽度键在首次访问时也建立基准，修复“没拖过宽度就仍按会话跳变”。`reduceFor` 的后台目标会话写入只保留会话数据，不反写全局显示偏好；`?dsh-sidebar-reset` 同时清全局显示键。
2. `src/client/Sidebar.tsx`：底部首次展开的上一次状态改为 `{sessionId, open}`；跨会话切换不算用户展开，避免悄悄创建终端。
3. 当前 Profile 真正加载的是 `lib/client.js`，已与上述源码同步做等价修改。编辑前备份到 `Data/Development/backup-dsh-better-sidebar-client-before-global-view-20260924.js`，SHA256 `AF36FCF4B4474C965A63605DA234224ABE1308203818193DF26800B0AE7E606F`。未触碰 `src/main.ts`、浏览器分桶或会话文件。

纯前端链路：卡片/底部开关及拖动 → `SidebarStore.reduce` → 当前会话内存快照 + 全局显示键 + 当前会话内容键 → `useSyncExternalStore` 重绘/布局让位。会话切换 → `setSession` 读取目标的标签内容并叠加同一全局显示偏好。没有新增后端入口或 API。
