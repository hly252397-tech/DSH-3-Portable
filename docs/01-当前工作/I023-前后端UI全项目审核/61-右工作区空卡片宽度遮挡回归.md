# 右工作区空卡片宽度遮挡回归

2026-09-23，用户提供四张真实桌面截图，要求修复右侧空卡片工作台宽度变化后遮挡主对话区的问题。本记录只覆盖该几何回归，不替其他会话的 UI 漂移、浏览器改造或设置窗口改动背书。

## 修改前诊断

问题是右面板实际宽度和主区让位宽度出现了第二套上限；证据是现役槽 `1.0.66-local-e5447837f5c9a061` 的只读探针在 1331 CSS px 视口记录：`--dsh-sidebar-width=691px`、面板 `left=640 / width=691`，但 `#root margin-right=560px / width=771`，输入框右缘 754 越过面板左缘 640，重叠约 114 px；下一步是移除 `dsh-ui-tweaks` 对空卡片/占位态的 `--dss-panel-width` 与 `#root` 条件覆盖，让面板、拖动线和主区恢复读取 better-sidebar 的同一个 `--dsh-sidebar-width`。

旧规则可反向复现：空卡片态把主区单独钳到 560 px，占位态单独钳到 420 px，而面板继续按内联持久化宽度渲染。请求宽度不超过上限时看似正常，拖宽或恢复较大持久化宽度后即产生截图中的不同遮挡量。

## GCC / 三项对齐

- Task Position：外置 `dsh-ui-tweaks` 展示层中的右工作区几何回归；better-sidebar 仍是唯一宽度写者。
- Direct Impact：空卡片态、编辑器占位态的主区让位；Indirect Impact：输入框、正文、分隔条、底部面板右缘和缩放/刷新恢复。
- Reusable：复用 `dsh-better-sidebar` 既有 `resolveWorkbenchWidth → writeGeometry → --dsh-sidebar-width` 链，不新增状态、监听器或接口。
- Constraints：保留三个板块边框、6 px 间距、全部右侧卡片、拖动和持久化宽度；关闭/紧凑态仍为 0；不恢复已删除入口。
- Expected Files：`customizations/ui-tweaks/lib/client.js`、实际加载副本、聚焦回归测试、本记录与功能清单。
- Do Not Touch：`src/main.ts`、`assets/**`、better-sidebar/sidebar-spaces 在途源码、浏览器与设置窗口、用户会话和数据、A/B 活动槽。
- Regression Scope：空卡片/占位/普通内容三态，面板打开/关闭，拖动，窗口尺寸，80%/100%/125%/150% 缩放，刷新；核对面板左缘不小于主区右缘。
- 纯前端例外：无后端能力、请求、权限或持久化协议变化；用户拖动/恢复状态仍由原 better-sidebar store 处理，UI 反馈是面板和主区同步移动。

## 实施

- 归档与实际加载的 `dsh-ui-tweaks/lib/client.js` 同步删除 4 条卡片类型相关几何规则。没有新增替代上限：右工作区的唯一结果继续由 better-sidebar 的 `writeGeometry()` 同时写给面板和 `--dsh-sidebar-width`。
- 新增 `test/ui-tweaks-workbench-geometry.test.ts`，阻止 ui-tweaks 再次声明 `--dss-panel-width` 或覆盖 `#root` 的右让位。
- 恢复：只把本记录所删的 4 条 CSS 加回两份 `client.js`；这会有意恢复旧遮挡，仅用于反向复现。

## 2026-09-23 续：防止下次重建回归

问题是运行 bundle 虽已统一宽度，better-sidebar 的 `src/client/sidebar.module.css` 还留有按 `editorPlaceholder`/`paneEmptyCards` 分别限制 420/560 px 的旧规则，而现有专项测试只扫描 ui-tweaks 两份副本；证据是源码两条 `max-width` 仍在、当前 bundle 中却没有，说明一次从源码重建足以把第二宽度源带回；下一步是清掉源码残留，并让门禁同时检查源码、运行产物和覆盖层的宽度归属，保存旧规则会被拦截的反向测试。

本次仅删除 better-sidebar 源码 CSS 的两条空态限宽；现役 `lib/client.js` 原本就没有这些规则，应用画面无需重新加载。新增 `scripts/workbench-geometry-guard.mjs`：核对 better-sidebar 源码与 bundle、sidebar-spaces 两份产物、ui-tweaks 两份副本、外壳主题共 7 个文件，禁止 CSS 再声明工作区状态宽度或让位，核对 bundle `#root` 只消费 `--dsh-sidebar-width`。`scripts/build-sidebar-layout-compat.mjs` 在写回活动 bundle 前执行该检查，`--check` 只验证不写入；`scripts/lint-ui-discipline.mjs` 同时检查静态文件与只读实机探针中的面板宽度、让位、中缝和输入框边界。专项测试以旧 `560px` 限宽、旧 `#root` 覆盖和原始 691/560 遮挡样本作反向对照。维护契约增加唯一宽度写者条款。

GCC/GIR：实际涉及的 UI 仅为未来从源码重建的右工作区；当前运行 bundle 与面板视觉不变。后端不适用，插件交互与持久化协议不变；对话、卡片、浏览器复用原 `resolveWorkbenchWidth → writeGeometry` 路径。与预判相比只增加了重建前的机械门禁和维护契约，没有变更公共接口、数据、槽位或用户会话。后续插件更新必须先跑守卫，再按 47 号矩阵复验拖动、缩放、空态和关闭态；静态守卫不能替代更新后的实机验收。
