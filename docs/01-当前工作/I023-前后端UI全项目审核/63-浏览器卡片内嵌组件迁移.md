# 浏览器卡片内嵌组件迁移（2026-09-25，核心已实机验收；快切菜单快照留账）

## 用户决定与问题诊断

用户要求彻底移除反复产生空白、遮挡和状态不同步的右卡片原生叠加层，同时 ERP 等禁止 iframe 的网页必须继续在卡片内直接操作；允许使用 Electron 卡片内嵌网页组件，且浏览器今后须可扩展。此决定覆盖 UI 维护契约中「`browser-panel.html` + 桌面 `WebContentsView` 是唯一完整浏览器」的旧呈现方式，但不撤销完整浏览器的标签、资料、下载、扩展和智能体操作能力。

问题是：当前卡片 DOM 与 `browserPanelView`/每标签 `WebContentsView` 分属不同渲染树，卡片可见、主进程 owner、边界和遮挡必须靠异步 IPC/心跳对齐；任一迟到的 hide 或会话切换都可能留下 `cardState:visible / owner:null / visible:false` 的白卡片。证据：`src/main.ts` 的 `layoutDshView`、`browserPanelView` 和 `BrowserTab.view`；`portable/browser-view.js` 的 claim/bounds/occlusion 循环；I023-62 的两次复现。下一步是先验证同一 DOM 中的 `<webview>`，再迁移 UI、状态与能力，最后删除原生浏览器视图，不能先删旧层让 ERP 失能。

## 隔离验证（尚非产品验收）

- Electron 44.3.0，独立隐藏窗口、独立 `Data/Temp/webview-spike/profile`：`<webview>` 成功加载 `data:` 页，`did-attach-webview` 后能读取 `{title:"Guest",body:"Inside card"}`。
- 同一宿主 DOM 中把已加载 `<webview>` 从一个容器移动到另一个容器，`getWebContentsId()` 前后均为 `2`；支持设计「卡片切换时把同一网页节点停放/移回」，仍须实测真实站点和状态。
- 「浏览器 chrome 本身作为一个 `<webview>`，里面再套网页 `<webview>`」在当前版本没有产生内层 guest，10 秒超时；这条双层嵌入尝试失败，不能用它假称完整浏览器已移植。应把 chrome 和网页组件放在同一宿主卡片 DOM 中。
- 随后验证了同一宿主 DOM 内的**两个兄弟** `<webview>`：工具栏 guest（`nested.html`）为 id 2、网页 guest 为 id 3；网页节点移动后仍是 id 3，工具栏仍是 id 2。可据此复用现有独立 `browser-panel.html`/preload/资料 UI，同时让网页成为卡片内相邻组件；菜单/资料全屏态须扩展工具栏组件的 DOM 区域并隐藏/恢复网页组件，不能靠跨层 z-index。
- Electron 官方文档不推荐 `<webview>`，因此此迁移必须固定当前版本、限制 guest 预加载/导航/权限，并以真实点击回归与 A/B 回滚控制风险；不能承诺将来永不回归。
