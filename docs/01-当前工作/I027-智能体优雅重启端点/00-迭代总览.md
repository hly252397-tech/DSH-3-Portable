# I027 - 智能体优雅重启端点

日期：2026-09-13。状态：实现与门禁完成，等待部署到活动槽后做端到端验证。

## 1. 用户诉求与背景

用户在排查「外链为什么开在内置浏览器窗口」时提出：智能体需要重启应用时，此前只能靠用户去按侧栏的「重启应用」按钮，或由智能体硬杀进程再拉起启动器。用户明确要求：「那你能不能做一个端点或者 CLI 呢？」

根因（已核实）：侧栏「重启应用」按钮走 `dshDesktopShell.action('app-restart')` → 渲染进程 IPC → 外壳 `requestAppRestart()`（先调度分离的新实例，再 `shutdownDesktop` 优雅关停：托盘销毁、服务停止、配置落盘、`app.exit(0)`）。这条链路只存在于 DSH 渲染进程内部，**没有对外 HTTP 端点或 CLI**，智能体无法调用。

## 2. 方案与改动

不做新的进程控制实现，只补一条**从运行时到外壳的请求通道**：

1. `src/main.ts` `handleDshIpc()`：新增 `app-restart` IPC 分流。判定兼容字符串与 `{ type: 'app-restart' }` 两种形态（与既有 `isRequestHarnessUpdateIpc` 同风格），命中后调用**既有** `requestAppRestart()`——与按钮/托盘/菜单完全同一条优雅关停链路，绝不硬杀。
2. `Data/DSH/profiles/web/local/dsh-restart-button/lib/index.js`：宿主半侧从空 `apply()` 扩展为注册 `webServer` prefix 端点 `POST /api/dsh-restart-button/restart`，校验 `x-dsh-agent-token` 后 `process.send({ type: 'app-restart' })` 上报外壳。附 Schemastery `Config`（`agentToken`）。
3. `Data/DSH/profiles/web/local/dsh-restart-button/cordis.patch.yml`：patch 条目内联 `config.agentToken`（本机随机密钥，留空即停用端点）。

规范对齐：导出形态为**命名导出** `name` + 模块级 `export const inject = ['webServer']` + `apply`（对照 MichengAI `dsh-im-connect` 实证形态①），patch 条目只写 `id`/`name`/`config`，不重复 inject 声明。端点沿用 `dsh-im-connect` 的 `webServer.register({ kind: 'prefix', path, handler })` 模式。可调参数走 Schemastery 配置而非硬编码。

安全边界：端点仅本机 webServer 可达、仅接受 POST、必须携带共享密钥；密钥未配置时端点整体返回 403（`token === ''` 短路），因此默认不暴露能力。**未**采用 `connection.requestRejection`（登录态 + 同源）是因为智能体从本机脚本调用没有会话 Cookie，会恒 401，无法使用。

归属对照（知识库第 10 节）：外壳进程控制是既有能力，本改动是**拦截/转发**而非新增能力面；未触碰模型可见输入，故不扩展 `SessionEventMap`（铁律 1 不适用）。所有注册经 `ctx.effect` 并返回 disposer，无手动清理。

## 3. 为什么改 `dsh-restart-button` 而不是新建插件

profile 依赖矩阵有已知地雷：任何 `pnpm install`（含为无关目的跑的）都会把整个新矩阵物化，历史上引发过三连故障。复用已挂载的 Junction 链接插件（`local/dsh-restart-button` → `node_modules/dsh-restart-button`）**零安装即可生效**，避免动 `package.json`/lockfile。该插件本就是「重启入口」，职责一致。

## 6. 已知限制

- 端点只在应用由桌面外壳启动时可用（`process.send` 依赖 IPC 通道）；`dsh web` 独立启动时返回 500 并说明原因。
- 令牌为明文写在 profile patch 内联 config，仅本机可见；轮换方式是改该字段并热重载。
