# 后台任务徽标竖排修复（2026-09-21）

> 一 bug 一文档。上游登记：`customizations/ui-tweaks/README.md` 里那条「未决项：有后台任务时
> 「3 个后台任务」徽标被挤成竖排（左上 x≈118，43×114）… 待另立任务」——本轮就是那个"另立的任务"。

## 1. 用户看到什么

「**为什么每个会话还不一样，能统一吗？**」——头部出现竖排文字，而且只在部分会话里出现。

## 2. 为什么"每个会话不一样"（源码级结论，不是猜）

官方 `@deepseek-ai/dsh-client-ui-jobs/lib/client.js` 的 `JobListAction`：

```js
const jobs = useSessions((state) => state.jobsBySession[sessionId]) ?? NO_TASKS;
// 注释原文：It renders nothing at all until the session has at least one job
```

即 **本会话没有后台任务就整块不渲染**。所以有任务在跑的会话才长出这块——这就是"每个会话不一样"。

## 3. 根因（先量后猜，带数字）

- 官方 `.QsffPG_count` 是 flex 项，**没有 `min-width:0`** ⇒ `min-width:auto = min-content`；
- 头部操作区 `headerActions` 宽度**随会话与布局在 60~224px 之间变化**（同一天实测到 68 / 149 / 177 / 220 / 226px 多种）；
- 放不下「N 个后台任务运行中」时，官方样式**不截断、改逐字折行**：

| 项 | 原故障态实测（页面实测值） |
|---|---|
| 文字 span | `[125,-14,23,144]` → **23px 宽、144px 高 = 竖排 8 行** |
| 按钮 | `[105,-17,56,150]` → **150px 高**，`y=-17` **越出视口顶部**（压到外壳标题栏区域） |

## 4. 改法

文件：`Data/DSH/profiles/web/local/dsh-ui-tweaks/lib/client.js`（本地插件是 Junction，改盘即生效，无需构建/重启）。

```css
body button[aria-label*="后台任务"],body button[aria-label*="background task" i]{white-space:nowrap!important;min-width:0!important;max-width:100%!important;max-height:32px!important}
body button[aria-label*="后台任务"]>span,body button[aria-label*="background task" i]>span{white-space:nowrap!important;min-width:0!important;overflow:hidden!important;text-overflow:ellipsis!important;max-width:none!important}
```

- 选择器走**语义属性 `aria-label`**，不用哈希类名 ⇒ 运行时升级后仍生效；
- `min-width:0` 同时写在**按钮**和**文字**上：按钮才允许被压到 min-content 以下，文字才能拿省略号；
- `max-width:100%` 是防横向越界的显式护栏。

### 失败尝试（如实记录）

1. `span{max-width:4.5ch}`：止住了折行，但 **224px 档仍只显示 2 字、白截断 157px**——只治了"折行"，没治"该显示的不显示"。
2. 只去掉上限（`max-width:none`）：按钮因 `min-width:auto` 以 min-content 为地板，**60/76/120px 档横向越界 84/68/24px**。
3. 正解 = ①＋② 的组合：**让按钮可收缩**，文字随之"有空间就全显示、没空间就省略号"。

## 5. 对照复现（不是正向自证）

方法：在**真实页面**把官方结构复刻进**真实 `headerActions`**，在同一同步帧内（无画面副作用）先量"现行 CSS"，
再追加**同特异性的后置样式**还原"旧行为"，四档容器宽各量一次：

| 容器宽 | 旧行为（还原换行） | 现行 |
|---|---|---|
| 60px | 60×96、**5 行**、y=-24 越界 | **60×28、1 行、显 3 字** |
| 76px | 76×60、**3 行**、y=-6 越界 | **76×28、1 行、显 4 字** |
| 120px | 120×42、**2 行** | **120×28、1 行、显 7 字** |
| 224px | 144×28、1 行、显 9 字 | **144×28、1 行、显 9 字（全显示）** |

**真实徽标**（官方 React 渲染的原件，非复刻）修复后实测：

## 6. ⚠️ 抓图工具纠错（本轮最值钱的教训）

**症状**：DOM 明确说徽标可见（`checkVisibility=true`、坐标正常），但我的"应用窗口截图"里**怎么都看不到它**。

**根因**：我用的 `CopyFromScreen` 抓的是**屏幕物理像素**。DSH 窗口当时被 **Chrome 窗口压住**（用户正在宏建云 ERP
里开「编码器」对话框），所以我抓到的是 Chrome —— 那个"页面"根本不是 DSH。差点据此得出"徽标没渲染"的错误结论。

**修法**：`PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT=2)` 直接渲染**窗口自身内容**，与遮挡无关。已固化为
[scripts/capture-app-window.ps1](../../scripts/capture-app-window.ps1)（支持裁剪/放大参数）。

**纪律**：

- 抓"应用窗口"**禁止**裸用 `CopyFromScreen`；`PrintWindow` 优先。仓库既有 `scripts/look-ui.ps1` 是
  "临时置顶 → 抓 → 还原置顶"，可用，但会**改变用户窗口层级并抢焦点**；用户正在别的窗口干活时优先用新脚本。
- `CopyFromScreen` 还有**隐私风险**：窗口被遮挡时会把别人的应用拍进证据文件（本轮差点把用户的 ERP 页面留档）。
- 截图"看不见某元素"时，先验证"我截的是不是那个窗口/那个页面"，再下结论。

## 8. 未决项（如实登记，不假装闭环）

1. 官方徽标只在「页面活着时收到 job 事件」才挂载（**页面重载不重取 jobs 快照**），因此没取到它自己的定点实拍；
   已用"同结构复刻进真实容器 + 真实级联 A/B + 真实元素坐标"代替。用户下次跑后台任务时就能看到实物。
2. `customizations/ui-tweaks/` 归档副本落后实体（791 行 vs 957 行；实体独有 176 行含本轮修法与采样仪器块，
   归档独有 10 行含 `:where` 中缝规则）——**两个方向都有改动**，故本轮只增量补证据目录 + README 一节，
