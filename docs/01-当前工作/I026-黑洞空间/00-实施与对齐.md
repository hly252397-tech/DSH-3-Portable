# I026：黑洞空间（DSH 内容板块）

> 历史实现记录，不能用作最终验收依据。2026-09-12 实机发现对话读取、引用保护与布局缺陷并修复；模型配置原先仅保存字段，尚未接入独立模型，现已禁用并说明。当前范围和证据以 [实机落地记录](01-实机落地.md) 为准。

**日期**：2026-09-11（Asia/Shanghai）  
**交付目标**：在 DSH 内增加可自定义的“黑洞”内容板块。DSH 负责发现对话中的价值，黑洞负责吸收、保存、整理和提醒，知识库/界面负责展示，未来再接入模型完成更深层理解。

## 1. 本次交付范围

已完成一个可运行的第一版：

- 默认创建“黑洞空间”，也支持用户继续创建多个黑洞。
- 从当前对话手动“放进黑洞”；对话内容达到价值阈值时主动提醒。
- 黑洞发现当前对话与已有记忆相关时提醒用户，并可打开黑洞查看。
- 吸收 TXT、Markdown、JSON、CSV；自动生成标题、摘要、类型、标签和价值分数。
- 内容去重、候选/确认/冲突/过期/归档状态、来源追踪、编辑、搜索、引用回当前对话。
- 每个黑洞独立设置目标、默认/专属大脑、模型标识、思考深度和提醒强度。
- 以成长值、等级和“初生/会记忆/会整理/会关联/会理解……”表达黑洞智力成长。
- 内置开发手册，明确已实现、开发中和当前限制。
- 本地持久化、原子写入、上一版本备份、版本冲突保护、同源/请求头/DSH 会话鉴权。

## 2. 文件位置

核心插件目录：

`Data/DSH/profiles/web/local/dsh-black-hole/`

| 文件 | 用途 |
|---|---|
| `lib/core.js` | 黑洞状态、资料分析、分类、标签、搜索、去重、成长值 |
| `lib/portable-store.js` | DSH_HOME 下的原子持久化与版本冲突保护 |
| `lib/index.js` | DSH Web Server 接口 `/black-hole/api/store` |
| `lib/client.js` | DSH 客户端模块：侧栏板块、对话按钮、价值提醒、文件吸收、记忆/手册/智力面板 |
| `package.json` | DSH 插件包和客户端模块声明 |
| `cordis.patch.yml` | 把插件挂载到 DSH Web Profile |
| `README.md` | 插件功能、存储位置和当前限制 |

## 4. 当前边界

本版本已经是可使用的本地黑洞 MVP，但“自动学习”目前采用确定性整理和检索，不修改基础模型权重，也没有接入真正的向量库/RAG 模型调用。PDF、Word、PPT、图片、音频解析，多黑洞知识融合，外部工具执行和审批流属于下一阶段。

这不是宏建云或任何外部业务系统插件；黑洞是 DSH 自己的内容板块。未来如果 DSH 增加连接器，连接器应作为黑洞可选能力，由用户授权后执行，不应把黑洞绑定到某一家系统。

## 5. 下一阶段建议

1. 接入 DSH 已有模型解析能力：吸收后生成更高质量摘要、事实、关系和待确认问题。
2. 增加统一文件解析管线：PDF/Word/PPT/网页/图片 OCR/音频转写。
3. 用向量索引替换当前轻量文本检索，同时保留来源引用和确定性回退。
4. 增加黑洞之间的共享知识、冲突检测和合并规则。
5. 增加连接器权限、预览、审批、执行结果回写，让黑洞可以安全地处理 DSH 内的业务动作。
