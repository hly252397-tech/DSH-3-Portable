# 黑洞对话相关资料提醒增强

日期：2026-09-13。状态：已完成，源码、Profile 部署物、测试和真实黑洞窗口通过；提醒命中 UI 的真实会话样本本轮未发送测试消息，详见验证边界。

## 用户目标

当用户在 DSH 对话中提到“界面设计规范、界面优化、UI”等主题时，如果当前黑洞中存在相关资料，黑洞应主动提醒用户；用户可以打开资料，也可以直接引用到当前对话。

## 现状与缺口

黑洞已有 `startRecallMonitor` 和提醒条，但旧匹配主要依赖整句文本、空格分词和字符二元组。中文自然表达通常没有空格，容易出现“明明有《界面设计规范》，却没有提醒”的漏匹配；已有相关提醒也只有打开黑洞入口，没有直接引用动作。

## 本轮范围

- 改进本地确定性主题匹配：按标点切分短语，分别在标题、标签、摘要和正文中加权匹配；保留当前任务/会话隔离和主动提醒强度设置。
- 相关资料提醒增加“引用到当前对话”动作；引用前由用户点击确认，不自动提交消息。
- 提醒展示资料标题和摘要片段，减少用户需要先打开黑洞才能判断是否相关。
- 增加匹配回归测试和真实 DSH 窗口验证。

## 不改变

- 不接入互联网搜索，不调用外部模型，不修改基础模型权重。
- 不改变黑洞存储结构、`POST /black-hole/api/store`、会话数据和任务隔离规则。
- 不自动把资料塞入模型上下文，也不自动发送消息；只有用户点击“引用到当前对话”才写入输入框草稿。

## 对齐关系

- 入口：DSH 当前对话输入区上方黑洞提醒条。
- 前端：`customizations/black-hole/lib/client.js` 的 `startRecallMonitor`、`RecallDock`。
- 后端/存储：复用现有黑洞读取、搜索和 `quoteInCurrentConversation`；本轮无后端变更。
- 反馈：提醒条显示相关资料标题/摘要；引用成功显示已放入输入框；输入框忙碌时保留现有错误保护。
