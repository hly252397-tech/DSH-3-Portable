# 黑洞首次打开：首页活动分布时序修正

日期：2026-09-13。状态：已完成，源码、生成物、真实窗口和回归门禁均通过。

## 问题

用户观察到：第一次打开黑洞时，DSH 主区左侧“任务最近活动分布”仍然显示；第二次打开后才消失。该卡片属于 DSH 首页活动区，不属于黑洞内容页。

## 根因

`dsh-sidebar-spaces` 的 `mountHeroActivityGrid` 原来只遍历 `.wSkVaW_composerHero`，只要节点仍在 DOM 中就保留活动卡片。打开黑洞是右侧面板操作，主区仍保持 `data-phase="hero"`，因此只判断首页阶段仍然不够；黑洞宿主 `.dbh-host` 出现后，活动卡片会残留到下一次 DOM 刷新。

## 修正

- 通过 `hero.closest('.wSkVaW_root')` 读取当前宿主阶段；兼容旧 DOM 模拟节点缺少 `closest/querySelector` 的情况。
- 只有首页阶段且不存在 `.dbh-host` 时才创建或保留活动卡片。
- 非首页阶段或黑洞面板出现时立即卸载 React root 并删除宿主节点。
- 黑洞面板关闭后，首页活动卡片自动重新挂载；重复打开不会产生重复卡片。
- 更新 `test/sidebar-spaces.test.ts` 的客户端契约断言，防止阶段判断被回退。

## 影响范围

- 直接：`Data/DSH/profiles/web/local/dsh-sidebar-spaces/lib/client.src.js` 与按脚本生成的 `client.js`。
- 间接：DSH 首页活动分布卡片在首页/对话/黑洞之间的显示生命周期。
- 不改变：黑洞数据、知识库、会话、后端路由、存储结构、模型配置和其他插件。
