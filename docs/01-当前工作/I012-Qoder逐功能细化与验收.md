## 依据与统一约束

参考用户截图的主界面 / 知识中心布局，以及 [Qoder 新工作台](https://qoder.com/zh/new-qoder) 的产品分区。本地 Qoder 正在运行，但本轮没有操控其窗口；以下交互依据官方文档和本项目源码，不声称已经逐项点击 Qoder。

所有模块共同要求：加载、空白、编辑、保存中、成功、失败、权限不足、离线均有可辨识状态；只有后端提交成功才显示成功。键盘可操作，主题变量贯穿弹层 / 图表 / 编辑器，危险操作说明对象和影响。

数据要求：以便携盘宿主数据为权威；任务、知识、设置、自动化不存版本槽；派生索引可重建，原记录不可因索引失败被重建为空。更新前后按稳定 ID 和数量校验；跨窗口版本冲突拒绝覆盖，保留草稿。密钥不写任务单或日志。模型调用、外部连接、无人值守与远程执行采用各自明确授权，入口存在不代表授权已授予。

- Q02.1 创建 / 继续 / 重命名：同一稳定 ID 贯穿标题、消息和产物；运行中改名不打断执行；存在基础，完整回归待验。

- Q02.4 归档 / 恢复：归档与永久删除分离；归档列表可检索，恢复保留消息、目录、关联产物；插件存在，正式流程待验。
- Q02.5 统一搜索入口：分组显示任务、知识、表格、项目文件；标明搜索范围与未就绪数据源，不能把当前两种搜索叫作统一索引。项目文件检索待接。
- Q02.6 丢失审计：先列当前 Profile、数据根、过滤条件和归档状态；只读对比原记录 / 索引 / 旧端口。导出恢复清单后再决定迁移，不自动搬动用户历史。
- 验收：正文命中 / 无结果 / 索引故障 / 快速换关键词 / 归档恢复 / 跨重启更新。原始事件数量及稳定 ID 保持一致；历史恢复未完成前不能关闭此项。

## Q05 知识库、资料引用与 Repo Wiki（P1）

参考 [Qoder 知识库](https://docs.qoder.com/qoder/knowledge-base)：按主题归库、添加文件、检查来源、在有效范围内使用。DSH 当前不具备 Qoder 全格式 / 大文件上传能力。

- Q05.1 库管理：创建、重命名、工作区范围、移动条目、空库删除保护、备份；I009 / I011 已有实现和隔离证据，正式迁移待验。
- Q05.2 文本文件：TXT / Markdown 单文件选择 → UTF-8 校验 → 正文草稿预览 → 选择所属库 / 标签 → 保存 → 搜索；本轮实现，验收记录见文末。限 256 KiB；不执行 Markdown 中的 HTML / 脚本。
- Q05.3 导入边界：空白、乱码、二进制、超限明确拒绝；取消不写库，同库相同正文不重复保存，失败保留草稿；旧正文与 JSON 备份不得在保存 / 导入时截成 4,000 字。本轮实现。
- Q05.4 文档流水线：PDF / DOCX 解析、原文件保管、页码、失败详情、重试、内容指纹与增量索引分别实现。当前未支持；不能用改后缀冒充解析成功。
- Q05.5 AI 检索：查询受工作区范围限制，返回文档 / 片段 / 版本 / 定位；模型实际读取的片段写入会话事件，回答可打开来源。当前未接；页面关键词搜索不等于 RAG。
- Q05.6 版本与失效：更新来源后标明旧引用和新版本；删除不破坏既有会话证据；知识缺失直接提示，不编造引用。
- Q05.7 Repo Wiki：项目选择、目录扫描范围与排除、生成计划、进度、章节预览、源码定位、变更后增量更新独立实现；生成需要模型时先展示配置和成本边界。
- 数据 / 接口：当前知识使用 I011 `workbench.sqlite` 和 revision；完整保存请求上限 8 MiB。后续大文件放便携附件目录，数据库保存元信息，不能无限扩大整库 JSON 请求。
- 验收：长中文 / emoji、重复导入、保存失败、并发冲突、搜索、刷新和升级；模型引用另用可定位的已知答案证明；Repo Wiki 不随库管理通过而标完成。
