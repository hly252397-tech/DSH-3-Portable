# 自定义空间与工作台服务合并（2026-09-27）

状态：已进入活动 Profile，单一设置入口、真实服务探活和宽窄布局局部验收通过。全项目基线未闭环，不代表全项目全绿。用户批准只保留“自定义空间”设置入口，把工作台服务管理并入该页。

问题是两个插件分别注册 settings.section，形成相邻重复感入口；证据是 custom-spaces 与 hj-workbench 的注册及用户截图；下一步是在自定义空间页声明子插槽，由工作台贡献原服务卡，取消其独立 settings.section 注册。

范围/影响：客户端组合，不改变后台 HTTP 服务、保活、wake/status API、用户空间配置和会话数据，不改工作台“+”标签和已有浏览器打开协议。空间拥有列表编辑，工作台拥有服务逻辑；子插槽随父注册清理，工作台晚加载仍通过 slots.inject 接入，未安装工作台时空间页无空卡。只有父空间插件启用时显示其服务卡，后台不受影响。保留原表单拒绝/迟到保存保护，避免将服务卡移动造成编辑草稿丢失。

前后端对应：空间编辑→原 configForms→Config；服务卡→原 status GET / wake POST→原宿主处理→原状态/错误反馈。纯前端改组合，不新增 API。新增标题进中英字典，原按钮逻辑不改。

现役确认：桌面9ea0/PID34428，运行时0.1.7-rc.2/4d29，活动v4-rc2b Profile；官方在线基线PASS(477b4f42)，基线原失败仅assets/shell.html。使用当前 ui-slots README/types 的 children 声明与 renderSlot；不写 CSS 隐藏菜单，不新增全局桥接，不重启、不改不可变槽。

预期文件：customizations/custom-spaces/lib/client.js、工作台客户端保留源 customizations/hj-workbench/lib/client.js、对应活动文件；定点测试及文档。备份在 customizations/audit-fixes/20260927/spaces-service-merge/，后续有并发写入时按局部差异回退，禁止整包覆盖。不替其他在途改动记基线。

## 失败尝试与验证边界

- Windows rg通配符路径及猜测 core.d.ts 不存在：改用实际目录/导出 index.d.ts，未据猜测API实现。
- 第一次定点测试未设置TEMP，运行器用C盘临时目录并自动清理，随后按便携规则重跑在G盘。全量失败现场保留于 `Data/Temp/dsh-test-runs/run-VPh9d4`。
- 初次真实设置页原生样式缺失（computed position=static），导致页面被排到主界面下方。两次客户端页面重载后恢复原生fixed/grid样式并复验通过；未查明该瞬时缺失成因，不宣称已根治独立样式问题。
- 对设置页误跑会话布局门禁，得到“采样目标是设置覆盖层”与让位不一致；改用设置页专用布局断言。第二次页面热刷初始采样缺数字几何，待加载完成后同一轮宽窗三项门禁全过。原失败均保留，不算通过。
- 最小化后台页面的异步点击结果曾超过15秒观察窗口；未把超时当按钮成功。后续临时恢复窗口并置顶、取得明确HTTP响应，再截图/还原，验证通过。最早观察器等待网络后才恢复，已改为同步点击后立即恢复并再次页面重载，避免后台超时残留。
