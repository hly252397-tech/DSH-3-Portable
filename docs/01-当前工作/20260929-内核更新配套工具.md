# 2026-09-29 — 内核更新配套工具（三条更新线各自独立拉取）

## 用户需求

「以后我可以单独拉取更新吗」「都要可以自己拉取自己更新」——内核（DSH 官方运行时）、插件、桌面壳三条更新线都要能各自独立拉取。插件线与桌面壳线本来就是应用内按钮独立拉；内核线缺"配套三件套"的自动化，本工具补齐。

## 交付物

| 文件 | 作用 |
|---|---|
| `scripts/prepare-kernel-update.mjs` | 内核更新配套：扫描 `Data/Runtime/Harness/slots/`，对每个**没有家园绑定**的版本自动执行 ①建代际（`--source-home` 取最新代际，防回落旧数据）②豁免清单迁移（compatibility.json 授权整体改命名新版本）③awareness peer 放宽（备份后追加版本号）+ 经正规安装器装入新代际。默认只报告（退出码 3=有待办），`--apply` 落盘；只做加法、可重入。 |
| `scripts/probe-runtime-boot.mjs` | 通用 boot 探针（从 Data/Temp 转正）：默认对活动绑定代际跑真实 bin.js `web --port 0 --no-open`，就绪计时、超时=复现卡死（退出码 2）。**必须带 `DSH_PORTABLE_ROOT`**——hj 等本地插件 env 优先推根，缺失时上溯推根在代际家园布局下解析成 `Data\DSH-generations\宏建云系统\...` 必炸（本轮实证：不带该 env 时 hj broker spawn ENOENT 直接 fatal）。 |
| `Prepare-DSH-Kernel-Update.cmd` | 双击入口：先只读报告 → 有待办才询问是否执行 → apply → 提示重启与体检。 |

## 使用流（内核单独拉取的完整闭环）

1. DSH 设置页点「检查更新」（manual 锁下唯一的拉取入口，A/B 槽 + 影子验证 + 自动回滚不变）。
2. 双击 `Prepare-DSH-Kernel-Update.cmd`（可在激活前后任何时候跑；建代际约 10–20 分钟 G: 盘拷贝）。
3. 托盘重启 DSH → 跑一键体检 `Tools/node/node.exe scripts/gate-node-run.mjs scripts/check-open-behavior.mjs`。
   忘了第 2 步也不会坏：重启后数据看着不对（回落旧家园）就补跑工具再重启一次，可自愈。

## 设计说明与边界

- 代际名 = `auto-` + 版本号去点（如 0.2.0-rc.2 → `auto-020-rc2`），代际脚本自身拒绝覆盖已存在代号。
- 为"仅下载未激活"的槽位提前建绑定是安全的：绑定只在活动版本等于其版本时才生效。
- 豁免迁移是机械改名（插件包随家园拷贝、版本不变，键 pkg@ver 保持）；若插件后续发了原生适配新内核的版本，旧授权键自然失效，无需清理。
- 本工具不触碰更新双通道的 manual 锁（用户红线），也不代点检查更新——拉取动作永远由用户在应用内发起。
