## 5. 🔴 缺陷：`scripts/check-open-behavior.mjs` 硬编码旧代际 ⇒ 体检在 0.2 上必然失败

`check-open-behavior.mjs:11` 写死：

```js
readFileSync(resolve(root, 'Data/DSH-generations/v4-rc2b/home/profiles/web/local/dsh-hj-workbench/lib/client.js'), 'utf8')
```

它从 **`v4-rc2b`** 取 `BROKER_TOKEN`，而活动代际是 **`v5-020rc1`**，运行中的 broker 在 v5 profile 里 ⇒ 拿旧代 token 打新代际 broker = 鉴权失败。也就是说**这个"重启后必跑的一键体检"在 0.2 代际上从原理上就跑不通**——而它恰恰是关闭 0.2 残留风险的标准手段。

修法是一行 import（`scripts/lib/active-ui-profile.mjs` 已提供 fail-closed 的活动代际解析，与官方 `resolveBundleDir` 同一套语义）：

```js
import { activeUiProfile } from './lib/active-ui-profile.mjs'
const { profile } = activeUiProfile(root)
const source = readFileSync(resolve(profile, 'local/dsh-hj-workbench/lib/client.js'), 'utf8')
```

**本轮未改**：属代码改动，且用户把本项范围限定为只读验证；也需与在途会话确认后再动。
