# I028 — 数据库模块可视化 · 方案

## 1. 目标

给 better-sidebar 工作台的「数据库」space 增加可视化视图：不改数据模型、不做写入（只读），让用户一眼看清表结构和数据分布。数据源就是现有 database space（`{version, fields[], records[]}`，经 portable-store 存于便携 SQLite）。

## 2. GitHub 参考项目（2026-09-13 检索）

| 项目 | 借鉴点 | 不采用的 |
|---|---|---|
| [chartdb/chartdb](https://github.com/chartdb/chartdb)（~15k★） | 「一次查询导入 schema → 自动出 ER 图 + 画布」的交互范式；字段类型图标 | React 依赖重、面向任意 SQL 库，我们只需自家模型 |
| [drawDB](https://github.com/drawdb-io/drawdb) | 表格卡片（表头+字段行+类型徽标）的视觉布局 | 完整编辑器能力（我们只读） |
| [jurerotar/sqlite-erd](https://github.com/jurerotar/sqlite-erd) | SQLite 专用、从 db 文件直出 ERD 的最小流程 | React Flow 渲染栈 |
| [datasette](https://github.com/simonw/datasette) | 只读浏览 + 每表自动汇总统计的安全模型（同源只读 GET） | REST 探索面 |
| [paulsmith/sqlite-schema-viz](https://github.com/paulsmith/sqlite-schema-viz) | 极简 schema→graph 的直接映射 | D3 渲染栈 |

共同结论：**没有现成项目基于 ECharts 做 SQLite 可视化**；我们侧栏已捆绑 `echarts.min.js`，自建渲染层成本最低。

## 3. 方案：三个只读视图（挂进数据库 space，与表格视图并列）

### 3.1 概览视图（MVP）
- 字段卡片行：字段名、类型徽标（number/text/date）、填充率（非空记录/总记录）进度条
- 汇总条：记录数、字段数、最近修改时间
- 技术：纯 DOM + 现有 dss-* 样式，无图表库

### 3.2 单列分析视图（MVP）
- 用户点选任一字段，按类型自动出图：
  - number → 直方图（echarts bar，自动分箱 ≤20 桶）+ min/max/均值/中位数
  - 分类文本（去重值 ≤30）→ 饼图/条形（echarts pie/bar）
  - date → 按日/月时间线（echarts line）
  - 长文本 → 词频 top20（echarts bar）
- 全部前端计算（records 已在内存），无后端新端点

### 3.3 结构关系图（二期）
- 若未来 database space 支持字段引用/多表，用 echarts `graph` 画表-字段关系（参考 chartdb 的 ERD 布局）；当前单表模型暂无关系可画，仅预留

## 4. 技术选型与边界

- 渲染：echarts（侧栏已捆绑，零新增依赖）
- 数据通道：复用现有 `/sidebar-spaces/api/store` 只读 load（same-origin + 既有 requestRejection 校验，不加新端点）
- 归属：新视图是 better-sidebar 的 UI 扩展，走 `ctx.slots.inject`/space 内视图注册；**不改 portable-store 写路径**
- 样式：dss-* 令牌 + `--chrome-*` 隔离，遵循 UI 契约（浅深双主题各验证）

## 5. 分期与验收

| 期 | 内容 | 验收（三项对齐） |
|---|---|---|
| MVP | 概览 + 单列分析 | 用户入口：数据库 space 内「可视化」切换；后端无新面（只读复用）；echarts 渲染与浅深主题截图；单测覆盖分箱/分类/日期聚合纯函数 |
| 二期 | 导出 PNG、时间线粒度切换 | 截图 + 交互记录 |

## 6. 风险

- 大记录量（>5k 行）前端聚合卡顿 → MVP 限抽样 2k 行并在 UI 标注
- echarts 与官方页面样式冲突 → 容器内 scoped 初始化（现有 space 页已有先例）
