# I005 全局主题系统：实施与验证

## 目标

在不修改 DSH 官方运行时源码的前提下，为桌面外壳、辅助窗口、DSH 页面、知识库与数据可视化提供一致的全局主题，并确保主题选择在桌面 A/B 更新后仍保留。

## 实现边界

- 桌面主进程是主题预设的唯一持久化权威，状态写入 `Data/Electron/UserData/shell/theme.json`。
- `assets/theme.css` 提供背景、表面、文字、边框、强调色、状态色、图表色、圆角和动效语义令牌。
- 桌面外壳页面直接加载共享样式；DSH `WebContentsView` 由主进程在导航完成后注入同一份样式。
- DSH 预加载层只同步 `data-color-scheme` 与 `data-dsh-preset`，不改写会话数据或模型可见输入。
- 主题变量映射到 DSH 的 `--dsw-alias-*` 接口，因此知识库、数据库和 ECharts 图表沿用同一套视觉语义。

## 同步流程

1. 启动时从便携用户数据目录读取主题预设；缺失或损坏时回退 `qoder`。
2. 主进程把颜色模式与预设写入各桌面窗口 bootstrap，并向 DSH View 发送专用 IPC。
3. 设置页切换预设时，通过最小权限 IPC 原子保存配置，再广播到全部窗口和 DSH View。
4. `localStorage` 仅用于旧版本降级和当前页面即时反馈，不作为跨版本权威状态。

## 兼容与恢复

- 主题文件位于不可变应用槽之外，桌面更新只切换 `Data/Updates/Desktop/slots/`，不会删除主题选择。
- 保存前自动创建 `shell` 子目录，写入使用同目录临时文件加原子改名。
- 未知预设、损坏 JSON 或首次启动均安全回退 Qoder Workbench。
- DSH 官方插件生命周期、Cordis 注册和 Profile 清单未被修改。

## 验证门禁

- 官方双基线在线检查通过后才实施。
- TypeScript 编译必须通过。
- 全量 `dist/test/*.test.js` 必须 0 fail；主题持久化测试覆盖首次读取、子目录创建、原子写入和重新载入。
- `dsh-sidebar-spaces` 的 `local/` 与 `node_modules/` 客户端产物哈希必须一致。
- `src/` 改动必须通过 `Build-DSH-Portable.ps1` 进入新的不可变候选槽，再由启动器完成健康验证与提交。
