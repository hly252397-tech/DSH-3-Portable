# 插件配置入口点击消失修复（2026-09-28）

状态：已在现役实例修复并通过活体全链路验证（无需重启桌面 App）。

## 问题

设置导航「插件配置」点击后：导航回落「常规」、该入口从导航中消失，重启页面（刷新）才恢复；再次点击再次消失。

## 根因（证据闭环）

- 现象复现（探针 `Data/Temp/diag5.cjs`，页面 console 钩子 + MutationObserver）：
  - 刷新后导航含「插件配置」；点击后 150ms 内导航移除该按钮（`removed: BUTTON.dcu-settings-link`），回落 `section=general`，`.dcu-plugin-config` 从未渲染。
  - console 捕获：`TypeError: props.useStore is not a function` → `slot entry crashed in 'settings.section'`。
- 机制（对照运行时 0.1.7-rc.2 源码）：
  1. `@michengai/dsh-codex-ui` 的 `registerPluginConfigSection` 把官方 PluginManagerPage 包进 `settings.section` 条目（id `plugin-config`），但注册时只转发了 `inject`，**没有转发 main 注册随带的 `store`**。
  2. 官方 PluginManagerPage 首渲染即调用 `props.useStore()`（store 钩子由条目的 `store` 句柄生成，见 `dsh-client-ui-slots` 的 `standardHookPropName`）→ TypeError。
  3. 崩溃经 `reportEntryError(abdicate)` 走「退位」通道：`SlotCore.entriesOfSlot` 永久排除已退位条目 → 导航行消失且不自动恢复（重注册仅在 main 条目对象变化时发生，而它没变）。
- 上游性质：codex-ui 1.1.18 自身缺陷；官方旧版同样复现（2026-09-28 上午已用旧版本确认，非本轮图标改动引入）。

## 修复（一行）

`registerPluginConfigSection` 的 `ctx.slots.register({...})` 增补 `store: entry.store`（并在准入判断加 `entry.store === void 0` 拒绝）。settings.section 与 main 同为 root scope，同一 store 句柄二次挂载合法（SlotCore handleScopes 按 scope 钉住，count 递增），官方页拿到 `useStore` 正常渲染。

- `Data/DSH/profiles/web/node_modules/@michengai/dsh-codex-ui/lib/client.js`（旧家园同步）

改前备份：`Data/Development/plugin-config-fix-backup-20260928/codex-ui-client-active.js`（改前哈希 `04106142…`）与 `plugin-config-diag-backup-20260928/codex-ui-client.js`。

## 关键教训

1. **活动家园是 `Data/DSH-generations/v4-rc2b/home`**（DSH_HOME 即技能基址），`Data/DSH/profiles/web` 是旧家园。本任务前半程改错了副本，导致「热重载失效」假象——判断改动生效必须先认活动制品（止损纪律 5「认活动槽」的又一次实证）。
2. 共享 broker `/status` 只暴露 `DONE[-1]`，并行会话高频任务会覆盖结果窗口；探针需「25ms 密集采样 + 错过即重推」。后台窗口定时器节流会让轮询延迟到 40s+，属正常等待不是挂死。
3. 崩溃退位（abdicate）机制：slot 条目组件崩溃后从 `entriesOfSlot` 投影中永久排除，表象是「导航项消失且不自愈」——同类症状先查 console 的 `slot entry crashed in '<slot>'`。
