# 点击与缩放失效：工具栏搬运监听循环

状态：修复已应用活动代际，点击、缩放、冷启动及两次独立重载实机回归通过；项目全量门禁仍有 3 项失败，不标记整体验收完成。

问题一是 ui-tweaks 的 DOM 搬运失败后立即重试形成 MutationObserver 循环；活动 Electron 追踪中渲染进程 73928 在约 8 秒内执行 15850 次 FunctionCall，热栈为 applyAll → lift / revert → unLift / markFloatingButtons。问题二是 MCP 刷新反复展开全局 schema 导致后端繁忙、页面重载阻塞。两项分别修复并保留旧新对照，详细证据与未通过项见末尾。

## 重载阻塞的第二个原因与范围复核

前端恢复后 Page.reload 的新文档长期 loading、DOM 为空，直接 GET `/` 也超时；后端 46676 累计 CPU 超过 600 秒。通过进程定点 inspector 采样得到 4134 样本、idle=0：`dsh-mcp-connector refresh → installRestriction → observedPublicNames → tools.schemas → agency-agents readHostLocale → settings.describe → composeEntries/structuredClone`。暂停读取 refresh 局部变量确认 agents=28、restrictions=0、pending=false。此前把这类刷新失败统称前端卡顿不准确。

GCC 扩展：模块为社区连接器 `connection-scopes.js`，上游 agent/created 和 tools/change，唯一 installRestriction 调用点为 refresh 的 agent 循环；每个 Agent 都重新生成全局工具 schema，重复且昂贵。修法仅把全局工具名称快照提到同一次 refresh 循环外；仍逐 Agent 判断 workspace 可见性并执行原 restrict/guard；不缓存跨刷新状态，不改 API/凭据/连接绑定，不关闭连接器。增加版本锚点兼容脚本与 28 Agent 行为测试，以脚本为可维护源码，安装时保留原文件备份。只应用活动代际社区包，不改官方运行时。

证据：`Data/Temp/ui-reload-backend-profile.json`。此项为完成页面重载验收所必需的追加修复，需同步验证工作区拒绝规则与 tools/change 更新仍生效。

第二项首候选（只合并 28 次 schema 生成）仍未足以恢复 HTTP：再次采样仍 idle=0，进入 `governance.syncRestrictions`。暂停确认实际治理 rules=0、disabledConnections=0，加载中的 Agent 数从 28 增至 47。追加明确无拒绝项的快路径：全局连接不展开 scope schema；零治理规则且没有停用连接不展开 governance schema，仍跑逐 Agent 清理旧限制。所有项目/deny/停用分支保留原判断，无权限绕过，无延迟生效。

补丁归档源和精确版本安装脚本位于 `customizations/mcp-connector/README.md`。测试包含旧 28 次→新 1 次、全局 0 次、工具变更、项目拒绝、转全局清除、停用连接拒绝、治理 deny 与处置。测试初次先后修正了排序期望及 vm 的原生 crypto import 装载，最终 2/2 通过；不是运行时实现放宽。
