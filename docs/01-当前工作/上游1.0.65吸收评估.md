### 语义变化一：启动清理口径从「白名单」改为「按依赖残留判定」

`src/plugin-seed.ts` 三处判定改写（上游 +4/−8）：

| 函数 | 旧口径 | 新口径（v1.0.65） |
| --- | --- | --- |
| `stripOfficialProfileDependencies` | 按 `OFFICIAL_PROFILE_BUNDLES` 白名单决定 bundles 里哪些官方项可留 | 先算出"从 dependencies 里摘掉的官方包"集合，**只有串进依赖的残留项**才从 bundles 剔除；没写进 `dependencies` 的官方可选层原样保留 |
| `reconcileProfileBundles` | 只保留白名单内的官方 bundle | **官方 bundle 一律保留**（由运行时解析），桌面只管社区插件与套件遗留项 |
| `pruneMissingProfileBundles` | 过滤条件用白名单 `includes` | 改用 `isOfficialProfileDependency(packageName)` |

动因是官方加一个官方层（例如 `dsh-experimental-future-layer`）就不必再改 Desktop：白名单是"穷举未来"，依赖残留判定是"只看事实"。

### 语义变化二：2 项内置插件升版

`@michengai/dsh-codex-ui` `1.1.13 → 1.1.14`、`dshmarket` `1.47.0 → 1.48.0`。其余 14 项与官方运行时 `0.1.6-alpha.2` 经 npm 实查已是 latest（`latest/next=0.1.5-rc.2`、`alpha=0.1.6-alpha.2`），本轮不动。

## 与本便携版现状的对照（关键结论）

- **本地是有实质分叉的**：`src/plugin-seed.ts` 本地 1046 行 vs 上游 v1.0.65 的 933 行（本地多出 profile 种子、link 迁移、store 相关定制）。因此**不能 cherry-pick 或整文件取上游**，本轮按 hunk 逐块外科移植，只取上述三处判定口径。
- **移植保真度的验证方式（不是目视比对）**：把上游 v1.0.65 的 `src/plugin-seed.ts` 与本地同抽出 `stripOfficialProfileDependencies`、`pruneMissingProfileBundles`、`reconcileProfileBundles` 三个函数体做字节 diff，结果**三个全部 identical**；`src/bundled-plugins.ts` 的矩阵两行与 `OFFICIAL_DSH_VERSION` 亦逐行与上游一致（上游同写 `0.1.6-alpha.2`，反向印证上面那处声明漂移确实是本地滞后）。
- **不动的地方（刻意）**：`dsh-better-sidebar` 保持 `0.19.1` 的本地链接分发口径（升 npm 会把定制件换成官方包）；`@michengai/dsh-automation` 保持在 0.1.42（补丁锚点，矩阵注释与既有约束如此规定）；`OFFICIAL_PROFILE_BUNDLES` 与 `OFFICIAL_DSH_VERSION` 不变。
- **本轮顺带修掉的一处声明漂移**：官方基线门禁在改完矩阵后报
  `打包回退运行时 0.1.6-alpha.2 与桌面清单 0.1.6-alpha.1 不一致`。根因是上游 v1.0.64 吸收时已把 `OFFICIAL_DSH_VERSION` 提到 alpha.2 并烘焙进随包运行时，而 `package.json` 的 `config.bundledDshVersion` 与基线 JSON 的 `bundled.dshVersion` 仍写 alpha.1（上游 v1.0.63 时的值）。门禁取槽内 `dsh-runtime.tgz` 实测为 alpha.2，**据实改正两处声明**，并在基线 JSON 的 `bundled.note` 写明这是声明滞后而非实装升级。
- **版本号**：`package.json` 由 `1.0.64+build.2` 改为 **`1.0.65`**（基础版本完全跟随上游的既定政策）。已确认本地不存在 `v1.0.65` 便携发布标签，无标签冲突；比较器实测 `compareReleaseVersions('1.0.65','1.0.64+build.2') = 1 > 0`（构建元数据 `+build.2` 按 SemVer 忽略），新槽会被启动器判为更新。

## 待决与风险

- **Codex UI 1.1.14 的客户端产物**：升版会改变 client bundle 内容，`customizations/ui/` 的受保护源码快照与 `ui-baseline` 覆盖的是**本地定制源码**（theme.css / sidebar-spaces 等），不是 npm 包内的产物，故本轮不构成基线漂移；但 1.1.14 若有新的客户端 DOM 结构，需在实机重启后确认既有主题选择器仍命中（**归入用户重启验收项**）。
- **dshmarket 1.48.0**：仅影响插件市场自身页面，与外壳无契约面。
- **官方 HEAD 漂移（已闭环）**：门禁同时报 `官方 HEAD 已变化：基线 c291e79…，当前 ddefc45f…`。人工审阅后确认新 HEAD 即标签 `dsh-v0.1.6-alpha.2` 的发布合并提交（与本仓随包运行时同版本），三份规范文件的逐行差异与逐子系统判定见
  [官方兼容基线](03-技术架构/DeepSeek-Harness-官方兼容基线.md) 的 2026-09-19 记录；审查基线已推进，实现基线不动。
