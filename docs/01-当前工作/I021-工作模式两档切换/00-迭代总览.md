## 4. 决策：会话档位记录走 storage domain，不走 sessionProjections

**决定**：Host 侧 `ctx.storageDomain` 的一个 domain global 映射 `{ [sessionId]: 'coding' | 'general' }`。

**替代方案（已否决）**：`ctx.sessionProjections.register(...)` + 自定义会话事件。这是 `dsh-permission-presets`（`lib/index.js:123` 的 `installSection` + `:152` 的 `session/created`）、`modelSelectionProjection`、`dsh-goal` 用来做"每会话分类"的官方形状，且带 `wire.viewSchema` 时值会自动随 list RPC 上屏，下一轮做列表过滤时不必再加管道。

**否决理由（一手证据）**：
- 自定义事件类型属于 out-of-repo 词法，读取端只在事件带 `ignorable` 标记时才允许跳过；不带标记时**必须拒绝重建该会话**（`@deepseek-ai/dsh-session/lib/types/known-event-types.d.ts:8-24`，`types.d.ts:418-427`）。
- 但公开的 `Session.append(type, data, ...opts)` 的 opts 只接受 `sourceEventSeqs` 与 `surfaceOp`，**没有任何通道设置 `ignorable`**（`dsh-session/lib/index.js:1367-1385` 实测）。
- 后果：一旦本插件被停用或卸载，插件开启期间创建的每个会话都会打不开。这直接违反 FR-04-B"旧任务升级后仍可打开"，也违反 I012 的数据安全要求（原记录不可因插件状态被拒读）。

**影响**：下一轮做"按模式过滤会话列表"时，Host domain 数据到不了客户端（`ctx.storageDomain` 在安装运行时里没有任何 client 侧引用），需要另开一条只读 RPC 或由本插件自己提供 client 可见服务。这个代价已知并接受，换来的是零会话日志风险。

### 7.3 Profile + Loader + 真实进程组合（发现并修复三处真实缺陷）

```
dsh --profile web --dump-config    # 组合树第 606-608 行含 dsh-work-mode（id: work-mode）
dsh --profile web --no-open        # 真实启动，healthy（dsh web: http://127.0.0.1:3080/...）
```

**缺陷一（首次真实启动抓到，单测漏掉）**：`[loader-isolation] entry work-mode failed: invalid unit name 'work-mode'`。存储域单元名规则是 `^[a-z][a-z0-9_]*$`（`dsh-storage/lib/index.js:80`，只允许下划线），而 settings 命名空间规则是连字符（`installSection` 要求 lowercase hyphenated identifier）。二者不同，域名必须用 `work_mode`。已改 `lib/index.js` 域名并双拷贝同步，重跑真实启动零错误。单测已加 `UNIT_NAME_RE` 断言防回归。

**缺陷二（2026-09-07 浏览器实测抓到）**：`.dcu-head` 本是两列网格（`minmax(0,1fr) auto`：品牌 | 操作），把开关 `prepend` 成第三个子元素后网格换行——品牌被挤到右上、`.dcu-head-actions` 掉到第二行，头部布局整体错位（用户截图所见）。

**缺陷三（缺陷二初版修复的回归，用户第二张截图复抓）**：初版修复把头部改三列 `auto minmax(0,1fr) auto` 并把品牌压进可压缩中列，侧栏 ~240px 宽下开关(~100px)+搜索(~64px)占掉两头，logo 被压瘪（用户："把我的 log 挤成啥样了"）。

**缺陷四（缺陷三"堆叠网格"版的回归，用户第三张截图复抓）**：堆叠版虽只加行不改列，但对 `.dcu-head` 的 `height:auto` + 行模板覆盖仍破坏 logo 尺寸与右侧图标定位（用户："deepseek 大小会发生变化，右侧图标也会移至最右边消失"）。**定论：头部两列网格 + 定高 60px 是应用原生布局的根基，任何覆盖（改列、加行、放高）都会连锁变形。终版头部零改动**：删除全部 `.dcu-head` 覆盖，开关作为 `.dcu-head` 的兄弟节点插入 `.dcu-expanded-shell`（flex column，`@michengai/dsh-codex-ui/dist/client.js` 原生样式确证）中头部之后，自然流到头部下方；折叠时外壳整体 `display:none` 开关随之隐藏；`ensureMounted` 以 `parentElement`/`previousElementSibling` 幂等补位抗 React 重渲染。浏览器实测：头部计算样式回到原生（grid / `minmax(0px,1fr) auto` / 60px / 无内联样式），开关 `parent=.dcu-expanded-shell`、`prevSibling=.dcu-head`、margin `0 8px 8px 12px`；点「通用」落盘回显收起工作目录行、点回「编程」恢复，全部照旧。单测 mock 补 `parentElement/insertBefore/previousElementSibling/nextSibling`，断言改为"无任何 .dcu-head 覆盖、无 grid-area/grid-template、开关 margin 对齐头部内边距"。
