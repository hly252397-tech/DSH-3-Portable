# 浏览器布局与便携重启链路：实施与验证记录

## 用户可见问题

1. 下载列表为空时仍固定占用约 248px，形成大面积无意义空白。
2. “打开文件夹 / 清空记录 / 收起”被错误排成竖列。
3. 浏览器资料与设置页在浅色主题下继承了白色回退文本，标题和说明几乎不可读。
4. 应用内“重启应用”可能绕过便携 A/B 启动器，或在 Electron/Chromium 进程树尚未释放时启动竞争实例。

## 浏览器布局修复

- `src/browser-panel-layout.ts` 统一计算下载抽屉高度：关闭为 0；空状态保持紧凑；有记录时按行数增长；最大 248px，并受短窗口高度约束。
- `src/main.ts` 与 `assets/browser-workspace.js` 使用同一个 `downloadsDrawerHeight` 状态，确保 DOM 工具栏和原生 `WebContentsView` 页面边界一致。
- `assets/browser-workspace.css` 改用明确的 `--browser-text`，不再回退为浅色主题下的白字。
- 标题说明区和操作区使用独立 class，操作按钮保持单行横向排列。
- 继续保留 I007 的原生层快照交接协议，因此打开 DSH 菜单时浏览器不会盖住菜单，也不会变成空白。

## 便携重启修复

最终链路为：

`Electron 主进程 → Windows cmd.exe start broker → 独立 PowerShell 根启动器 → 等待旧进程树释放 → A/B 指针校验 → 启动当前槽/候选槽 → 存活或 readiness 验证`

关键门禁：

- 应用先等待 `Data/Updates/Desktop/handoffs` 中的接管握手文件，收到确认后才允许退出。
- `cmd.exe start` 负责把 PowerShell 启动器从 Electron 的父子进程生命周期中隔离；已用随包 Node 复现实验证明 `detached: true` 会提前退出，而 broker 模式可以持续执行。
- 根启动器等待旧主进程自然退出，再等待全部便携 Electron/Chromium 子进程消失，并额外保留 750ms 单实例锁稳定窗口。
- 普通重启和回滚启动前使用 `Remove-Item Env:` 真正删除候选事务变量；禁止把已提交事务误继承到下一实例。
- 新桌面进程必须通过 1.5 秒存活检查，最多重试三次；候选仍执行完整 DSH readiness 健康提交和失败回滚。
- 接管失败写入便携盘 `Data/Updates/Desktop/restart-handoff.log`，不再静默失败。
