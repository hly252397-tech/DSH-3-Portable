## 一句话

dshView 的 **renderer 主线程被 100% 占死**（CPU 满核、CDP evaluate 20 秒无响应），鼠标键盘事件因主线程无暇处理而全部丢弃——**页面本身活着**（合成器线程独立渲染、DOM 数据仍在更新），所以现象是"画面正常、JS 能注入、焦点 API 自报成功、真实点击键盘全灭"。

|---|---|---|

## 已排除嫌疑清单（下次不要再查）

1. **主进程消息泵阻塞**——实验 5 反证。
2. **shell HTML 层**（drag region / pointer-events / body 高度）——`app-region` 只有顶栏 44px；病灶在 renderer。
3. **幽灵 view 层**——`src/main.ts` 全文只有一处 `addChildView`（dshView），childView 列表干净。
4. **`before-input-event` 键盘钩子**——只拦浏览器标签页的 Ctrl+F/L/T/W、F5、Alt+方向，不吞普通键。
5. **dsh-view-preload.cjs**——实验 8 硬对照：摘空后照样烧。
6. **页面/插件 JS 代码**——实验 7：Edge 同页面全 idle。
7. **主进程 existsSync 风暴**——存在（broadcastShellState → browserShellState → detectSources 每次全盘 existsSync）但只占 ~9% CPU，留作独立优化项。
8. **DSH 服务端**——进程活着、端口监听正常（页面能持续拿数据流就是证明）。

**坑（已踩，勿再踩）**：

- **CDP 静默黑洞**：Chrome 111+ 的 CDP 校验 Origin，不在 `--remote-allow-origins` 白名单时**握手 101 成功但所有消息静默丢弃**——三种 WS 客户端（undici/.NET/手写 net）同症状时先查这个，别怀疑自己代码。
- **asar 内文件真实起点在 header 偏移 +2 处**（与用户 2026-09-25 手工修的"偏移差 2 字节"同源）；`asar-patch.cjs` 已自动处理。
- **僵尸端口**：被杀 Electron 进程的继承句柄会让 9333 保持 LISTENING 但无响应，换端口绕开。
- **Git Bash 的 taskkill**：`/PID` 被 MSYS 路径转换吃掉，要经 `powershell -Command "taskkill /PID ..."` 执行。
- **截图脚本**：`capture-app-window.ps1` 不带 `-Hwnd` 会按进程名挑错窗口，先 `Get-Process | Where MainWindowHandle` 拿准句柄。
