## Global Context Check（改前 12 项）

1. 定位：DSH 插件/知识数据层，不属 Electron 宿主或运行时升级。
2. 系统职责：模型知道当前环境、按需查可用能力、读取和改进手册。
3. 用户链路：新/旧会话请求 → 认知上下文 → 能力查询 → 手册检索/编辑 → 修订记录。
4. 上游：systemPrompt、tools、profileContext、webServer/client slots（实际已装声明为准）。
5. 下游：模型请求/会话记录、手册 Markdown、修订历史、独立 UI。
6. 调用者：任意使用上述 DSH prompt assembly 的模型适配器；不声称覆盖未接入的外部模型。
7. 复用：官方 scope/tool/output/Loader；参考 agent-discipline、agent-bridge 与 p3-tiny-watch 安装和测试。
8. 契约：新增工具和插件，不更改既有工具名、Session 格式及官方模块。
9. 便携：源码 plugins；部署 Data/DSH/profiles/web/local；知识在 Data/DSH，配置以相对路径为主。
10. 风险：scope 泄漏、PTC 调用误导、陈旧文档、覆盖编辑、路径穿越、插件卸载残留。
11. 回退：注销本轮两 bundle/链接，保留知识与历史；不整体还原脏 Profile。
12. 验证：纯逻辑/安全/并发/生命周期测试，真实 Loader + keyless 请求/日志，tsc/全测，实际入口验收；未完成项如实列明。

结论：独立插件可并行实施；共享清单仅做精确增量，运行时激活不得干扰另一任务。

## 实施边界

- `plugins/dsh-system-awareness/`：环境事实、按 scope 的能力目录、版本摘要、native/PTC 调用说明。
- `plugins/dsh-manual/`：限定来源整理、检索、Markdown 编辑、修订/冲突/恢复、独立入口。
- `scripts/` 与 `test/`：本任务专有安装/验证和回归文件。
- 自动生成事实与人工/模型笔记分开，模型经验默认草稿；更新不覆盖自写内容。
- 不扫描凭据、会话全文、商业工作目录，不把手册内容当高优先级指令。
