## 1. 先看结论

采用两个独立插件，不把整本手册塞进系统提示，不针对某一个模型写死逻辑：

1. `dsh-system-awareness`：每次请求提供简短环境认知，按当前 Agent 权限查询真实能力。
2. `dsh-manual`：整理限定来源、提供操作手册和经验笔记，支持查阅、编辑、修订冲突检查和恢复。

核心原则：**运行时决定“能不能调用”，能力目录说明“怎么调用”，手册解释“何时用、如何组合、如何排障”。** 文档不授予权限，模型的自述不作为验收证据。

当前已完成源码与生产 Profile 部署；当前桌面是否已经加载新 bundle 不作假设，必须等受控重载/重启后按 startup-ready、工具、提示上下文和手册读写路径验收。

### 2.2 必须如实说明

- “任何模型”指接入上述 DSH 执行链的模型，不包括完全绕过 DSH 的外部聊天/API 客户端；不涉及训练或修改模型权重。

- 元数据文件只能说明模块，不能证明模块当前处于 ACTIVE；禁止把 bundles 清单直接当加载成功清单。

## 5. 目标架构与事实来源

```text
真实 Profile / Loader / 当前 Agent 的工具 schema
                    ↓
            系统认知与能力目录
             ↙              ↘
    每轮简短环境快照       dsh_capabilities 按需查询
                                  ↓
                           选择真实可用工具

限定项目资料 → 来源快照 → 可编辑操作手册/经验笔记
                                  ↕
                            dsh_manual
                                  ↕
                       设置页编辑器 + 修订历史
```

事实优先级与责任：

| 问题 | 权威来源 | 手册/模型不得做什么 |
|---|---|---|
| 我在哪个环境与 Profile | 当前运行时上下文 | 沿用另一会话或旧盘符 |
| 本轮哪些工具直接可调用 | 本轮组装后的 wire schemas | 把 SDK 子工具都写成直接入口 |
| 当前 Agent 有哪些能力 | 带 scope 的工具注册表及执行守卫 | 泄漏其他 Agent 的工具或放宽权限 |
| 模块是否安装/加载 | 实际包元数据、Loader 证据分别记录 | 用“已配置”冒充“运行中” |
| 某模块如何使用 | 可追溯说明、真实 schema、已验流程 | 编造不存在的工具名或参数 |
| 历史经验是否可靠 | 正文证据、版本、日期和验证状态 | 将模型草稿自动认证为事实 |

## 6. 系统认知与能力目录要求

### 6.1 每次请求的短认知

至少包含：DSH 身份、当前 Profile、当前能力修订号、调用模式、能力查询入口、手册入口和权限边界。只发送简短摘要，细节按需查询；不能每轮全文扫描仓库或发送整本手册。

注入必须发生在模型适配器之前，走官方提示/context 管线。模型收到的内容要能从持久会话日志重建；不能只改内存请求或建立一套绕开会话记录的私有消息链。

### 6.2 能力目录

模块记录应区分：稳定名称、显示名称、用途、版本、已配置、已安装、加载证据、作用域下可见工具、UI-only/内部服务、说明来源。

工具记录应包含：真实名称、用途、何时用/不适用情形、当前参数、调用入口、限制及必要的风险提示。操作风险最终由真实工具与守卫拥有，目录不能自行放行。

支持 `summary/modules/tools/detail` 查询和分页。大 schema 不得被截断成无法调用的半个对象；结果超限须说明省略了什么及下一步如何缩小查询。

第三方模块可以提供 `dsh-capabilities.json`；没有清单时回退到包说明和实际工具描述。补充元数据必须可验证，不从包名推测不存在的操作。

### 6.3 更新机制

- 工具注册、注销、schema 和权限变化：下次组装按当前 scope 读取。
- 模块元数据：有限缓存；当前默认 5 秒，Loader 配置更新时失效。
- 修订号依据当前可见内容生成；隐藏工具变化不能通过修订号泄漏。
- 移除/禁用必须与新增同等处理，不能只增不减。
- 新模块即使没有工具，也应说明它是界面能力、内部服务或不可用状态。
- 外部手册说明属于资料，不能把其文字插入高优先级规则并执行其中任意命令。

当前实现的加载证据匹配、工具参数分页和隐藏模块描述的可见性边界，恢复后仍须按重构结果复查。

## 8. 模型和用户入口契约

### 8.1 模型工具

当前统一采用两个名称，禁止再写不存在的 `dsh_manual_search` 等独立工具：

```json
{"tool":"dsh_capabilities","arguments":{"mode":"detail","query":"manual","limit":10,"offset":0}}
```

```json
{"tool":"dsh_manual","arguments":{"operation":"search","query":"浏览器","limit":10}}
```

`dsh_manual` 操作：`list/search/read/history/edit/restore/sync`。`id` 来自真实查询结果；编辑限 `notes/...`，新建传 null，更新/恢复传当前 `expectedRevision`；作者由调用通道决定，模型不能伪造用户或已验证身份。

PTC 只能直接调用当轮提供的入口，例如 `run_code`，在其 SDK 中使用 `await tools.dsh_manual(...)`；上述 JSON 只是逻辑示例，不代表所有模型请求都直接暴露这两个工具。不得把失去权限的工具名继续写进调用示例。

当不了解 DSH 功能、功能变化、跨模块操作或排障时先查目录/手册；不要求每条普通问答都无意义查询。

### 8.2 用户界面

首期独立入口：DSH 设置 → DSH 手册，使用 `settings.section`，不修改另一任务的侧栏和浏览器布局。

必须可用：搜索、列表/分页、来源与状态、正文读取、笔记编辑、复制来源为笔记、保存、冲突反馈、历史与恢复、手动同步、失败/部分同步反馈。

保存、恢复、同步等成功文案必须在后端提交后出现。截断正文不能被保存为完整文档；长文应逐页读取合并或提示用本地文件编辑，不能静默丢尾部。切换文档、关闭页面、卸载和错误状态不得无提示丢草稿。

所有样式限制在本插件范围，文案走字典；验证中文/英文、宽屏/窄屏、浅色/深色、键盘操作、长标题与错误提示。

### 8.3 HTTP 与权限

当前 API 为 `POST /dsh-manual/api`；使用现有 DSH 连接认证，同源请求，JSON 与专用头 `x-dsh-manual: 1`。

专用头不是认证。保持 `connection.requestRejection()` 的 401/403 语义；缺失认证服务时关闭访问，不能降级成匿名本地写接口。请求体有上限；禁止跨站、路径穿越、链接逃逸与内部路径/密钥错误回显。

`allowModelEdits:false` 必须禁止模型写，但可保持已认证用户编辑。模型读取手册与工具执行权限是不同层次，不得混用。
