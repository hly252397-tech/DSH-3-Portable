# 浏览器原生层遮挡修复：实施与验证记录

## 问题边界

- 仅在 `dsh-better-sidebar` 的“浏览器”标签激活时复现。
- 文件、知识库等纯 DOM 标签没有该问题。
- 原因不是普通 CSS `z-index`：完整版浏览器由 Electron `WebContentsView` 承载，原生视图会覆盖 DSH 渲染器中的 portal 菜单。

## 修复设计

采用“快照交接 + 临时遮挡”两阶段协议，不关闭、不销毁、不重载浏览器：

1. 浏览器标签组件使用标准语义角色 `[role="menu"]`、`[role="dialog"]`、`[role="listbox"]` 检测与浏览器宿主区域相交的 DSH 浮层。
2. 浮层出现时，先通过最小权限 IPC 捕获浏览器工具栏和当前页面两个内存 PNG 快照；快照不落盘、不进入用户数据和会话目录。
3. DSH 渲染器先把两张快照按原始边界铺到浏览器宿主区域，并等待一个渲染帧，保证视觉代理已经提交。
4. 主进程随后统一隐藏浏览器工具栏和页面两个 `WebContentsView`，因此 DSH portal 菜单可以显示在最上层，同时浏览器区域不会变成空白。
5. 浮层关闭时先恢复两个原生层，等待一个渲染帧后再移除内存快照；标签、URL、历史记录、Cookie、登录态和下载状态全程保留。
6. 状态机覆盖快速连续开关、组件卸载、标签关闭、面板隐藏和窗口退出，异步快照过期时按修订号丢弃，禁止陈旧结果和遮挡状态泄漏。

实现不依赖“浏览器”“新建标签页”等中文文案，也不劫持点击事件，兼容 DSH 语言切换和官方菜单实现更新。

## 2026-09-03 浏览器自身“更多”菜单回归修复

### 回归现象与根因

上述协议解决的是 DSH 的 `+` 菜单等 portal 浮层；浏览器自身的“更多”菜单仍会触发主进程隐藏当前页面 `WebContentsView`，而浏览器面板没有先提供视觉代理，因此页面区域显示为空白。

第一轮补入页面快照握手后，实机复测又发现快照被压缩成 14px 宽并变为深灰。原因是 `browser-panel.html` 的通用图标规则 `.browser img` 以及浅色主题规则 `:root[data-color-scheme="light"] .browser img` 同时作用到了页面快照：前者强制 `14px × 14px`，后者执行 `brightness(0)` 和 `opacity:.72`。该问题由真实应用复测发现，没有将失败候选误判为完成。

### 最终修复

1. 新增最小权限 `browserPrepareMenuSnapshot` IPC，仅允许浏览器面板请求活动页面内存快照。
2. 打开“更多”前先捕获活动 `WebContentsView`，等待图片解码和连续两个动画帧；只有视觉代理可见后才允许主进程隐藏原生页面层。
3. 快照失败时保持原生页面可见并拒绝打开菜单，禁止用空白界面降级。
4. 关闭菜单时先恢复原生页面，下一帧再清除快照，避免恢复闪烁。
5. 使用 `.browser img.browser-page-snapshot` 覆盖通用图标尺寸，并为浅色主题增加同等上下文的专用规则，明确固定 `filter:none; opacity:1`。
